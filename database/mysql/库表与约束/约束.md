# 约束

*类型：knowledge ｜ 难度：基础 ｜ 标签：MySQL、约束、数据完整性 ｜ 更新：2026-09-22*

**约束用于定义字段的规则和限制，保证数据的完整性、准确性与一致性。六个约束各司其职：NOT NULL 保证有值、DEFAULT 兜底、UNIQUE 防重复（允许多个 NULL）、PRIMARY KEY 等于 NOT NULL + UNIQUE 且一表只有一个、FOREIGN KEY 建立跨表引用（外键消耗资源，实践中常在应用层处理）、CHECK 校验条件（8.0+ 才生效）。给已有表加约束前必须先清洗存量数据，否则 ALTER 直接报错。**

## NOT NULL：非空约束

字段中不能存在 NULL 值。

```sql
-- 创建表时直接定义
CREATE TABLE users (
  id INT PRIMARY KEY,
  name VARCHAR(100) NOT NULL
);

-- 修改已有字段为 NOT NULL
ALTER TABLE users
MODIFY name VARCHAR(100) NOT NULL;

-- 修改为允许 NULL（这也是删除 NOT NULL 的方式，MySQL 没有 DROP NOT NULL 语法）
ALTER TABLE users
MODIFY name VARCHAR(100) NULL;
```

- 字段中已存在 NULL 时，修改为 NOT NULL 会失败，需先处理存量数据：

```sql
-- 1. 查找空值
SELECT * FROM users WHERE name IS NULL;

-- 2. 用默认值替换空值
UPDATE users SET name = '未知' WHERE name IS NULL;

-- 3. 再添加约束
ALTER TABLE users MODIFY name VARCHAR(100) NOT NULL;
```

```text
ERROR 1138 (22004): Invalid use of NULL value
```

- NOT NULL 不等于有值：空字符串 '' 不是 NULL。

## DEFAULT：默认值

插入数据时未提供该字段的值，则使用默认值。

```sql
CREATE TABLE users (
  id INT PRIMARY KEY,
  status VARCHAR(20) DEFAULT 'active'
);
```

## UNIQUE：唯一约束

确保字段值唯一，可应用在一个或多个字段上。

```sql
-- 单列唯一（字段级）
CREATE TABLE users (
  id INT PRIMARY KEY,
  email VARCHAR(255) UNIQUE
);

-- 复合唯一（表级）
CREATE TABLE users (
  first_name VARCHAR(50),
  last_name VARCHAR(50),
  UNIQUE (first_name, last_name)
);

-- 命名约束，两种等价写法
CREATE TABLE users (
  first_name VARCHAR(50),
  last_name VARCHAR(50),
  CONSTRAINT unique_name UNIQUE (first_name, last_name)
);

CREATE TABLE users (
  first_name VARCHAR(50),
  last_name VARCHAR(50),
  UNIQUE KEY unique_name (first_name, last_name)
);
```

### 添加 UNIQUE 约束

```sql
-- 已有表添加单字段唯一约束
ALTER TABLE users
ADD CONSTRAINT uq_email UNIQUE (email);

-- 已有表添加多字段（联合唯一）约束
ALTER TABLE users
ADD CONSTRAINT uq_name_email UNIQUE (first_name, email);
```

- CONSTRAINT 后的名字是约束名，MySQL 会自动创建对应的唯一索引。

### 删除 UNIQUE 约束

MySQL 把 UNIQUE 约束当作唯一索引，删除唯一约束等于删除唯一索引。

```sql
-- 先查看索引名（Key_name）
SHOW INDEX FROM users;

-- 按索引名删除
ALTER TABLE users DROP INDEX uq_email;
```

### 注意事项

- UNIQUE 字段可以插入多个 NULL：SQL 标准中 NULL <> NULL，不构成冲突。

```sql
INSERT INTO users (email) VALUES (NULL), (NULL);  -- 合法
```

- 一个表可以有多个 UNIQUE 约束，各自维护唯一性。
- 复合唯一中只要有一个字段不同即认为唯一：允许两个「张三」，但不允许两个「张三 + 李四」组合。
- 插入重复数据、或添加约束时表中已存在重复数据，都会报错：

```text
ERROR 1062 (23000): Duplicate entry 'xxx' for key 'uq_email'
```

## PRIMARY KEY：主键约束

### 添加主键

```sql
-- 创建表时：字段级（单字段主键）
CREATE TABLE users (
  id INT PRIMARY KEY,
  name VARCHAR(100)
);

-- 创建表时：表级（联合主键）
CREATE TABLE orders (
  order_id INT,
  product_id INT,
  quantity INT,
  PRIMARY KEY (order_id, product_id)
);

-- 已有表添加主键
ALTER TABLE users
ADD PRIMARY KEY (id);

ALTER TABLE orders
ADD PRIMARY KEY (order_id, product_id);
```

### 注意事项

- 主键字段不允许重复值、不允许 NULL；联合主键的任一字段都不能为 NULL。
- 一个表只能有一个主键。
- 自增字段必须是主键或唯一键。
- 联合主键的字段顺序很重要：PRIMARY KEY (a, b) 与 PRIMARY KEY (b, a) 不同，顺序影响索引使用效率，一般将唯一性强、查询频率高的字段放前面。
- 主键类型建议用整数（INT、BIGINT），避免 VARCHAR、UUID 等长字符串导致索引性能下降。

## FOREIGN KEY：外键约束

建立表与表之间的引用关系，限制某一字段的值必须来自另一个表的主键或唯一键。

- 主表（parent / referenced table）：被引用的表（主键或唯一键所在）。
- 子表（child / referencing table）：包含外键的表。

### 添加外键

```sql
-- 创建表时添加
CREATE TABLE orders (
  id INT PRIMARY KEY,
  user_id INT,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 命名外键，便于后续修改或删除
CREATE TABLE orders (
  id INT PRIMARY KEY,
  user_id INT,
  CONSTRAINT fk_user FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 修改表添加
ALTER TABLE orders
ADD CONSTRAINT fk_user FOREIGN KEY (user_id) REFERENCES users(id);
```

### 删除与查看外键

```sql
-- 按约束名删除（不是字段名）
ALTER TABLE orders DROP FOREIGN KEY fk_user;

-- 查看外键定义
SHOW CREATE TABLE orders;

-- 或查信息表
SELECT * FROM information_schema.KEY_COLUMN_USAGE
WHERE TABLE_NAME = 'orders';
```

### 注意事项

| 要点 | 说明 |
| --- | --- |
| 引用字段必须是主键或唯一键 | 否则报错 |
| 类型必须匹配 | 数据类型、长度、符号要一致（如 INT 对 INT） |
| 引用表必须存在 | 先创建主表，再创建子表 |
| 引擎必须支持外键 | MyISAM 不支持，需使用 InnoDB |
| 外键值必须存在于主表 | 否则插入失败 |

### 级联操作

主表更新 / 删除时，对子表行为的定义：

| 动作 | 说明 |
| --- | --- |
| CASCADE | 主表更新 / 删除时，子表跟着更新 / 删除 |
| SET NULL | 主表更新 / 删除时，子表字段设为 NULL（字段须允许 NULL） |
| RESTRICT | 子表中有引用时不允许操作主表（默认行为） |
| NO ACTION | 与 RESTRICT 类似（MySQL 实际不区分） |

```sql
-- 删除主表用户时，该用户的所有订单自动删除
CREATE TABLE orders (
  id INT PRIMARY KEY,
  user_id INT,
  CONSTRAINT fk_user FOREIGN KEY (user_id)
    REFERENCES users(id)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);
```

- 外键约束较消耗资源，实践中推荐在应用层保证引用关系。

## CHECK：检查约束

MySQL 8.0+ 支持，限制字段必须满足某个条件。

```sql
CREATE TABLE products (
  id INT PRIMARY KEY,
  price DECIMAL(10, 2),
  CHECK (price >= 0)
);
```

## AUTO_INCREMENT：自增列

自动生成唯一的整数值，通常作为主键使用。

### 语法与规则

```sql
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50)
);
```

- 数据类型必须是整数类型（INT、BIGINT），不能用于 VARCHAR、DATE 等。
- 必须搭配 PRIMARY KEY 或 UNIQUE 使用，否则报错：

```text
Incorrect table definition; there can be only one auto column and it must be defined as a key
```

### 手动插入自增值

```sql
-- 手动指定 id = 10 后，系统从 11 继续自增
INSERT INTO users (id, name) VALUES (10, 'Spike');
INSERT INTO users (name) VALUES ('Tyke');  -- id = 11
```

### 修改起始值和步长

```sql
-- 设置起始值
ALTER TABLE users AUTO_INCREMENT = 100;

-- 设置步长（每次递增 2）
SET @@auto_increment_increment = 2;
```

### 删除记录后编号不回退

```sql
DELETE FROM users WHERE id = 3;
INSERT INTO users (name) VALUES ('Tuffy');  -- id 依然是 4
```

- MySQL 8.0 中自增计数持久化，重启数据库也不会回退。
