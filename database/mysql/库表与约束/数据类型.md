# 数据类型

*类型：knowledge ｜ 难度：基础 ｜ 标签：MySQL、数据类型、表设计 ｜ 更新：2026-09-22*

**选对数据类型是表设计的第一课：整数按范围选 TINYINT 到 BIGINT；金额必须用 DECIMAL，FLOAT/DOUBLE 有精度误差；字符串默认 VARCHAR，长度固定才用 CHAR，TEXT 不能整列做索引；时间首选 DATETIME（不受时区影响），TIMESTAMP 只到 2038 年且受时区约束。两个易混点——LENGTH 数字节、CHAR_LENGTH 数字符，长度定义的「字符」与存储字节因字符集而异；BOOLEAN 只是 TINYINT(1) 的别名。**

## 数值类型

### 整数类型

| 类型 | 占用空间 | 范围（有符号） | 范围（无符号） |
| --- | --- | --- | --- |
| TINYINT | 1 字节 | -128 ~ 127 | 0 ~ 255 |
| SMALLINT | 2 字节 | -32,768 ~ 32,767 | 0 ~ 65,535 |
| MEDIUMINT | 3 字节 | 约 -838 万 ~ 838 万 | 0 ~ 约 1677 万 |
| INT / INTEGER | 4 字节 | 约 -21 亿 ~ 21 亿 | 0 ~ 约 42 亿 |
| BIGINT | 8 字节 | 非常大 | 更大 |

### 浮点型与定点型

| 类型 | 说明 |
| --- | --- |
| FLOAT | 单精度浮点数（4 字节） |
| DOUBLE | 双精度浮点数（8 字节） |
| DECIMAL(m, d) | 定点数，用于存储精确小数（如金额） |

- 金额类数据必须用 DECIMAL，不要用 FLOAT/DOUBLE，后者有精度误差。
- DECIMAL 的范围由 m 和 d 决定，占用空间为 m + 2。
- DECIMAL 不指定 m 和 d 时，默认为 (10, 0)。

## 字符串类型

| 类型 | 说明 |
| --- | --- |
| CHAR(n) | 定长字符串，最多 255 字符 |
| VARCHAR(n) | 变长字符串，最多 65535 字节（受编码限制） |
| TEXT | 长文本，最多 64KB |
| TINYTEXT | 最多 255 字节 |
| MEDIUMTEXT | 最多 16MB |
| LONGTEXT | 最多 4GB |

### CHAR 与 VARCHAR

- 长度定义的是「字符」不是字节，实际存储与字符集有关（如 utf8 中一个汉字占 3 字节）。

| 比较项 | CHAR(n) | VARCHAR(n) |
| --- | --- | --- |
| 是否定长 | 是 | 否，变长 |
| 空间占用 | 固定分配 n 个字符的空间 | 实际内容长度 + 1~2 字节长度信息 |
| 存储性能 | 更快（定长结构，容易缓存） | 稍慢（每行长度不一致，处理复杂） |
| 末尾空格处理 | 自动填充并保留 | 不保留末尾空格（自动截断） |
| 适用场景 | 长度一致的短字符串（国家代码、性别等） | 可变长度字符串（用户名、邮箱等） |
| 最大长度 | 255 个字符 | 65535 字节（受行最大限制影响） |

```sql
-- CHAR(2) 永远占两个字符：'US' 或补空格后的 'U ' 都一样
CREATE TABLE country (
  code CHAR(2),
  name VARCHAR(100)
);

-- VARCHAR 按实际内容存储：'Tom' 占 3 字符 + 1 长度字节
CREATE TABLE user (
  id INT,
  nickname VARCHAR(20)
);
```

末尾空格处理差异：

```sql
-- CHAR 保留末尾空格，VARCHAR 自动截掉
SELECT LENGTH(CHAR_FIELD) FROM t;
SELECT LENGTH(VARCHAR_FIELD) FROM t;
```

选型建议：

| 场景 | 推荐类型 |
| --- | --- |
| 性别、国别码等位数固定的字段 | CHAR |
| 用户名、邮箱、地址等长度不定字段 | VARCHAR |
| 数据量大且字段长度一致、性能优先 | CHAR |
| 节省空间优先 | VARCHAR |

### TEXT 类

| 类型 | 最大长度 | 用途示例 |
| --- | --- | --- |
| TINYTEXT | 255 字符 | 短文本：评论、标签、标题 |
| TEXT | 65,535 字符（64 KB） | 一般的文章内容、评论 |
| MEDIUMTEXT | 16,777,215 字符（16 MB） | 中等长度文本：日志、文章 |
| LONGTEXT | 4,294,967,295 字符（4 GB） | 超长文本：小说、备份 |

```sql
CREATE TABLE articles (
  id INT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(255),
  content TEXT
);
```

注意事项：

- TEXT 不能直接作为 PRIMARY KEY 或 UNIQUE KEY，只能指定前缀长度做部分索引，且索引性能差。
- 大文本查询需要额外 I/O，无索引时性能问题明显。
- 短文本用 VARCHAR 更高效，不浪费存储空间。
- TEXT 存字符数据，BLOB 存二进制数据，两者容量限制相似但用途不同。

## 日期和时间类型

| 类型 | 示例 | 描述 | 小数秒（5.6.4+） |
| --- | --- | --- | --- |
| DATE | '2025-03-20' | 只含日期，YYYY-MM-DD | 不支持 |
| TIME | '12:34:56' | 只含时间，hh:mm:ss | 支持毫秒~微秒 |
| DATETIME | '2025-03-20 12:34:56' | 日期 + 时间，业务记录常用 | 支持毫秒~微秒 |
| TIMESTAMP | '2025-03-20 12:34:56' | 类似 DATETIME，与时区强相关 | 支持毫秒~微秒 |
| YEAR | 2025 | 只存年份（1901–2155） | 不支持 |

### YEAR

- 存储 4 位年份，范围 1901 ~ 2155；0000 需明确指定才可存入。

```sql
INSERT INTO t (graduation_year) VALUES (2025);
INSERT INTO t (graduation_year) VALUES ('2025');
INSERT INTO t (graduation_year) VALUES ('25'); -- 自动补成 2025
```

- 两位年份按切换点规则转换：00–69 转 2000–2069，70–99 转 1970–1999。
- 尽量避免插入两位年份，容易产生歧义。

### DATE

- 格式 'YYYY-MM-DD'，占 3 字节，范围 1000-01-01 ~ 9999-12-31，无时间部分、与系统时区无关。

```sql
INSERT INTO holidays (name, holiday_date) VALUES ('元旦', '2025-01-01');

-- 查询今天的记录
SELECT * FROM events WHERE event_date = CURRENT_DATE;

-- 查询某个月的数据
SELECT * FROM events
WHERE event_date BETWEEN '2025-03-01' AND '2025-03-31';

-- 计算距离今天还有几天；提取年月日
SELECT DATEDIFF('2025-12-25', CURRENT_DATE) AS days_left;
SELECT YEAR(birthday), MONTH(birthday), DAY(birthday) FROM users;
```

- 插入非法日期（如 '2025-02-30'）会报错或变成 '0000-00-00'，取决于 SQL 模式。
- NULL 与 '0000-00-00' 是不同的值，是否允许取决于 SQL 模式。
- DATE 是常见的索引字段（订单日期、注册日期等）。

### TIME

- 格式 'hh:mm:ss'，范围 -838:59:59 ~ 838:59:59（支持超过 24 小时与负时间段，可用于表示时间间隔）。

```sql
-- 精度可选：TIME(0) 秒、TIME(3) 毫秒、TIME(6) 微秒
INSERT INTO schedule (start_time) VALUES ('08:30:00');
```

- MySQL 接受多种缩写格式：'10:20' 存为 '10:20:00'，'3:5:9' 存为 '03:05:09'。

```sql
SELECT CURTIME();               -- 当前时间，如 '16:45:22'
SELECT SEC_TO_TIME(3661);       -- 秒转时间：'01:01:01'
SELECT SUBTIME('08:30:00', '07:15:00');  -- 时间差：'01:15:00'
```

### DATETIME

最通用的时间类型，记录一个具体时间点：不受时区影响、支持微秒精度，是业务时间字段的首选。

- 格式 'YYYY-MM-DD HH:MM:SS'，范围 '1000-01-01 00:00:00' ~ '9999-12-31 23:59:59'。
- 占 8 字节（无小数秒），带小数秒时 9~13 字节；精度 DATETIME(fsp)，fsp 取 0~6。
- 不支持时区自动换算，可以加索引、做范围查询，效率好。

```sql
INSERT INTO logs (log_time) VALUES ('2025-03-20 14:45:00');
INSERT INTO logs (log_time) VALUES (NOW());

-- 查询今天的记录
SELECT * FROM logs WHERE DATE(log_time) = CURDATE();

-- 精确到毫秒
CREATE TABLE t (
  created_at DATETIME(3)  -- 如 2025-03-20 14:45:30.123
);

-- 自动记录插入和更新时间，常见于「最后修改时间」场景
CREATE TABLE orders (
  id INT PRIMARY KEY,
  customer_id INT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

- 插入非法格式（如 '2025-02-30 00:00:00'）会报错；只给日期部分时时间默认补成 '00:00:00'。
- 不要用字符串存时间，否则失去时间函数与类型支持。

### TIMESTAMP

紧凑高效、支持自动更新的时间戳类型，适合记录服务器时间点、日志、审计信息。

- 实际存储 UTC 时间，查询时按 MySQL 的 time_zone 设置自动转换为本地时间。

```sql
SET time_zone = '+00:00';
SELECT CURRENT_TIMESTAMP;  -- 比北京时间少 8 小时

SET time_zone = '+08:00';
SELECT CURRENT_TIMESTAMP;  -- 显示北京时间
```

- 范围 '1970-01-01 00:00:01' ~ '2038-01-19 03:14:07'（32 位 Unix 时间戳限制）。
- 占 4 字节（无小数秒），支持精度 TIMESTAMP(3) 等。
- 支持 DEFAULT CURRENT_TIMESTAMP 与 ON UPDATE CURRENT_TIMESTAMP。

```sql
CREATE TABLE logs (
  id INT PRIMARY KEY,
  message VARCHAR(100),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

注意事项：

- 超过 2038 年会出错。
- 时区切换会影响显示值，迁移数据或修改时区配置前要小心。
- 一个表中自动更新的时间戳字段有限制（5.6.5 之前只允许一个 ON UPDATE CURRENT_TIMESTAMP）。
- 未声明为 NULL 时，插入 NULL 会报错（除非显式允许）。

### DATETIME vs TIMESTAMP

| 对比点 | DATETIME | TIMESTAMP |
| --- | --- | --- |
| 存储方式 | 格式化存储的本地时间 | UTC 时间戳（Unix time） |
| 时区影响 | 不受时区影响 | 与当前时区有关 |
| 存储范围 | 1000-01-01 ~ 9999-12-31 | 1970-01-01 ~ 2038-01-19 |
| 默认值支持 | 早期版本不支持 CURRENT_TIMESTAMP 默认值 | 支持 DEFAULT CURRENT_TIMESTAMP |
| 占用空间 | 8 字节 | 4 字节（随精度增加） |
| 推荐场景 | 普通业务时间（创建时间等） | 系统日志、多服务器同步的事件时间戳 |

开发建议：一般业务用 DATETIME 避免时区干扰；跨服务器、多时区的日志同步场景用 TIMESTAMP。

## 布尔类型（BOOLEAN）

MySQL 没有真正的 BOOLEAN，它是 TINYINT(1) 的别名：TRUE = 1，FALSE = 0。

```sql
CREATE TABLE example (
  is_active BOOLEAN  -- 实际就是 TINYINT(1)
);
```

## 枚举与集合（ENUM / SET）

### ENUM

从一组预定义值中选择一个值，本质是字符串类型但按整数存储。

```sql
CREATE TABLE user (
  id INT PRIMARY KEY,
  gender ENUM('Male', 'Female', 'Other') NOT NULL
);
```

- 以整数形式存储，占 1~3 字节（取决于选项个数）。
- 比较时按定义顺序转换为整数。
- 优点：比 VARCHAR 省空间，且能阻止无效值插入。
- 缺点：改选项集需要修改表结构，扩展性差。

### SET

从一组预定义值中选择零个或多个值，按位图（bitmap）存储。

```sql
CREATE TABLE user (
  id INT PRIMARY KEY,
  hobbies SET('Reading', 'Swimming', 'Traveling', 'Gaming') NOT NULL
);
```

- 可以存 'Reading,Traveling' 这样的组合值。
- 优点：一个字段存多个选项，适合兴趣、权限等组合场景。
- 缺点：多选项查询复杂（通常要 FIND_IN_SET 或位操作），改选项集同样要改表结构。

### ENUM 与 SET 对比

| 特性 | ENUM | SET |
| --- | --- | --- |
| 存储方式 | 整数存储，一个值代表一个选项 | 位图存储，每个选项占一位 |
| 值的选择 | 每个字段只能选一个值 | 可以选多个值 |
| 适用场景 | 互斥选项（性别、状态） | 可组合选项（兴趣、权限） |
| 查询复杂度 | 较简单 | 较复杂，需 FIND_IN_SET 或位操作 |
| 最大选项数 | 65,535 个（实际较少用） | 64 个 |

选型：互斥、固定有序的选择项用 ENUM；需要多选组合用 SET。

## JSON 类型

MySQL 5.7+ 原生支持，自动验证 JSON 格式，并以优化的二进制格式存储（比纯文本更高效）。

```sql
CREATE TABLE example (
  id INT PRIMARY KEY,
  data JSON
);
```

常用操作：

```sql
-- 插入 JSON 字符串，MySQL 自动验证合法性
INSERT INTO example (id, data)
VALUES (1, '{"name": "Alice", "age": 25, "is_member": true}');

-- -> 提取字段（返回 JSON 格式值）
SELECT data->'$.name' AS name
FROM example
WHERE id = 1;

-- JSON_SET 修改指定键值
UPDATE example
SET data = JSON_SET(data, '$.age', 26)
WHERE id = 1;

-- 数组：插入与按下标提取
INSERT INTO example (id, data)
VALUES (2, '{"tags": ["web", "development", "mysql"]}');
SELECT data->'$.tags[0]' AS first_tag FROM example WHERE id = 2;

-- 数组长度 / 对象键数量
SELECT JSON_LENGTH(data->'$.tags') AS tags_count FROM example WHERE id = 2;
```

查询运算符与函数：

- `->` 提取值（返回 JSON 格式）；`->>` 提取值并转为文本。
- JSON_EXTRACT() 按路径提取；JSON_UNQUOTE() 去引号。

通过生成列（Generated Column）建立索引：

```sql
-- 基于JSON字段生成 STORED 列，再对生成列建索引
CREATE TABLE example (
  id INT PRIMARY KEY,
  data JSON,
  name VARCHAR(255) GENERATED ALWAYS AS (data->>'$.name') STORED
);

CREATE INDEX idx_name ON example(name);
```

适用场景：结构不固定的配置数据、API 数据交换、日志存储、用户自定义的动态属性。

## 位类型（BIT）

存储二进制位（0 和 1），适合表示开关、权限、状态等位图信息，操作复杂、一般不推荐新手使用。

```sql
CREATE TABLE users (
  id INT,
  permissions BIT(8)
);
```

## 二进制类型

| 类型 | 特点 | 适用场景 |
| --- | --- | --- |
| BINARY | 固定长度二进制 | 长度固定的二进制数据（如加密摘要） |
| VARBINARY | 可变长度二进制 | 长度不固定的二进制数据 |
| BLOB | 大二进制，最大 4 GB | 大文件数据（图像、音频、视频） |
| TINYBLOB | 最大 255 字节 | 小型二进制数据（小图标） |
| MEDIUMBLOB | 最大 16 MB | 中等大小的二进制数据 |
| LONGBLOB | 最大 4 GB | 非常大的二进制数据 |
