# 运算符

*类型：knowledge ｜ 难度：基础 ｜ 标签：MySQL、运算符、WHERE ｜ 更新：2026-09-22*

**运算符是 SQL 表达式的零件：算术、比较、逻辑三大类覆盖日常过滤，关键字式比较（IS NULL / BETWEEN / IN / LIKE）专门处理空值、区间、集合与模式匹配。两个最容易踩的坑：与 NULL 的任何比较结果都是 NULL 而不是 FALSE，判空只能用 IS NULL 或安全等于 <=>；AND 与 OR 混用时按 NOT > AND > OR 结合，拿不准就加括号。**

## 算术运算符

主要用于数值类型的字段或表达式之间的计算，常用于 SELECT 查询、UPDATE 赋值等语句。

| 运算符 | 含义 | 示例 |
| --- | --- | --- |
| `+` | 加法 | `a + b` |
| `-` | 减法 | `a - b` |
| `*` | 乘法 | `a * b` |
| `/` | 除法 | `a / b` |
| `%` | 取模（求余） | `a % b` |

注意事项：

- `/` 在整数除法中结果可能是小数，取决于字段的数据类型。
- `%` 在 MySQL 中可直接用于模运算（不同于某些方言，如 Oracle 使用 MOD(a, b)）。
- 空值参与计算时，结果为 NULL：

```sql
SELECT NULL + 5;  -- 结果为 NULL
```

## 比较运算符

用于比较两个值的大小、是否相等，通常出现在 WHERE 子句中过滤数据。

| 运算符 | 含义 | 示例 |
| --- | --- | --- |
| `=` | 等于 | `price = 10` |
| `<=>` | 安全等于 | `price <=> 10` |
| `<>` / `!=` | 不等于 | `price <> 10` |
| `>` | 大于 | `price > 10` |
| `<` | 小于 | `price < 10` |
| `>=` | 大于等于 | `price >= 10` |
| `<=` | 小于等于 | `price <= 10` |

### 等号 = 的隐式转换

- 字符串与数字比较存在隐式转换，转换不成功则视为 0。
- 两边都是字符串时，按 ANSI 比较规则比较。
- 只要有一边是 NULL，比较结果就为 NULL。

```sql
SELECT 1 = 2, 1 = '1', 1 = 'a', 0 = 'a' FROM DUAL;
-- 结果：0  1  0  1（'a' 转不成数字，被视为 0）
```

### 安全等于 <=>

- 专门用于判断 NULL：NULL 与 NULL 比较返回 1。
- 唯一能正确判断 NULL 的比较运算符，其余比较符遇 NULL 都返回 NULL。

## 关键字式比较运算符

除了通用比较符，SQL 还提供一批关键字式的比较语法，覆盖集合、区间、模式匹配等场景。

| 类型 | 运算符 |
| --- | --- |
| 空值判断 | IS NULL、IS NOT NULL |
| 范围判断 | BETWEEN、NOT BETWEEN |
| 集合判断 | IN、NOT IN |
| 模式匹配 | LIKE、NOT LIKE、REGEXP、NOT REGEXP |
| 布尔值判断 | IS TRUE、IS FALSE、IS UNKNOWN |
| 子查询判断 | EXISTS、NOT EXISTS |

### 空值判断

```sql
SELECT last_name, salary
FROM employees
WHERE commission_pct IS NOT NULL;

-- 等价的函数写法
SELECT last_name, salary
FROM employees
WHERE ISNULL(commission_pct);
```

### 范围判断

- BETWEEN a AND b 判断是否在区间 [a, b] 内，含边界。
- 上下限 a、b 不能交换顺序。

```sql
SELECT * FROM products
WHERE price BETWEEN 3 AND 6;
```

### 集合判断

```sql
SELECT * FROM products
WHERE name IN ('Apple', 'Mango');
```

### 模式匹配

- `%`：匹配任意多个字符（包括 0 个）。
- `_`：匹配任意一个字符。
- 需要匹配字符 `_` 本身时，使用转义符 `\`。

```sql
-- 查询以 'A' 开头的商品名
SELECT * FROM products
WHERE name LIKE 'A%';

-- 查询名称中包含 "an" 的商品
SELECT * FROM products
WHERE name LIKE '%an%';
```

### 布尔判断

- IS TRUE / IS FALSE 判断布尔表达式的真假。
- IS UNKNOWN 判断结果是否为 UNKNOWN（通常对应 NULL）。

### EXISTS

- EXISTS (子查询) 判断子查询是否返回了至少一行，NOT EXISTS 反之。

## 逻辑运算符

用于组合多个判断条件，一般用在 WHERE、HAVING 等子句中，最终返回 TRUE / FALSE / UNKNOWN。

```sql
-- AND：两个条件都成立才为真
SELECT * FROM products WHERE price > 3 AND stock < 50;

-- OR：只要有一个条件成立就为真
SELECT * FROM products WHERE price < 2 OR stock > 100;

-- NOT：取反
SELECT * FROM products WHERE NOT price = 5;

-- XOR：异或，恰好一个条件成立才为真
SELECT * FROM products WHERE price < 2 XOR stock > 100;
```

### 逻辑优先级

默认结合顺序为 NOT > AND > OR。

```sql
-- 容易歧义：AND 先于 OR 结合，实际含义可能不是你想要的
SELECT * FROM products
WHERE price > 3 OR price < 2 AND stock > 50;

-- 推荐加括号明确意图
SELECT * FROM products
WHERE price > 3 OR (price < 2 AND stock > 50);
```

### NULL 的特殊情况

- NULL 不是 TRUE 也不是 FALSE，而是 UNKNOWN。
- 条件结果为 UNKNOWN 的行不会被选中，一些「看起来没问题」的过滤因此失效。

```sql
-- 如果 discount 是 NULL，条件返回 UNKNOWN 而非 FALSE，该行不会出现
SELECT * FROM products
WHERE discount > 0.9;

-- 正确做法：先排除 NULL
SELECT * FROM products
WHERE discount IS NOT NULL AND discount > 0.9;
```

## 位运算符

直接对整数的二进制位操作，适用于权限标志位、状态组合、压缩存储的整型字段等场景。

| 运算符 | 名称 | 含义 | 示例 |
| --- | --- | --- | --- |
| `&` | 按位与 | 两位都为 1，结果为 1 | `6 & 3 = 2` |
| `\|` | 按位或 | 有一位为 1，结果为 1 | `6 \| 3 = 7` |
| `^` | 按位异或 | 不同为 1，相同为 0 | `6 ^ 3 = 5` |
| `~` | 按位取反 | 所有位取反（补码） | `~6 = -7` |
| `<<` | 左移 | 低位补 0，相当于乘以 2 的幂 | `3 << 2 = 12` |
| `>>` | 右移 | 高位补符号位，相当于除以 2 的幂 | `8 >> 2 = 2` |

注意事项：

- 位运算只能用于整数类型字段。
- `~` 的结果是负数，因为 MySQL 按补码处理。
- 在业务层维护权限位时，应封装好权限掩码，避免魔法数字。

## 运算符优先级

多个运算符组合时按优先级解析，了解它可以避免「我写的不是我想的」。

| 优先级 | 运算符 | 类型 | 示例 |
| --- | --- | --- | --- |
| 1 | `()` | 括号 | `(price + tax) * 0.9` |
| 2 | `*`、`/`、`%` | 算术运算 | `price * 1.05` |
| 3 | `+`、`-` | 算术运算 | `price - discount` |
| 4 | `=`、`!=`、`<`、`>`、`<=`、`>=`、IS、LIKE、BETWEEN、IN | 比较运算 | `price >= 100` |
| 5 | NOT | 逻辑非 | `NOT price > 5` |
| 6 | AND | 逻辑与 | `price > 3 AND stock > 10` |
| 7 | OR | 逻辑或 | `stock < 10 OR price < 2` |

推荐习惯：

- 始终用括号明确逻辑组合，特别是 AND 与 OR 混用时。
- 括号更安全、清晰、可维护，调试时也便于分块分析。
