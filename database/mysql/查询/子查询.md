# 子查询

*类型：knowledge ｜ 难度：基础 ｜ 标签：MySQL、子查询、SQL ｜ 更新：2026-09-22*

**子查询是嵌套在另一个查询里的 SELECT，被括号包裹，可以出现在 SELECT、FROM、WHERE、HAVING 中，按返回结果的形状分为标量（一个值）、列（一列多行）、表（整张临时表）三类。选用原则：搭配 =、> 等运算符时必须只返回一个值；取一列做过滤用 IN / EXISTS；需要关联展示子表字段时优先 JOIN，数据量大、性能敏感时 JOIN 通常也优于子查询。**

## 什么是子查询

子查询是嵌套在另一个 SQL 查询中的查询语句，可以看成一个「临时产生的结果表」，在主查询中被引用。

- 子查询必须包含在括号 () 中。
- 可以出现在 SELECT、FROM、WHERE、HAVING 等位置。

## 三种常见类型

### 标量子查询

子查询只返回一个值（一个单元格）：

```sql
-- 比较每位员工的工资是否高于全体平均值
SELECT first_name, salary
FROM employees
WHERE salary > (
  SELECT AVG(salary)
  FROM employees
);
```

### 列子查询

子查询返回一列多行：

```sql
-- 拿出所有在 1700 地点的部门中的员工
SELECT first_name, department_id
FROM employees
WHERE department_id IN (
  SELECT department_id
  FROM departments
  WHERE location_id = 1700
);
```

### 行 / 表子查询

子查询返回一整行或一整张表，整个结果被当成临时表，外层可以继续筛选、排序：

```sql
SELECT *
FROM (
  SELECT department_id, AVG(salary) AS avg_sal
  FROM employees
  GROUP BY department_id
  HAVING AVG(salary) > 10000
) AS high_salary_departments;
```

## 搭配的操作符

| 操作符 | 用法说明 |
| --- | --- |
| IN | 是否属于子查询返回的列表 |
| EXISTS | 子查询是否返回了至少一行 |
| =、<、> | 搭配标量子查询使用 |
| ANY、ALL | 与集合比较（高级用法） |

```sql
-- EXISTS：只要某个部门下存在员工，就返回该部门
SELECT d.department_name
FROM departments d
WHERE EXISTS (
  SELECT 1
  FROM employees e
  WHERE e.department_id = d.department_id
);
```

- EXISTS 判断「存在性」，子查询大时通常比 IN 更高效。

## 子查询 vs JOIN 的选择

| 情况 | 建议用法 |
| --- | --- |
| 只取结果，不用关联额外字段 | 子查询（简洁） |
| 需要拿子表中的字段一起展示 | JOIN（扩展性强） |
| 数据量大、性能敏感 | JOIN 通常更好 |

## 注意事项

- 子查询不能返回多列（除非用在 FROM 中当作表）。
- 在 =、> 等运算符后，子查询必须只返回一个值。
- 子查询的性能可能不如 JOIN，尤其在大数据量时；早期 MySQL 对子查询的优化能力较弱。

典型应用场景：

- 比较某个值是否高于平均（标量子查询）。
- 从另一个表取一列做过滤（列子查询）。
- 构造临时表做进一步查询（表子查询）。
- 替代 JOIN 做权限或数据隔离（如多租户）。
