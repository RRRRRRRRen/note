# 多表查询

*类型：knowledge ｜ 难度：基础 ｜ 标签：MySQL、JOIN、UNION ｜ 更新：2026-09-22*

**多表查询按连接条件把多张表横向拼接：n 张表至少需要 n-1 个连接条件，否则产生笛卡尔积。按维度分类——连接条件用 = 是等值连接（走索引、性能好），用区间等是非等值连接；同一张表 join 自己是自连接（必须起别名区分字段）；内连接只留匹配行，外连接（LEFT / RIGHT）保留单侧全部行、缺失侧补 NULL，MySQL 不支持 FULL JOIN 需用 UNION 模拟。而 UNION 是纵向的行合并，与 JOIN 的横向列合并互补。**

## 使用别名

可以在 SELECT 和 WHERE 中使用表的别名：

```sql
SELECT dep.dept_name, depm.emp_no
FROM departments dep, dept_manager depm
WHERE dep.dept_no = depm.dept_no;
```

- 一旦在 FROM 中定义了别名，就必须在 SELECT 和 WHERE 中使用别名，不能再使用原名，否则报错。

## 连接条件

- 没有连接条件会出现笛卡尔积错误（行数 = 两表行数之积）。
- n 个表做多表查询，至少需要 n-1 个连接条件。

```sql
SELECT t1.dept_name, t3.first_name, t3.last_name
FROM departments t1, dept_manager t2, employees t3
WHERE t1.dept_no = t2.dept_no
  AND t2.emp_no = t3.emp_no;
```

## 多表查询的分类

### 等值连接与非等值连接

**等值连接**：连接条件是「等于」（=），常用于两表有主外键关系。

```sql
SELECT e.name, d.name
FROM employees e
JOIN departments d ON e.dept_id = d.id;
```

- 几乎所有的 INNER JOIN 都是等值连接。
- 可以是 INNER JOIN、LEFT JOIN、RIGHT JOIN 等形式。

**非等值连接**：连接条件使用非等于关系（>、<、>=、<=、BETWEEN、LIKE 等）。

```sql
-- 员工表 employees 与工资等级表 salary_grades，
-- 按薪资落在哪个区间匹配等级
SELECT e.name, e.salary, g.grade
FROM employees e
JOIN salary_grades g
  ON e.salary BETWEEN g.min_salary AND g.max_salary;
```

- 常见于分类、打标签、区间分组的业务。
- 性能相对差一些（不能直接走等值哈希连接 / 索引优化）。

| 比较项 | 等值连接 | 非等值连接 |
| --- | --- | --- |
| 连接条件 | 使用 = | 使用 <>、>、<、BETWEEN 等 |
| 使用场景 | 主外键关联、字段一致时 | 区间查找、分级、标签匹配 |
| 性能 | 一般更优（可以走索引） | 一般较差 |
| 常见语法 | ON A.id = B.id | ON A.salary BETWEEN B.min AND B.max |

### 自连接与非自连接

**自连接**：一张表和自己 JOIN，相当于「把一张表复制两份再连接」。

```sql
-- 查询每位员工的上司名字：
-- 本质是把 employees 用两次，用别名 e1、e2，通过 manager_id 匹配 id
SELECT e1.name, e2.name
FROM employees e1, employees e2
WHERE e1.manager_id = e2.employee_id;
```

典型场景：

- 组织结构表中的上级 / 下级关系。
- 树形结构表（菜单、分类）中的父子节点关系。

注意：

- 必须使用别名，否则同名字段（如两个 id）无法区分。
- 自连接可以使用任意 JOIN 类型（INNER / LEFT / RIGHT）。

**非自连接**：最常见的两张不同表的 JOIN。

| 特性 | 自连接 | 非自连接 |
| --- | --- | --- |
| 表数量 | 1 张表参与 2 次 | 2 张或更多不同表 |
| 是否必须起别名 | 必须，否则字段无法区分 | 推荐使用，防止字段冲突 |
| 应用场景 | 树形结构、父子关系、上下级 | 各种实体之间的关联 |
| 性能差别 | 基本一样 | 取决于索引与数据量 |

### 内连接与外连接

内连接只返回两表中匹配的记录，不匹配的行被过滤；外连接把不匹配的行也查出来，用 NULL 填充空位。

**内连接（INNER JOIN）**

```sql
SELECT u.name, o.order_no
FROM users u
INNER JOIN orders o ON u.id = o.user_id;
```

- INNER JOIN 等价于 JOIN，JOIN 是 INNER JOIN 的简写。
- 以 users（Alice、Bob、Charlie）与 orders（挂在 Alice、Bob 名下）为例：结果只含 Alice、Bob 的订单，Charlie 因没有订单被过滤掉。

**左外连接（LEFT JOIN）**

- 保留左表所有行，右表匹配不上就用 NULL 补。

```sql
SELECT u.name, o.order_no
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;
-- Charlie 被保留，order_no 显示 NULL
```

**右外连接（RIGHT JOIN）**

- 保留右表所有行，左表匹配不上就 NULL 补，与 LEFT JOIN 角度相反。

**全外连接（FULL JOIN）**

- 保留两表所有行，没匹配上的位置都用 NULL 补。
- MySQL 不支持 FULL JOIN，用 UNION 模拟：

```sql
SELECT * FROM users u
LEFT JOIN orders o ON u.id = o.user_id
UNION
SELECT * FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;
```

| 类型 | 保留左表 | 保留右表 | 不匹配时 |
| --- | --- | --- | --- |
| INNER JOIN | 否 | 否 | 不保留 |
| LEFT JOIN | 是 | 否 | 用 NULL 补右边 |
| RIGHT JOIN | 否 | 是 | 用 NULL 补左边 |
| FULL JOIN | 是 | 是 | 两边都补 NULL（MySQL 不支持） |

实战建议：

- 大多数场景用 INNER JOIN（更高效）。
- LEFT JOIN 用于查「可能不存在」的信息，如所有用户 + 他们的订单。
- RIGHT JOIN 很少用，多数场景可以调整表顺序改写成 LEFT JOIN。

## JOIN ON 语法

### 通用语法结构

```sql
SELECT 字段列表
FROM 表A
JOIN_TYPE 表B
ON 连接条件
[WHERE 条件]
[ORDER BY ...]
[LIMIT ...];
```

JOIN_TYPE 常见取值：INNER JOIN、LEFT JOIN、RIGHT JOIN、FULL JOIN（MySQL 不支持，需用 UNION）、CROSS JOIN、SELF JOIN（表连接自己，仍用以上语法）。

### 各类型示例

以 users 表与 orders 表为例：

```sql
-- INNER JOIN：只选出两表中都匹配的行，可简写为 JOIN
SELECT u.name, o.order_no
FROM users u
JOIN orders o ON u.id = o.user_id;

-- LEFT JOIN：保留左表全部，右表匹配不上用 NULL
SELECT u.name, o.order_no
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

-- RIGHT JOIN：保留右表全部，左表匹配不上用 NULL
SELECT u.name, o.order_no
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- FULL OUTER JOIN：MySQL 不支持，用 UNION 模拟
SELECT u.name, o.order_no
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
UNION
SELECT u.name, o.order_no
FROM users u
RIGHT JOIN orders o ON u.id = o.user_id;

-- CROSS JOIN：笛卡尔积，每一行对每一行，慎用
-- users 3 条 x orders 2 条 = 6 条记录
SELECT u.name, o.order_no
FROM users u
CROSS JOIN orders o;
```

记忆图示：

```text
INNER JOIN   ->  A ∩ B（都存在）
LEFT JOIN    ->  A ⟕ B（左表全保留）
RIGHT JOIN   ->  A ⟖ B（右表全保留）
FULL JOIN    ->  A ∪ B（都保留，MySQL 用 UNION 模拟）
CROSS JOIN   ->  A × B（笛卡尔积）
```

注意事项：

- 强烈建议使用表别名（u、o），避免字段冲突。
- ON 是连接条件，WHERE 是过滤条件，不要混淆。
- JOIN 逻辑不写清楚容易导致笛卡尔积，数据量爆炸。

## UNION 语法

UNION 用于合并多个查询结果集，适合「多个来源的数据整合到一起」的场景。

- 合并的是行（不是列），所有 SELECT 的列数必须相同，类型要兼容。
- 默认去重，想保留重复记录用 UNION ALL。

```sql
-- UNION：得到客户和供应商中所有姓名，不重复
SELECT name FROM customers
UNION
SELECT name FROM suppliers;

-- UNION ALL：保留重复，性能更好
SELECT name FROM customers
UNION ALL
SELECT name FROM suppliers;
```

限制与注意：

| 限制项 | 说明 |
| --- | --- |
| 列数 | 所有 SELECT 的列数必须一样 |
| 列类型 | 对应列的类型应兼容（int 与 float、varchar 与 text 等） |
| 列名 | 最终结果集的列名以第一个 SELECT 为准 |
| 排序 | 只能写一个 ORDER BY，且写在最后一个 SELECT 之后 |

```sql
-- 对合并结果整体排序
SELECT name, '客户' AS source FROM customers
UNION
SELECT name, '供应商' FROM suppliers
ORDER BY name;
```

典型用途：

- 多张结构相同的表合并（历史表、月表）。
- 不同来源的数据整合为一个结果（客户和员工）。
- 子查询中组合多个条件。

### UNION vs JOIN

| 功能 | UNION | JOIN |
| --- | --- | --- |
| 合并方向 | 纵向（按行合并） | 横向（按列合并） |
| 表结构要求 | 列数一致、类型兼容 | 可不一样，但需有连接条件 |
| 常见用途 | 合并多个查询结果 | 表间数据的逻辑关联 |
| 是否去重 | 默认去重，ALL 保留 | 不涉及去重，取决于连接方式 |
