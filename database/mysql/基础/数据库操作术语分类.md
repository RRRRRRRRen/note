# 数据库操作术语分类

*类型：knowledge ｜ 难度：入门 ｜ 标签：MySQL、SQL、事务 ｜ 更新：2026-09-22*

**SQL 语句按用途分为 DDL、DML、DCL、TCL、DRL 五类：结构定义、数据操作、权限控制、事务控制、数据查询。五类之间最重要的实践分界是可回滚性——DML 在提交前可以 ROLLBACK；而 DDL 和 DCL 一执行就隐式提交、立即生效，永远无法回滚，TRUNCATE 虽然看起来像 DELETE，实际是 DDL，同样不可回滚。**

## 五类语句总览

| 缩写 | 全称 | 作用范围 | 常见关键字 |
| --- | --- | --- | --- |
| DDL | Data Definition Language | 定义结构 | CREATE、ALTER、DROP、RENAME |
| DML | Data Manipulation Language | 操作数据 | INSERT、UPDATE、DELETE |
| DCL | Data Control Language | 权限控制 | GRANT、REVOKE |
| TCL | Transaction Control Language | 控制事务 | BEGIN、COMMIT、ROLLBACK |
| DRL | Data Retrieval Language | 查询数据（可选分类） | SELECT |

## DDL：数据定义语言

用来定义或修改数据库结构：数据库、表、字段、索引等。

| 语句 | 作用说明 |
| --- | --- |
| CREATE | 创建数据库、表、视图等 |
| ALTER | 修改数据库结构 |
| DROP | 删除数据库或表 |
| TRUNCATE | 清空表数据，但保留结构 |
| RENAME | 重命名表或字段 |

MySQL 8.0 起支持 DDL 原子化（Atomic DDL）：DDL 语句执行时具备事务原子性，要么全部成功、要么全部失败，不会留下中间状态。

## DML：数据操作语言

用来对表中的数据进行增、删、改、查。

| 语句 | 作用说明 |
| --- | --- |
| INSERT | 插入新数据行 |
| UPDATE | 修改已有数据 |
| DELETE | 删除数据 |
| SELECT | 查询数据（有时单独归类为 DRL） |

## DCL：数据控制语言

用来定义权限和安全级别。

| 语句 | 作用说明 |
| --- | --- |
| GRANT | 授权用户执行某些操作 |
| REVOKE | 撤销用户权限 |

## TCL：事务控制语言

用于控制事务的执行和一致性。

| 语句 | 作用说明 |
| --- | --- |
| BEGIN | 开始一个事务（某些数据库使用） |
| START TRANSACTION | 开启事务（MySQL 推荐） |
| COMMIT | 提交事务，保存修改 |
| ROLLBACK | 回滚事务，撤销未提交的修改 |
| SAVEPOINT | 设置一个事务保存点 |
| RELEASE SAVEPOINT | 删除保存点 |

## DRL：数据查询语言

有时将 SELECT 单独列为一类，称为数据查询语言。

| 语句 | 作用说明 |
| --- | --- |
| SELECT | 从表中查询数据 |

## 回滚与提交

| 语句类型 | 语句 | 是否可回滚 | 说明 |
| --- | --- | --- | --- |
| DML | INSERT / UPDATE / DELETE | 是 | 未提交前都可以通过 ROLLBACK 撤销 |
| DDL | CREATE / DROP / ALTER / TRUNCATE / RENAME | 否 | 一执行就立即生效，不可回滚 |
| DCL | GRANT / REVOKE | 否 | 权限变更一旦执行即生效，不能撤销 |
| TCL | COMMIT / ROLLBACK / SAVEPOINT | 是 | 本身就是用于事务控制 |
| SELECT | SELECT | 不涉及 | 查询不修改数据，无需回滚 |

三点特别说明：

- DDL 语句是隐式提交事务的：执行 DDL 前会自动提交当前事务，然后再执行自身，所以即使写在事务中也无法回滚。
- TRUNCATE 虽然只是清空表，看似像 DELETE，但它是 DDL 操作，不能回滚。
- MyISAM 引擎的表不支持事务，回滚不会生效；需要事务请使用 InnoDB。
