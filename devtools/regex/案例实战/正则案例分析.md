# 正则案例分析

*类型：practice ｜ 难度：进阶 ｜ 标签：正则、实战案例、环视、反向引用*

**正则的真正掌握靠案例沉淀：本篇覆盖字符串、位置、括号三类的典型实战——精确描述「字符怎么排布」比堆量词更重要，惰性/排除字符组防越界，环视解决「在哪儿插入」，反向引用解决「前后一致」。每个案例先拆解子模式，再看组合逻辑。**

## 字符串匹配案例

### 匹配 HTML 标签的 id 属性

两种思路：惰性匹配「点到为止」，或排除字符组「划清边界」。

```js
let string = '<div id="container" class="main"></div>';

// 思路一：惰性匹配，遇到第一个 " 就停
let regex1 = /id=".*?"/;
// id="      a：匹配 id="
// .*        b：匹配换行符之外的任意字符任意个数
// .*?       c：惰性匹配 b，尽可能少
// id=".*?"  d：开头 a、中间 c、结尾 "

string.match(regex1)[0]; // id="container"

// 思路二：排除字符组，值里不允许出现 "
let regex2 = /id="[^"]*"/;
// id="      a：匹配 id="
// [^"]*     b：匹配任意个非 " 字符
// id="[^"]*"  c：首尾都是 "

string.match(regex2)[0]; // id="container"
```

`[^"]*` 比 `.*?` 意图更明确，也不依赖引擎回溯，优先采用。

### 匹配 16 进制颜色值

6 位完整写法优先于 3 位缩写，靠分支顺序保证：

```js
let string = "#ffbbad #Fc01DF #FFF #ffE";
let regex = /#([a-fA-F\d]{6}|[a-fA-F\d]{3})/g;
// #                       a：匹配 #
// [a-fA-F\d]{6}           b：匹配 6 个 16 进制字符
// [a-fA-F\d]{3}           c：匹配 3 个 16 进制字符
// (b|c)                   d：6 位优先，3 位兜底
// /g                      e：全局匹配

string.match(regex); // ['#ffbbad', '#Fc01DF', '#FFF', '#ffE']
```

若把 `{3}` 写在前面，`#ffbbad` 会被错误地截成 `#ffa` 之类的 3 位匹配——分支命中即停。

### 匹配 24 小时制时间

时和位分别枚举合法取值：

```js
let regex = /^(0?\d|1\d|2[0-3]):(0?|[1-5])\d/;
// 0?\d       a：0 点到 9 点，前导 0 可有可无
// 1\d        b：10 点到 19 点
// 2[0-3]     c：20 点到 23 点
// (a|b|c)    d：小时的全部合法情况
// :          e：冒号分隔
// (0?|[1-5])\d  h：分钟，前导 0 可省略或为 1-5 的十位

regex.test("23:59"); // true
regex.test("02:07"); // true
regex.test("7:09");  // true
```

### 匹配日期（yyyy-mm-dd）

用 `^ $` 锚定整串，月日各自限定合法范围：

```js
var regex = /^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$/;
// \d{4}-                  a：四位年份 + 连字符
// (0[1-9]|1[0-2])-        b：01 到 12 的月份
// (0[1-9]|[12][0-9]|3[01])  c：01 到 31 的日期
// ^ $                     d：锚定开头与结尾，防止部分匹配

regex.test("2017-06-10"); // true
```

该正则只保证格式合法，不校验「2 月 30 日」这类逻辑日期。

### 匹配 Windows 文件路径

盘符、目录、文件名三段式，目录部分允许重复零到多次：

```js
var regex = /^[a-zA-Z]:\\([^\\:*<>|"?\r\n/]+\\)*([^\\:*<>|"?\r\n/]+)?$/;
// ^[a-zA-Z]:              a：盘符 + 冒号
// \\                      b：一个反斜杠（正则中需转义）
// [^\\:*<>|"?\r\n/]+      c：路径段，排除 Windows 非法字符
// (c\\)*                  d：目录名 + 反斜杠，重复任意次
// (c)?                    e：最后的文件名，可有可无（支持以 \ 结尾的目录）

regex.test("F:\\study\\javascript\\regex\\regular expression.pdf"); // true
regex.test("F:\\study\\javascript\\regex\\"); // true
regex.test("F:\\study\\javascript"); // true
regex.test("F:\\"); // true
```

## 位置匹配案例

### 数字千分位分割

环视找到「后面是 3 的倍数个数字」的位置，插入逗号：

```js
let price = '123456789';
let priceReg = /(?=(\d{3})+$)/g;
// (\d{3})+        a：3 个数字为一组
// (\d{3})+$       b：这些组一直延续到结尾
// (?=(\d{3})+$)   c：满足 b 的位置（前面）

price.replace(priceReg, ','); // 123,456,789
```

单串场景够用，但字符串里有多个数字时会误伤开头位置，用 `\B` 限定：

```js
var string = "12345678 123456789";
var reg = /\B(?=(\d{3})+\b)/g;
// (\d{3})+\b      a：连续 3 的倍数个数字后是单词边界
// (?=(\d{3})+\b)  b：a 前面的位置
// \B(...)         c：且该位置不能是开头（非单词边界）

string.replace(reg, ','); // => "12,345,678 123,456,789"
```

### 密码验证字符种类

环视「预检查」开头位置，再放行整体格式：

```js
// 要求同时包含数字和小写字母
var string = 'aa112233aa';
var reg = /^(?=.*[0-9])(?=.*[a-z])[a-zA-Z0-9]{6,12}$/;
// ^(?=.*[0-9])    a：开头位置向右看，必须存在数字
// (?=.*[a-z])     b：开头位置向右看，必须存在小写字母
// [a-zA-Z0-9]{6,12}$  c：整体由 6-12 位字母数字构成

reg.test(string); // true
```

「至少包含两种字符」改用排除法：逐个排除纯单一字符的情况。

```js
var string = 'aa112233aaZZ';
var reg = /(?!^[0-9]{6,12}$)(?!^[a-z]{6,12}$)(?!^[A-Z]{6,12}$)[a-zA-Z0-9]{6,12}$/;
// (?!^[0-9]{6,12}$)   a：不能是纯数字
// (?!^[a-z]{6,12}$)   b：不能是纯小写字母
// (?!^[A-Z]{6,12}$)   c：不能是纯大写字母

reg.test(string); // true
```

## 括号案例

### 匹配成对标签

反向引用保证闭标签与开标签同名：

```js
var regex = /<([^>]+)>[\d\D]*<\/\1>/;
// ([^>]+)   a：分组 1，标签名（至少一个非 > 字符）
// <a>       b：完整开标签
// [\d\D]*   c：任意内容（含换行）
// <\/\1>    d：闭标签，\1 回指分组 1 捕获的名字

regex.test("<title>regular expression</title>"); // true
regex.test("<p>laoyao bye bye</p>");             // true
regex.test("<title>wrong!</p>");                 // false，首尾标签不一致
```

`[\d\D]` 是「任意字符」的写法，比 `.` 多覆盖换行符。

### 日期格式转换

分组提取 + 替换的三种等价写法：

```js
// 将 2021-08-14 转换为 08/14/2021
let string = '2021-08-14';
let reg = /(\d{4})-(\d{2})-(\d{2})/;

// 写法一：$n 模板引用
let result1 = string.replace(reg, '$2/$3/$1');
console.log(result1); // 08/14/2021

// 写法二：替换函数内读 RegExp 全局属性
let result2 = string.replace(reg, () => {
  return RegExp.$2 + '/' + RegExp.$3 + '/' + RegExp.$1;
});
console.log(result2); // 08/14/2021

// 写法三：替换函数参数按顺序接收整体与各分组
let result3 = string.replace(reg, ($0, $1, $2, $3) => {
  return $2 + '/' + $3 + '/' + $1;
});
console.log(result3); // 08/14/2021
```

## 案例沉淀的通用套路

- 值的边界用排除字符组 `[^...]` 划清，优于惰性 `.*?`。
- 格式类校验（日期、时间）逐位枚举合法取值，再用 `^ $` 锚定整串。
- 「在某处插入/校验存在性」用环视；「前后一致」用反向引用。
- 分支多选把长的写前面，避免短分支抢先命中。
- 任意字符（含换行）用 `[\d\D]`，别裸用 `.`。
