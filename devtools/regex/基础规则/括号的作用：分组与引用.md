# 括号的作用：分组与引用

*类型：knowledge ｜ 难度：进阶 ｜ 标签：正则、分组、捕获、反向引用、非捕获分组*

**括号提供分组，让量词能作用于整体、让分支能框住子表达式；更强大的能力是「引用」——在 API 中用 `$1` 提取数据，在正则内部用 `\1` 做反向引用。若只要分组不要引用，用非捕获分组 `(?:p)` 省去捕获开销。**

## 分组和分支结构

这是括号最原始的两个功能。

### 分组

让量词作用于整体而不是单个字符。

```js
// (ab)+ 匹配 ab 这个整体重复出现
var regex = /(ab)+/g;
var string = "ababa abbb ababab";
string.match(regex); // => ["abab", "ab", "ababab"]
```

### 分支结构

把多选分支框在括号内，与前后文组合。

```js
var regex = /^I love (JavaScript|Regular Expression)$/;
regex.test("I love JavaScript"); // => true
regex.test("I love Regular Expression"); // => true
```

## 引用分组

配合环境 API，分组匹配到的数据可以被提取或替换，这是括号最重要的作用。

### 提取数据

以提取 `2017-06-12` 中的年月日为例，三种方式：

```js
var regex = /(\d{4})-(\d{2})-(\d{2})/;
var string = "2017-06-12";

// 方式一：String.prototype.match
// 返回数组：[0] 整体匹配，[1..n] 各分组，之后是 index 与 input
string.match(regex);
// => ["2017-06-12", "2017", "06", "12", index: 0, input: "2017-06-12"]

// 方式二：RegExp.prototype.exec，返回结构与 match 相同
regex.exec(string);

// 方式三：构造函数全局属性 $1 至 $9（执行任意正则操作后即可读）
regex.test(string);
RegExp.$1; // "2017"
RegExp.$2; // "06"
RegExp.$3; // "12"
```

注意：正则带不带 `g` 修饰符，`match` 返回的数组格式不同（带 `g` 时只返回整体匹配数组，不含分组信息）。

### 替换数据

以日期格式化 `2017-06-12` 转 `06/12/2017` 为例，同样三种写法：

```js
var regex = /(\d{4})-(\d{2})-(\d{2})/;
var string = "2017-06-12";

// 方式一：replace 第二参用 $n 模板
string.replace(regex, "$2/$3/$1"); // => "06/12/2017"

// 方式二：replace 第二参为函数，函数内读构造函数属性
string.replace(regex, function () {
  return RegExp.$2 + "/" + RegExp.$3 + "/" + RegExp.$1;
}); // => "06/12/2017"

// 方式三：函数参数按顺序接收整体匹配与各分组
string.replace(regex, function (match, year, month, day) {
  return month + "/" + day + "/" + year;
}); // => "06/12/2017"
```

## 反向引用

在正则本身里引用之前分组捕获的内容，写作 `\1` `\2`……注意 `\1` 代表**上一个分组实际匹配到的内容**，而不是上一个分组写法的简写。

```js
// 匹配分隔符前后一致的日期
var regex = /\d{4}(-|\/|\.)\d{2}\1\d{2}/;
regex.test("2017-06-12"); // true，\1 回指 "-"
regex.test("2017/06/12"); // true，\1 回指 "/"
regex.test("2017.06.12"); // true，\1 回指 "."
regex.test("2016-06/12"); // false，开头是 "-"，后面却是 "/"，不一致
```

### 嵌套括号

以左括号为准，从外到内依次计数：

```js
var regex = /^((\d)(\d(\d)))\1\2\3\4$/;
regex.test("1231231233"); // true
RegExp.$1; // "123"  第 1 组：((\d)(\d(\d)))
RegExp.$2; // "1"    第 2 组：(\d)
RegExp.$3; // "23"   第 3 组：(\d(\d))
RegExp.$4; // "3"    第 4 组：最内层 (\d)
```

### 引用不存在的分组

分组不存在时，`\1` 会被当作字符转义处理，识别为 `\u0001`，不会报错但语义完全变了——写反向引用前先数清括号。

## 非捕获分组

只要分组的「整体作用」，既不在 API 里引用、也不做反向引用时，用 `(?:p)`，不捕获数据。

```js
var regex = /(?:ab)+/g;
var string = "ababa abbb ababab";
string.match(regex); // => ["abab", "ab", "ababab"]
```

效果与捕获分组一致，但不会占用 `$1`、`\1` 的编号。

## 常见误区

- 以为 `\1` 是「第一个分组写法」的缩写：它是第一个分组捕获到的具体内容。
- 以为 `\d{4}(-|\/|\.){1}` 不加 `\1` 也能约束分隔符一致：不加反向引用，三处分隔符可以各不相同。
- 该用非捕获分组时用了捕获分组：多余的捕获会顶乱 `$n` 编号，也让引擎多付捕获开销。
