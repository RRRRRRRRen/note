# 命令速查：初始化、日志与高级操作

*类型：practice ｜ 难度：入门 ｜ 标签：Git、init、config、alias、log、branch、tag、rebase、cherry-pick ｜ 更新：2026-09-22*

**初始化与配置是一次性的环境工程：init 建仓库、config 定身份、alias 省键盘。log 家族负责「看历史」——`--graph` 看拓扑、`--follow` 追改名、`-p` 看内容，`reflog` 是找回误删提交的总入口；分支与标签是两类指针的增删查，标签专用于发布锚点。高级操作里 `rebase -i` 整理自己的未共享历史、cherry-pick 跨分支摘提交——两者都在改写或搬运提交，对已 push 的共享分支要保持警惕。**

## 初始化与配置

```bash
# 在当前目录初始化仓库
git init
# 创建 my-project 目录并初始化仓库
git init my-project

# 设置全局用户名和邮箱（仅需设置一次）
git config --global user.name "your-name"
git config --global user.email "your-email@example.com"

# 查看当前配置
git config --list

# 设置别名（简化命令）
git config --global alias.st status
git config --global alias.co checkout
```

## 历史记录

```bash
# 查看详细提交历史
git log
# 以一行显示简要历史
git log --oneline
# 查看图形化的分支历史
git log --graph --oneline --all
# 查看指定文件的历史（跟踪重命名，改名前的记录也连着看）
git log --follow filename.txt
# 显示每次提交的文件变更统计
git log --stat
# 显示每次提交的具体代码变化
git log -p

# 查看 HEAD 移动历史（包含已删除的提交，用于找回误删内容）
git reflog
# 查看特定分支的移动历史
git reflog show feature-branch
```

- log 看的是「从分支可达的提交」，reflog 看的是「HEAD 走过的路」——reset 之后提交从 log 消失，但 reflog 里还在。

## 分支管理

```bash
# 查看本地分支（当前分支前有 * 标记）
git branch
# 查看所有分支（包括远程分支）
git branch -a
# 查看远程分支
git branch -r

# 创建新分支
git branch feature-branch
# 删除本地分支（已合并才能删除）
git branch -d feature-branch
# 强制删除本地分支
git branch -D feature-branch

# 切换到指定分支（checkout）
git checkout branch-name
# 创建并切换到新分支
git checkout -b new-feature
# 恢复指定文件到指定版本
git checkout HEAD~1 -- filename.txt

# 切换到指定分支（switch，较新版本推荐）
git switch main
# 创建并切换到新分支
git switch -c new-feature
# 切换到上一个分支
git switch -
```

## 标签管理

```bash
# 查看所有标签
git tag
# 创建轻量标签（仅指向提交的指针）
git tag v1.0.0
# 创建附注标签（包含完整元数据，推荐用于发布）
git tag -a v1.0.0 -m "Release version 1.0.0"
# 推送单个标签到远程
git push origin v1.0.0
# 推送所有标签到远程
git push origin --tags
# 删除本地标签
git tag -d v1.0.0
# 删除远程标签
git push origin --delete v1.0.0
```

## 高级操作

### 交互式变基（rebase -i）

```bash
# 将 feature-branch 的提交移植到 main 的最新节点上
git checkout feature-branch
git rebase main

# 交互式变基，修改最近 3 次提交历史
git rebase -i HEAD~3
```

执行后进入编辑器，每行一个提交，把行首的 `pick` 换成对应指令：

| 指令 | 说明 |
| --- | --- |
| `pick` | 保留此提交 |
| `reword` | 保留但修改提交信息 |
| `edit` | 保留但允许修改内容 |
| `squash` | 与前一提交合并（保留提交信息） |
| `fixup` | 与前一提交合并（丢弃提交信息） |
| `drop` | 删除此提交 |

- 黄金法则：只 rebase 自己未 push 的分支——rebase 生成全新哈希链，对已共享分支执行等于改写公共历史。

### 拣选提交（cherry-pick）

```bash
# 将指定提交应用到当前分支
git cherry-pick commit-hash
# 拣选多个不连续的提交
git cherry-pick commit1 commit2 commit3
# 拣选一段范围的提交（不含 commit1）
git cherry-pick commit1..commit3
# 拣选一段范围的提交（含 commit1）
git cherry-pick commit1^..commit3
```
