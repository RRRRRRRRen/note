# 数字证书

*类型：knowledge ｜ 难度：入门 ｜ 标签：HTTPS、数字证书、CA、数字签名、中间人攻击*

**数字证书解决「公钥是谁的」这个信任问题：CA（证书颁发机构）用 Hash 算法对「公钥 + 其他信息」生成摘要，再用 CA 私钥对摘要签名，与原始信息合并成证书。接收方验证时用相同 Hash 算法重算摘要，用 CA 公钥解出证书里的签名摘要，两者一致即证明公钥未被替换——这是阻断中间人攻击的关键，否则中间人可以替换公钥、截获并解密全部通信。**

## 证书的生成

使用 Hash 算法对公钥和其他信息生成摘要，由 CA（证书颁发机构）用私钥对摘要签名，将原始信息与签名合并形成数字证书。

```text
服务器公钥 + 其他信息
        ↓ Hash
      摘要
        ↓ CA 私钥签名
  数字证书 = 原始信息 + 签名
```

## 验证流程

接收方验证流程：

1. 用相同 Hash 算法对证书原始信息生成摘要
2. 用 CA 公钥解密证书中的签名，得到 CA 生成的摘要
3. 对比两个摘要是否一致

```text
收到的证书 ──┬─ 原始信息 ── Hash ──▶ 摘要 A ─┐
             └─ 签名 ── CA 公钥解密 ─▶ 摘要 B ─┴─ 相等则证书可信
```

## 作用：防中间人攻击

若无证书，中间人可替换公钥，截获并解密通信内容，双方无法察觉：

```text
无证书（中间人攻击）            有证书（攻击失败）
客户端 ◀──假公钥──▶ 中间人       客户端验证签名失败
中间人 ◀──真公钥──▶ 服务器       ↓
（中间人明文转述一切）           连接被终止，攻击暴露
```

证书把「服务器声称的公钥」与「CA 的信用背书」绑定——验证不过，通信根本不会开始。
