# 浏览器进程与线程

*类型：knowledge ｜ 难度：入门 ｜ 标签：浏览器、进程、线程、架构*

**进程是资源分配的最小单位，线程是 CPU 调度的最小单位：进程拥有独立资源空间、崩溃互不影响，但通信需要 IPC；线程共享进程资源、通信直接且开销小，但一个线程崩溃可能导致整个进程崩溃。Chrome 采用多进程架构——浏览器进程管「外壳」，每个标签页一个渲染进程，再配 GPU、网络、插件进程，用「多占内存」换来「单页崩溃不拖垮全局」的稳定性与安全性。**

## 进程与线程的区别

| 维度 | 进程 | 线程 |
| --- | --- | --- |
| 定义 | 资源分配的最小单位 | CPU 调度的最小单位 |
| 独立性 | 可独立运行 | 不能独立存在 |
| 资源 | 拥有独立资源空间 | 共享进程资源 |
| 通信 | 需要 IPC | 可直接共享数据 |
| 开销 | 创建和销毁开销大 | 开销小 |
| 崩溃影响 | 不影响其他进程 | 可能导致整个进程崩溃 |

## Chrome 多进程架构

| 进程 | 职责 |
| --- | --- |
| 浏览器进程 | 界面显示、用户交互、子进程管理 |
| 渲染进程 | 每个标签页一个，负责页面渲染、脚本执行、事件处理 |
| GPU 进程 | 3D 绘制和硬件加速 |
| 网络进程 | 网络资源加载 |
| 插件进程 | 每个插件一个 |

架构取舍：

- 优点：标签页崩溃互不影响，安全性和稳定性更好，充分利用多核 CPU
- 缺点：内存占用较大
