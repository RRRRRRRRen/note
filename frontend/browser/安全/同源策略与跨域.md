# 同源策略与跨域

*类型：knowledge ｜ 难度：进阶 ｜ 标签：浏览器、同源策略、跨域、CORS、面试*

**同源策略要求协议、域名、端口三者完全一致，它限制的是浏览器侧的「读」：跨源的 Cookie/存储、DOM、AJAX 响应都被拦截（注意：跨域请求能发出，只是响应被浏览器扣下）。跨域的正统解法是 CORS——关键在服务器配置响应头；JSONP 借 `<script>` 不受同源限制但只支持 GET；postMessage 解决多窗口间通信；代理服务器则利用「同源策略只限制浏览器」这一点，让同源代理转发请求。**

## 同源策略

协议、域名、端口三者必须完全一致才算同源。

限制内容：

- 无法读取非同源的 Cookie、LocalStorage、IndexedDB
- 无法访问非同源的 DOM
- 无法发送非同源的 AJAX 请求（可发送，但浏览器拦截响应）

以下标签允许跨域加载资源（但无法读取内容）：`<script>`、`<link>`、`<img>`、`<video>`、`<audio>`、`<iframe>`。

## 跨域解决方案

### CORS（跨域资源共享）

W3C 标准，由浏览器自动处理，关键在于服务器配置。

```js
// Node.js 示例：在响应头中声明允许的来源、方法与请求头
res.setHeader('Access-Control-Allow-Origin', '*');
res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
res.setHeader('Access-Control-Allow-Headers', 'Content-Type');
```

优点：支持所有 HTTP 请求类型，是跨域的正统解决方案。

### JSONP

利用 `<script>` 标签不受同源策略限制的特性，服务器返回一个函数调用。

```js
// 前端：提前定义好回调函数，函数名通过 callback 参数传给服务器
function handleResponse(data) {
  console.log(data);
}
const script = document.createElement('script');
script.src = 'http://example.com/api?callback=handleResponse';
document.body.appendChild(script);

// 服务器返回一段可执行的 JS：直接调用前端定义的回调
// handleResponse({"name": "张三", "age": 20});
```

缺点：只支持 GET 请求，存在 XSS 风险，错误处理困难。

### postMessage

HTML5 API，用于跨源通信，适合页面与新窗口、多窗口、iframe 之间的消息传递。

```js
// 发送：targetOrigin 指定目标源，防止消息发给不可信页面
targetWindow.postMessage(data, targetOrigin);

// 接收：务必先校验 event.origin 再使用数据
window.addEventListener('message', (event) => {
  if (event.origin !== 'http://example.com') return;
  console.log('接收到的数据：', event.data);
});
```

### 代理服务器

同源策略只限制浏览器，服务器间通信不受限制。前端请求同源代理服务器，由代理转发到目标服务器。

Nginx 反向代理配置示例：

```nginx
server {
  listen 80;
  server_name example.com;

  # 前端请求同源的 /api，由 Nginx 转发到目标服务器，浏览器视角永远是同源
  location /api {
    proxy_pass http://target-server.com;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

## 正向代理与反向代理

| 特性 | 正向代理 | 反向代理 |
| --- | --- | --- |
| 代理对象 | 代理客户端 | 代理服务器 |
| 隐藏对象 | 隐藏真实客户端 | 隐藏真实服务器 |
| 客户端配置 | 需要修改 | 不需要修改 |
| 常见应用 | VPN、翻墙 | 负载均衡、缓存加速 |

```text
正向代理：客户端 → 代理服务器 → 目标服务器
反向代理：客户端 → 反向代理服务器 → 服务器集群
```
