# 模块

*类型：knowledge ｜ 难度：基础 ｜ 标签：webpack、module、模块化*

**在模块化编程中，开发者将程序分解为功能离散的 chunk，并称之为模块：每个模块都拥有小于完整程序的体积，使验证、调试及测试变得轻而易举；精心编写的模块提供可靠的抽象和封装界限，让应用程序条理清晰、目的明确。** 与 Node.js 模块相比，webpack 模块能以更多方式表达依赖关系；ESM、CommonJS、AMD、Assets、WebAssembly 是天生支持的类型，其余语言与预处理语法靠 loader 扩展。

## webpack 模块表达依赖的方式

与 Node.js 模块相比，webpack 模块能以各种方式表达它们的依赖关系：

- ES2015 `import` 语句。
- CommonJS `require()` 语句。
- AMD `define` 和 `require` 语句。
- css/sass/less 文件中的 `@import` 语句。
- stylesheet `url(...)` 或 HTML `<img src=...>` 文件中的图片链接。

## 支持的模块类型

webpack 天生支持如下模块类型：

- ECMAScript 模块。
- CommonJS 模块。
- AMD 模块。
- Assets（资源模块）。
- WebAssembly 模块。

## 用 loader 扩展模块类型

**loader 向 webpack 描述如何处理非原生模块，并将相关依赖引入你的 bundle。** webpack 社区已经为各种流行的语言和预处理器创建了 loader，其中包括：

- CoffeeScript。
- TypeScript。
- ESNext（Babel）。
- Sass。
- Less。
- Stylus。
- Elm。
