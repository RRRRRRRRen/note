# 模块热替换概念

*类型：knowledge ｜ 难度：进阶 ｜ 标签：webpack、HMR、模块热替换、开发效率*

**模块热替换（HMR - hot module replacement）会在应用程序运行过程中，替换、添加或删除模块，而无需重新加载整个页面。** 它通过三件事显著加快开发速度：保留完全重新加载页面期间会丢失的应用程序状态、只更新变更内容以节省开发时间、源代码中 CSS/JS 产生修改时立刻在浏览器中更新——几乎相当于在浏览器 devtools 里直接更改样式。

## HMR 解决的问题

开发时每次改动代码都要整页刷新，代价是内存状态清零：表单填到一半、组件内部的交互状态全部丢失，还要重新走一遍「回到出错位置」的路径。HMR 把「重新执行」的范围从整页缩小到模块：

- **保留状态**：完全重新加载页面期间丢失的应用程序状态得以保留。
- **增量更新**：只更新变更内容，节省宝贵的开发时间。
- **即时反馈**：CSS/JS 产生修改时立刻在浏览器中更新，近乎在 devtools 中直接改样式。

## 与实战篇的关系

概念上 HMR 由三部分咬合：编译侧产出「manifest + 更新 chunk」，页面内常驻的 HMR runtime 通过 WebSocket 收到通知后拉取补丁，`module.hot.accept` 声明的边界决定补丁如何应用、没有边界则沿依赖图冒泡直至整页刷新兜底。完整的更新旅程、accept 边界、dispose 状态交棒与 dev-server 配置，见《模块热替换实战》。
