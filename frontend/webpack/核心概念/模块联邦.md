# 模块联邦

*类型：knowledge ｜ 难度：进阶 ｜ 标签：webpack、Module Federation、微前端*

**Module Federation（模块联邦）是 webpack 5 提出的多应用模块共享机制：一个应用可以把自身模块作为「远程模块」暴露出去，也可以在运行时直接消费其他应用暴露的模块，从而让多个独立构建、独立部署的应用像使用本地依赖一样共享代码。** 它解决了微前端架构下「公共模块重复打包、跨应用状态与依赖难以对齐」的问题——每个应用既是 Host（消费者）又是 Remote（提供者），共享依赖由运行时协商版本，避免了「组件库改一行，所有应用都要重发包」的连锁成本。

## 核心角色

- Host：消费远程模块的应用，在 `remotes` 中声明要引用的远端。
- Remote：暴露模块给其他应用使用的应用，在 `exposes` 中声明暴露路径。
- Shared：共享依赖声明，运行时按版本与作用域协商，尽量复用已加载实例而不是各带一份。

## 基本用法

Remote 应用暴露模块：

```js
const { ModuleFederationPlugin } = require('webpack').container;

module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      // 唯一的应用名，作为共享作用域的标识
      name: 'app_remote',
      // 暴露的模块映射：消费方以 'app_remote/Button' 的形式引用
      exposes: {
        './Button': './src/components/Button.js',
      },
      // 共享依赖：优先复用宿主已加载的版本，版本不满足才加载自己的
      shared: ['react', 'react-dom'],
    }),
  ],
};
```

Host 应用消费远程模块：

```js
const { ModuleFederationPlugin } = require('webpack').container;

module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: 'app_host',
      // 远端映射：'app_remote@https://remote.example.com/remoteEntry.js'
      // 前半段是 remote 名称，后半段是其 remoteEntry 入口文件地址
      remotes: {
        app_remote: 'app_remote@https://remote.example.com/remoteEntry.js',
      },
      shared: ['react', 'react-dom'],
    }),
  ],
};
```

Host 代码中像引用普通模块一样引用远程模块：

```js
// 运行时从远程加载：'app_remote/Button' 对应 Remote exposes 里的 './Button'
const Button = await import('app_remote/Button');
```

## 适用与代价

- 适用场景：微前端拆分的多团队仓库、共享登录态组件/设计系统组件、独立部署节奏但需要公共依赖一致性的应用群。
- 代价与注意点：运行时跨网络加载模块，要求 remoteEntry 地址可用且版本兼容；`shared` 依赖需要双方声明一致才能命中复用；调试链路横跨多个应用，可观测性建设要提前规划。
