# 缓存策略

*类型：practice ｜ 难度：进阶 ｜ 标签：webpack、缓存、contenthash、runtimeChunk、moduleIds*

**缓存的核心矛盾：浏览器靠文件名判断资源是否更新，部署新版本时不改文件名，浏览器就会继续用缓存旧版。** webpack 的对策是 `[contenthash]`——内容变则文件名变；再配合 `runtimeChunk` 抽离运行时、`cacheGroups` 拆分 vendor、`moduleIds: 'deterministic'` 稳定模块 ID，把「一处改动、全量失效」收敛为「只失效真正变了的文件」。

## 输出文件的文件名

webpack 通过称为 **substitution（可替换模板字符串）** 的方式，用带括号字符串模板化文件名。其中 `[contenthash]` 将根据资源内容创建唯一 hash：资源内容发生变化时，`[contenthash]` 也会随之变化：

```js
module.exports = {
  output: {
    filename: '[name].[contenthash].js',
  },
};
```

## 提取引导模板（extracting boilerplate）

`SplitChunksPlugin` 用于将模块分离到单独的 bundle；`optimization.runtimeChunk` 将 runtime 代码拆分为一个单独的 chunk——runtime 随每次构建变化，单独拆出后业务代码的 hash 才能稳定：

```js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  plugins: [
    new HtmlWebpackPlugin({
      title: 'Caching',
    }),
  ],
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  optimization: {
    // 将 runtime 独立出来，打包会多出一个 runtime chunk 文件
    runtimeChunk: 'single',
    // 代码分割选项
    splitChunks: {
      // 缓存组：将多个模块打包到同一个文件中
      cacheGroups: {
        // 缓存组名称：vendor
        vendor: {
          // 匹配 node_modules 目录下的模块
          test: /[\\/]node_modules[\\/]/,
          // 打包后的文件名称
          name: 'vendors',
          // all：同步和异步模块都打进该组
          chunks: 'all',
        },
      },
    },
  },
};
```

## 模块标识符（module identifier）

问题：只改私有代码、不动第三方库时，所有文件的 hash 都会改变，无法命中缓存。原因是每个 `module.id` 默认基于解析顺序（resolve order）递增——解析顺序变化，ID 随之变化，依赖它的 chunk 内容也就变了。

```js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  entry: './src/index.js',
  plugins: [
    new HtmlWebpackPlugin({
      title: 'Caching',
    }),
  ],
  output: {
    filename: '[name].[contenthash].js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  optimization: {
    // 设置模块 id 的生成方式为确定性的
    moduleIds: 'deterministic',
    runtimeChunk: 'single',
    splitChunks: {
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          chunks: 'all',
        },
      },
    },
  },
};
```

`optimization.moduleIds` 两个可选值：

- `natural`（默认）：按解析顺序递增分配 ID，顺序变化则 ID 变化。
- `deterministic`：基于模块内容生成固定哈希作为模块标识符，不因构建环境或时间变化，保证构建结果可预测、文件名稳定。

`deterministic` 优化了缓存效果，浏览器可以更好地缓存资源、提高加载速度；代价是一些构建速度和代码体积——webpack 需要对每个模块做哈希计算和排序。
