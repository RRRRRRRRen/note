# 模块热替换实战

*类型：practice ｜ 难度：进阶 ｜ 标签：webpack、HMR、module.hot、dev-server*

**从 `webpack-dev-server` v4.0.0 开始，热模块替换默认开启；要让被依赖的模块更新后「可被接受」，需要在入口用 `module.hot.accept` 声明处理回调——这是 HMR 的 opt-in 语义。** 实际项目中热更新能力大多已集成在常用 loader 里：`style-loader` 让 CSS 热替换开箱即用，`Vue Loader` 对 vue 组件提供开箱即用的 HMR。

## 手动接受模块更新

修改 `index.js`，当 `print.js` 内部发生变更时告诉 webpack 接受更新的模块：

```js
import _ from 'lodash';
import printMe from './print.js';

function component() {
  const element = document.createElement('div');
  const btn = document.createElement('button');

  element.innerHTML = _.join(['Hello', 'webpack'], ' ');

  btn.innerHTML = 'Click me and check the console!';
  btn.onclick = printMe;

  element.appendChild(btn);

  return element;
}

document.body.appendChild(component());

// 热替换代码，本质是一个 webpack 提供的回调函数，用来监听模块的变化：
// ./print.js 更新时执行回调，用新模块重新执行 printMe，而不是整页刷新
if (module.hot) {
  module.hot.accept('./print.js', function () {
    console.log('Accepting the updated printMe module!');
    printMe();
  });
}
```

- `module.hot`：当前运行环境支持 HMR 时才存在，先判空再注册回调。
- `module.hot.accept('./print.js', callback)`：声明「print.js 变更由我处理」，callback 拿到更新后重新调用被替换的模块代码。

## loader 集成的热更新

热更新功能大多都集成在常用的 loader 中，无需手写 accept：

- `style-loader`：借助它使用模块热替换加载 CSS 极其简单，样式变更只替换 style 节点。
- `Vue Loader`：支持 vue 组件的 HMR，提供开箱即用体验。

更完整的更新旅程——增量编译产出的 manifest 与补丁 chunk、runtime 的 check/apply 流程、accept 边界与向上冒泡、dispose 状态交棒——见工程化篇《HMR 是怎么做到只替换一块代码的？》。
