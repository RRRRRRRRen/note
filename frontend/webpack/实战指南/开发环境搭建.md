# 开发环境搭建

*类型：practice ｜ 难度：基础 ｜ 标签：webpack、source map、webpack-dev-server、watch*

**开发环境的三大件：`devtool: 'inline-source-map'` 让报错定位回源码，`webpack-dev-server` 提供带 live reloading 的本地服务器省掉手动构建，`optimization.runtimeChunk: 'single'` 解决多入口下的运行时重复问题。** 自动编译有三个可选方案——watch mode、webpack-dev-server、webpack-dev-middleware——多数场景选 dev-server。

## 使用 source map

webpack 打包源代码后很难追踪 error 和 warning 在源代码中的原始位置：三个源文件打包进一个 bundle，堆栈跟踪只会指向 `bundle.js`。为了更容易地追踪，JavaScript 提供了 source maps 功能，可以将编译后的代码映射回原始源代码——错误来自 `b.js`，source map 就会明确告诉你。

```js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  // 开发模式打包
  mode: 'development',
  entry: {
    index: './src/index.js',
    print: './src/print.js',
  },
  // 开启行内模式的 source-map
  devtool: 'inline-source-map',
  plugins: [
    new HtmlWebpackPlugin({
      title: 'Development',
    }),
  ],
  output: {
    filename: '[name].bundle.js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
};
```

## 三种自动编译方式

| 方式 | 特点 | 适用 |
| --- | --- | --- |
| watch mode | 监听依赖图文件变化，变更后重新编译，无服务器 | 简单场景、纯构建产物调试 |
| webpack-dev-server | 提供 web server + live reloading | 多数场景的首选 |
| webpack-dev-middleware | 把 webpack 处理过的文件发送到一个 server，配合 Node 自定义 | 需要深度定制 server |

### watch mode（观察模式）

指示 webpack "watch" 依赖图中所有文件的更改，其中一个文件被更新，代码将被重新编译，不必再手动运行整个构建。在 package.json 中添加脚本即可：

```json
{
  "scripts": {
    "watch": "webpack --watch"
  }
}
```

### webpack-dev-server

提供一个基本的 web server，并且具有 live reloading（实时重新加载）功能：

```bash
npm install --save-dev webpack-dev-server
```

```js
const path = require('path');
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  mode: 'development',
  entry: {
    index: './src/index.js',
    print: './src/print.js',
  },
  devtool: 'inline-source-map',
  // 开启 dev-server
  devServer: {
    // 打包后的静态资源目录
    static: './dist',
  },
  plugins: [
    new HtmlWebpackPlugin({
      title: 'Development',
    }),
  ],
  output: {
    filename: '[name].bundle.js',
    path: path.resolve(__dirname, 'dist'),
    clean: true,
  },
  // 多入口文件需要进行额外的优化配置：
  // 把 runtime 提取为单独 chunk，避免每个入口各带一份运行时
  optimization: {
    runtimeChunk: 'single',
  },
};
```

### webpack-dev-middleware

需要配合 Node 使用：它把 webpack 处理过的文件发送到一个 server。`webpack-dev-server` 在内部使用了它，但它也可以作为一个单独的 package 使用，以便根据需求进行更多自定义设置。

### 在 Vagrant 虚拟机中使用 webpack

如果你在开发一个更加高级的项目，并且使用 [Vagrant](https://www.vagrantup.com/) 来实现在虚拟机（Virtual Machine）上运行你的开发环境，那你可能会需要在虚拟机中运行 webpack。

Vagrant 通过共享目录（如 VirtualBox 的 vboxsf）把宿主机项目目录挂载进虚拟机，这类文件系统的文件变更事件（inotify）**不会通知到虚拟机内部**，因此 webpack 的常规文件监听会失效。解决办法是开启 `watchOptions.poll` 轮询模式，让 webpack 主动定时检查文件变更：

```js
// webpack.config.js
module.exports = {
  // ...
  watchOptions: {
    // 开启轮询：每 1000ms 检查一次文件变更
    // 用于 NFS / Vagrant / VirtualBox 等文件变更事件不可用的环境
    poll: 1000,
    // 需要排除的文件或目录（忽略大目录可降低 CPU 占用）
    ignored: /node_modules/
  }
};
```

要点：

- 共享目录中的 inotify 事件无法穿透到虚拟机 → 必须 `poll: true` 或指定轮询间隔毫秒数。
- 轮询间隔越大越省 CPU，但感知变更越慢，一般 1000ms 起步。
- 配合 `ignored` 排除 `node_modules` 等大目录，避免轮询遍历带来的性能开销。
