# 管理输出

*类型：practice ｜ 难度：基础 ｜ 标签：webpack、output、html-webpack-plugin、clean*

**多入口打包的核心问题是产物对不上号：`[name]` 占位符解决「文件名冲突」，`html-webpack-plugin` 解决「HTML 如何自动引入带 hash 的产物」，`output.clean` 解决「旧产物残留」。** 三者配合，`dist` 目录的产物始终保持与入口一致、引用自动更新、没有历史垃圾。

## 完整配置

```js
const path = require('path');
// npm 包：html-webpack-plugin
// 用于生成或使用 html 模板自动引入打包后的资源
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  // 多个入口
  entry: {
    index: './src/index.js',
    print: './src/print.js',
  },
  plugins: [
    new HtmlWebpackPlugin({
      // 一般建议使用 template，而不是书写配置项
      title: 'Output Management',
    }),
  ],
  output: {
    // 使用占位符 [name] 表示入口名称，避免多入口文件名冲突
    filename: '[name].bundle.js',
    path: path.resolve(__dirname, 'dist'),
    // 打包前是否清空 dist 目录，之前需要用插件完成，现在直接通过配置完成
    clean: true,
  },
};
```

## 要点解析

- **`[name]` 占位符**：多入口时如果文件名写死，后打包的入口会覆盖先打包的；`filename: '[name].bundle.js'` 按 entry 的 key 输出 `index.bundle.js` 与 `print.bundle.js`。
- **HtmlWebpackPlugin**：构建时生成（或复用模板生成）HTML，并把所有产物以 script 标签自动注入——文件名带 hash、按需加载的异步 chunk 都不需要手动维护引用。
- **`clean: true`**：每次构建前清空 `output.path` 目录，防止改名/删除入口后旧文件残留在线上目录里。
