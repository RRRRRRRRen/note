# 依赖管理

*类型：knowledge ｜ 难度：进阶 ｜ 标签：webpack、require.context、上下文模块、动态依赖*

**webpack 处理「写不确定的依赖」有两套机制：带表达式的 require 语句会创建一个 context module，把目录下所有匹配的模块全部打包并生成映射；`require.context()` 则让你显式创建自己的 context，在构建期批量导入模块。** 前者是隐式的（可能打包进很多用不到的模块），后者是显式声明搜索范围，工程上更推荐后者。

## 带表达式的 require 语句

当代码中出现含有表达式的 require 语句：

```js
// 运行前无法确定具体模块，webpack 只能按规则穷举
require('./template/' + name + '.ejs');
```

webpack 内部将其解析为一个目录加一个正则：

```text
Directory: ./template
Regular expression: /^.*\.ejs$/
```

然后查找所有符合该规则的模块，生成相应映射——这会导致所有可能的模块都被打包进 bundle：

```json
{
  "./table.ejs": 42,
  "./table-row.ejs": 43,
  "./directory/another.ejs": 44
}
```

## require.context

通过 `require.context()` 函数可以创建自己的 context。传入三个参数：要搜索的目录、是否搜索其子目录的标记、匹配文件的正则表达式。webpack 会在构建中解析代码中的 `require.context()`。

```js
require.context(
  directory,
  (useSubdirectories = true),
  (regExp = /^\.\/.*$/),
  (mode = 'sync'),
);
```

示例：

```js
// 创建一个 context：文件来自 test 目录（不递归），request 以 .test.js 结尾
require.context('./test', false, /\.test\.js$/);
// 创建一个 context：所有文件来自父文件夹及其所有子级文件夹，request 以 .stories.js 结尾
require.context('../', true, /\.stories\.js$/);
```

## context module API

context module 返回的函数带有 `keys()` 方法，可以遍历所有匹配的模块：

```js
const cache = {};

// 遍历 context 中的每个模块，把构建期解析到的模块填充进 cache
function importAll(r) {
  r.keys().forEach((key) => (cache[key] = r(key)));
}

importAll(require.context('../components/', true, /\.js$/));
// 在构建时（build-time），所有被 require 的模块都会被填充到 cache 对象中。
```
