# 状态管理

*类型：practice ｜ 难度：入门 ｜ 标签：vue-vben-admin、Pinia、状态管理、持久化*

**Vben Admin 使用 Pinia 做状态管理：`createPinia` 创建实例，注册持久化插件，再通过 `setupStore` 以 Vue 插件的标准方式挂载到应用上。该主题的源码笔记尚处起步阶段，本篇整理已有的注册入口实现，并补充其在项目中的整体定位。**

## 状态管理器注册

`main.ts` 中有关 store 的执行代码：

```ts
import { setupStore } from '@/store';

// ...
async function bootstrap() {
  // 挂载状态管理器
  setupStore(app);
}
```

### 注册状态管理器

来源：`src/store/index.ts`

```ts
import type { App } from 'vue';
import { createPinia } from 'pinia';
import { registerPiniaPersistPlugin } from '@/store/plugin/persist';

// 创建 pinia 实例
const store = createPinia();

// 注册持久化插件
registerPiniaPersistPlugin(store);

// 与 setupRouter 一致，以插件方式挂载到应用
export function setupStore(app: App<Element>) {
  app.use(store);
}

export { store };
```

要点解析：

- `createPinia()` 创建 pinia 实例，它是所有 store 的载体。
- `registerPiniaPersistPlugin(store)` 注册持久化插件——刷新页面后登录信息、主题配置等状态不丢失的关键。
- `setupStore(app)` 与路由注册的 `setupRouter(app)` 写法完全一致：都接收 `App<Element>` 类型并调用 `app.use()`，保持入口函数风格统一。

## 在项目中的定位

Pinia 是 Vue3 官方推荐的状态管理方案，相比 Vuex 的核心变化：

- 去掉 mutation，action 中直接修改状态。
- 完整的 TypeScript 类型推导。
- store 按模块自由拆分，没有嵌套模块的层级负担。

在 vben 中，store 通常按业务域拆分为独立模块（如用户、权限、应用配置等），每个模块是一个独立的 store 文件，通过 `defineStore` 定义。需要跨组件、跨页面共享的状态（登录用户信息、权限码、菜单、主题设置、多标签页）都收拢在 store 中，配合路由守卫做权限判断（见路由配置篇）。

## 学习建议

- 先读懂本篇的注册入口，理解 pinia 实例、插件、应用挂载三者的关系。
- 再挑用户 store 或权限 store 精读，观察 `defineStore` 的 state/getters/actions 组织方式。
- 持久化插件的实现（`@/store/plugin/persist`）值得一读，核心是订阅状态变化并同步到 localStorage。
