# 代码格式化

*类型：practice ｜ 难度：入门 ｜ 标签：vue-vben-admin、Prettier、Stylelint、ESLint、代码规范*

**Vben Admin 用三件工具覆盖全部代码格式化与检查：Prettier 管代码格式、Stylelint 管样式规范、ESLint 管 JS/TS/Vue 语法。每个工具都有「npm 包 + vscode 插件」两种形态——npm 包供命令行与 CI 强制执行，插件提供编辑器内即时反馈，两者共用同一份根目录配置文件。**

## Prettier

Prettier 是流行的代码格式化工具，用于统一和美化代码风格。

**npm 包与 vscode 插件的关系**：

- npm 安装的 prettier 是独立的 node 脚本，可以在命令行单独运行，不需要任何载体即可检查指定文件。
- vscode 插件市场的 prettier 解决了 npm 包的痛点——不需要手动在命令行执行命令，即可快速完成格式化。
- 仍需要 npm 包的原因：无法保证所有协作者都安装插件、甚至都使用 vscode，所以需要在核心操作（例如提交代码前）自动触发 prettier 命令格式化代码。

这一点同样适用于其他插件和其对应的 npm 包。

### `.prettierrc.js`

根目录下的 `.prettierrc.js` 是 prettier 的配置文件，可以同时作用于 prettier 命令和 prettier 插件。

```js
module.exports = {
  // 每行最大字符宽度，超过将被折行
  printWidth: 100,
  // 是否在语句末尾添加分号
  semi: true,
  // Vue 单文件组件的 <script> 和 <style> 标签是否使用额外缩进
  vueIndentScriptAndStyle: true,
  // 是否使用单引号包裹字符串
  singleQuote: true,
  // 多行数组或对象的最后一项是否添加逗号
  trailingComma: 'all',
  // Markdown 文件是否根据 printWidth 对文本换行
  proseWrap: 'never',
  // HTML 文件空白符敏感度
  htmlWhitespaceSensitivity: 'strict',
  // 换行符类型
  endOfLine: 'auto',
  // 额外插件：规范化 package.json 的格式与字段顺序
  plugins: ['prettier-plugin-packagejson'],
  // 针对特定文件的配置覆盖
  overrides: [
    // 以 .*rc 结尾的文件使用 JSON 解析器进行格式化
    {
      files: '.*rc',
      options: {
        parser: 'json',
      },
    },
  ],
};
```

关键配置解析：

- `htmlWhitespaceSensitivity: 'strict'`：处理 HTML 元素之间的空白。元素之间有多个空白按一个处理，没有空白就不添加。最大的差别在于元素标签是否被打断到两行显示——打断后可以避免产生空白，保证页面渲染时能准确识别是否写了空白。
- `plugins: ['prettier-plugin-packagejson']`：专门处理 `package.json` 的格式化，包括缩进、换行符、引号类型、属性顺序等。
- `overrides`：针对特定文件或文件类型做单独配置覆盖。上述配置表示所有以 `.rc` 结尾的文件（如 `.eslintrc`、`.prettierrc`）按 JSON 格式解析和格式化。

### `.prettierignore`

用于配置 Prettier 忽略特定文件或文件夹的规则：

```text
dist
.local
.output.js
node_modules

**/*.svg
**/*.sh

public
.npmrc
```

忽略规则的几种模式：

- `xxxx` 模式（`dist`、`node_modules`、`public`）：匹配任意文件层级下该文件夹内的所有文件。
- `.xxxx` 模式（`.local`、`.npmrc`）：匹配任意文件层级下的同名文件。
- `.xxxx.xxx` 模式（`.output.js`）：同上。
- `**/*.xxx` 模式（`**/*.svg`、`**/*.sh`）：匹配所有以 xxx 结尾的文件，不管在哪个文件夹。

需要重点忽略 `node_modules`、`dist`、`public`——这些文件夹内的文件不建议任何变动，不需要格式化的改动。语法规则与 gitignore 一致。

## Stylelint

Stylelint 用于检测和自动修复 CSS 及预处理器代码规范，可以检查 CSS 语法错误和警告、命名/缩进/空格/换行等风格规范、不推荐写法与过时属性，并支持插件扩展。

### `.stylelintrc.js`

```js
module.exports = {
  // 表示根目录
  root: true,
  // 预设规则扩展
  extends: ['@vben/stylelint-config'],
};
```

- `root`：插件运行时从当前作用文件的同级目录寻找配置文件，一层层往上找，直到系统根目录或遇到含 `root: true` 的配置文件——告诉插件“不用找了，我就是最后一层”。
- `extends`：预设规则集。Stylelint 允许社区配置统一的规范集，使用规则集可以减少繁琐配置，做到拿来就用。`@vben/stylelint-config` 是 vben 提供的规则集。

### `.stylelintignore`

```text
dist
public
```

类似 `.prettierignore`，配置忽略规则。

### 排查：css 文件检查不生效

写 css 相关代码时应得到 stylelint 支持，但 css 文件可能没有任何报错。检查配置：找到 `@vben/stylelint-config` 实体文件 `internal/stylelint-config/index.ts`，重点看这段代码：

```js
export default {
  // ...
  overrides: [
    {
      files: ['**/*.(css|html|vue)'],
      customSyntax: 'postcss-html',
    },
    // ...
  ]
  // ...
}
```

问题：`postcss-html` 也解析了 `css` 文件，然而 postcss-html 并不支持解析 css 文件；css 文件不需要任何解析器，stylelint 原生就支持检查 css。删除 css 的匹配：

```diff
- files: ['**/*.(css|html|vue)'],
+ files: ['**/*.(html|vue)'],
```

重启编辑器（很重要，可直接重新加载窗口）后检查即可生效。

## ESLint

Prettier 和 Stylelint 解决了代码格式与 css 语法问题，js 语法问题需要 ESLint 规范。它不但可以检查 js 语法，也可以用于 js 代码的格式化。

### `.eslintrc.js`

```js
module.exports = {
  root: true,
  extends: ['@vben'],
};
```

`extends` 的缩写模式：

- 以 **eslint-config** 开头的安装包（如 `eslint-config-standard`）可省略前缀 `eslint-config`。
- 以 **@ + 命名空间**开头的安装包，如 `@vben` 表示 `@vben/eslint-config`。

### `@vben/eslint-config` 规则集解析

实体文件位置：`internal/eslint-config/src/index.ts`。

**指定运行环境**

```js
env: {
  browser: true,
  node: true,
  es6: true,
},
```

- `browser: true`：识别浏览器环境全局变量（`window`、`document` 等）。
- `node: true`：识别 Node.js 环境全局变量（`process`、`module` 等）。
- `es6: true`：识别 ES6 新增语法特性（箭头函数、模块导入导出、解构赋值等）。

**解析器配置**

```js
// 指定解析器 vue-eslint-parser
parser: 'vue-eslint-parser',
// 解析器配置项
parserOptions: {
  parser: '@typescript-eslint/parser',
  ecmaVersion: 2020,
  sourceType: 'module',
  jsxPragma: 'React',
  ecmaFeatures: {
    jsx: true,
  },
  project: './tsconfig.*?.json',
  createDefaultProgram: false,
  extraFileExtensions: ['.vue'],
},
```

- 为什么有两个 `parser`：`parserOptions.parser` 只是 `vue-eslint-parser` 的一个配置项，用来指定专门解析 `<script>` 标签内容的解析器——标签内可能使用 js 或 ts 语法。vben 使用 ts 开发，所以指定 `@typescript-eslint/parser`；还可以设置为对象，对 ts 和 js 分别指定解析器。
- `ecmaVersion: 2020`：指定解析的 ECMAScript 版本。与 `env.es6` 的关系：env 用于指定全局的 es 版本为 6，解析器版本由 ecmaVersion 单独覆盖。
- `sourceType: 'module'`：指定模块类型为 ES 模块。`env.es6` 开启所有 es6 功能但除模块化之外，此配置用于自由选择模块化语法。
- `jsxPragma`：指定 JSX 语法中的 pragma，即用于解析 JSX 的库名称。
- `ecmaFeatures.jsx`：启用 jsx 语法支持。
- `project`：指定 TypeScript 配置文件路径，提供类型检查和类型推断支持，使用通配符匹配多个可能的 tsconfig。
- `createDefaultProgram: false`：禁用 ESLint 默认的 TypeScript 项目创建，即是否联合解析 ts 文件。联合解析可复用已解析的文件和类型信息提高性能；设为 false 时每个文件独立解析，减少内存占用和构建时间，项目大建议 false。
- `extraFileExtensions`：额外文件扩展名 `.vue`，让 ESLint 识别并解析 .vue 文件中的代码。

注意：ESLint 的 vscode 插件并不一定全部支持这些设置，只有使用命令行执行 ESLint 相关操作时才会完全按配置执行。

**插件和扩展**

```js
plugins: ['vue', '@typescript-eslint', 'import'],
extends: [
  'eslint:recommended',
  'plugin:vue/vue3-recommended',
  'plugin:@typescript-eslint/recommended',
  'plugin:prettier/recommended',
],
```

`plugins` 指定使用的插件：

- `vue`：提供检查和规范 Vue.js 代码的规则。
- `@typescript-eslint`：提供检查和规范 TypeScript 代码的规则，使 ESLint 能处理 TS 特定语法和类型注解。
- `import`：提供检查和规范模块导入语句的规则。

`extends` 指定继承的规则集：

- `eslint:recommended`：ESLint 官方推荐规则集，包含常见代码风格和错误检查规则。
- `plugin:vue/vue3-recommended`：Vue 官方推荐的规则集，适用于 Vue 3 项目。
- `plugin:@typescript-eslint/recommended`：TypeScript ESLint 插件提供的规则集。
- `plugin:prettier/recommended`：Prettier 插件规则集，与 Prettier 配合确保代码风格一致性。

**自定义规则与全局变量**

```js
rules: {
  // 内置规则
  'space-before-function-paren': 'off',
  // import 插件的规则，需要前缀
  'import/first': 'error',
},
// 定义全局变量 defineOptions 为只读，避免未声明变量报错
globals: { defineOptions: 'readonly' },
```

rules 用于自定义内置规则和插件规则（插件规则需要前缀区分），此处规则具有最高优先级，可覆盖插件中的规则。

### 解析器的验证思路

解析器的作用是将代码转化为 AST，默认情况下 ESLint 只认识 js 文件。借助 [AST explorer](https://astexplorer.net/) 可验证：`vue-eslint-parser` 默认可以解析 vue 文件和 js 文件；ts 文件和 vue 中的 ts 语法交给 `parserOptions.parser: '@typescript-eslint/parser'`。有了 vue 的 AST 后，还需要 `eslint-plugin-vue` 插件来检查 vue 语法树，并提供规则集 `plugin:vue/vue3-recommended`——至此 ESLint 完整支持 vue 文件。

### `.eslintignore`

忽略列表，语法与 `.prettierignore` 相同。
