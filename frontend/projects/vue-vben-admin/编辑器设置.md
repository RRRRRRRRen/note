# 编辑器设置

*类型：practice ｜ 难度：入门 ｜ 标签：vue-vben-admin、VSCode、settings.json、EditorConfig、i18n-ally*

**Vben Admin 的编辑器设置分两层：全局 `settings.json` 放与项目无关的通用配置，项目级 `.vscode/` 文件夹放与项目强相关的配置（优先级最高），再用跨编辑器生效的 `.editorconfig` 统一缩进与换行符。目的只有一个：统一所有协作成员的编辑器行为，防止同一项目写出的代码千人千面。**

## 全局配置

### 进入设置

- 可交互的设置界面：vscode 左下角按钮进入全局设置，按分类逐项设置。适合简单修改。
- 编辑器的配置文件：设置项较多时推荐前往源头文件 `settings.json` 修改，可通过命令面板快捷键（command + shift + P）输入 settings 快速进入。

全局配置的三个主要作用：

- 设置通用配置，例如字体、主题、终端配置、编辑器行为等。
- 定义各种文件的默认格式化工具和编辑器本身的格式化行为。
- 通用插件的配置选项，例如 better-comments（给注释加上各种强调色）。

与项目无关的配置放在全局，或提前为可能与项目有关的配置设置好默认值。

### 通用配置示例

一份精简的全局设置，配置项不多，尽量维持全局配置的纯粹：

```json
{
  // 外观
  "window.zoomLevel": 1,
  "editor.fontSize": 16,
  "editor.lineHeight": 24,
  "workbench.iconTheme": "material-icon-theme",
  "workbench.colorTheme": "Dracula Soft",

  // 编辑器
  "editor.tabSize": 2,
  "editor.dragAndDrop": false,
  "editor.guides.bracketPairs": true,

  // 保存行为：关闭自动格式化，保存时执行 ESLint 修复
  "editor.formatOnSave": false,
  "editor.formatOnPaste": false,
  "editor.formatOnType": false,
  "editor.codeActionsOnSave": {
    "source.fixAll": true,
    "source.fixAll.eslint": true
  },

  // 代码校验交给 ESLint/TS，关闭编辑器自带验证
  "javascript.validate.enable": false,
  "typescript.validate.enable": false,

  // 文件资源管理器：隐藏无关文件
  "files.exclude": {
    "**/.svn": true,
    "**/.hg": true,
    "**/.DS_Store": true,
    "**/.sass-cache": true,
    "**/.vscode": false,
    "**/node_modules": false
  },

  // 代码格式化：各文件类型统一使用 Prettier
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "[vue]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
  "[javascript]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
  "[typescript]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
  "[less]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
  "[css]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
  "[json]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },

  // ESLint 插件
  "eslint.enable": true,
  "eslint.quiet": true,
  "eslint.validate": ["javascript", "javascriptreact", "vue"],
  "eslint.format.enable": true,
  "eslint.lintTask.enable": true
}
```

## 项目级配置

与项目强相关的配置不应为适配某个项目而把全局配置改得面目全非。在项目根目录下创建 `.vscode` 文件夹即可实现项目级设置，其中配置的优先级最高。

```text
.vscode
├── extensions.json   # 推荐插件列表
├── launch.json       # 调试配置
└── settings.json     # 主要项目设置
```

### extensions.json：推荐插件

```json
{
  "recommendations": [
    "vue.volar",
    "dbaeumer.vscode-eslint",
    "stylelint.vscode-stylelint",
    "esbenp.prettier-vscode",
    "mrmlnc.vscode-less",
    "lokalise.i18n-ally",
    "antfu.iconify",
    "mikestead.dotenv",
    "heybourn.headwind"
  ]
}
```

- 在数组中添加插件标识符，插件就会出现在 vscode 插件市场的推荐菜单下；已安装的插件不会出现在推荐菜单。
- 插件标识符的获取方式：右击插件选择复制扩展 id。

主要推荐插件的作用：

- `vue.volar`：Vue 语言支持插件，提供 Vue 3 开发支持、语法高亮、智能提示、类型检查。
- `dbaeumer.vscode-eslint`：集成 ESLint，进行 JS/TS 静态分析和快速修复。
- `stylelint.vscode-stylelint`：集成 Stylelint，实时检测 CSS/SCSS/LESS 的语法与风格问题。
- `esbenp.prettier-vscode`：集成 Prettier，保存时自动格式化代码。
- `mrmlnc.vscode-less`：LESS 语言支持，语法高亮与智能提示。
- `lokalise.i18n-ally`：国际化开发插件，管理和编辑多语言字符串。
- `antfu.iconify`：集成 Iconify 图标系统，快速搜索、预览和插入图标。
- `mikestead.dotenv`：`.env` 文件语法高亮与校验。
- `heybourn.headwind`：整理和排序 CSS 类名。

### launch.json：调试配置

`.vscode/launch.json` 是 VSCode 的调试配置文件，用于配置和定义调试器的行为：设置断点、观察变量、逐步执行代码等。配置完成后可以在 vscode 中进行浏览器端的调试。

### settings.json：主要设置

`.vscode/settings.json` 中的配置优先级高于全局配置，用于项目个性化定制。逐段解析：

**Volar 与 TS 配置**

```json
// 配置 ts 开发工具包地址：使用项目安装的 ts 版本，而非可能存在的全局版本
"typescript.tsdk": "./node_modules/typescript/lib",
// 开启 ts 插件（已弃用，默认开启）
"volar.tsPlugin": true,
"volar.tsPluginStatus": false,
```

**基础编辑配置**

```json
// 指定包管理器，但只能改变 vscode 触发的行为，不能限制终端中的命令行
"npm.packageManager": "pnpm",
// 缩进宽度为 2 个空格
"editor.tabSize": 2,
// 默认使用 Prettier 插件格式化
"editor.defaultFormatter": "esbenp.prettier-vscode",
// 文本文件行尾符统一为 \n
"files.eol": "\n",
```

`files.eol`：不同操作系统行尾符不同——Unix/Linux 为 `\n`，Windows 为 `\r\n`，旧版 Mac OS 为 `\r`。跨平台协作时统一换行符有助于代码一致性。

**文件系统管理**

```json
// 全局搜索时忽略的文件夹和文件
"search.exclude": {
  "**/node_modules": true,
  "**/.yarn": true
},
// 在工作区隐藏文件，避免手动误改
"files.exclude": {
  "**/.cache": true,
  "**/.DS_Store": true
},
// 文件监视器忽略的文件
"files.watcherExclude": {
  "**/.git/objects/**": true,
  "**/yarn.lock": true
},
```

`files.watcherExclude` 实际使用中有诡异之处：按文档说明被匹配文件不会被 vscode 文件监视器监视，但实测格式化、自动保存、git 状态变化仍会触发。Stack Overflow 上的解释是 vscode 插件扩展可以覆盖或绕过这个设置，所以部分插件在被排除文件中依然正常工作。

**Stylelint 配置**

```json
// 启用 Stylelint 对当前项目进行样式检查
"stylelint.enable": true,
// 需要进行样式验证的文件类型
"stylelint.validate": ["css", "less", "postcss", "scss", "vue", "sass"],
```

Stylelint 是样式代码检查工具，主要功能包括语法检查（缺少分号、括号不匹配）、风格规则（缩进、命名约定、属性顺序）、错误提示、自定义规则和插件扩展。

**Path Intellisense 配置**

```json
// 配置路径映射规则：输入 /@/ 前缀自动补全为 src 目录
"path-intellisense.mappings": {
  "/@/": "${workspaceRoot}/src"
},
```

Path Intellisense 提供路径自动补全。另外 tsconfig.json 中 `compilerOptions.paths` 也可以起到同样作用，且优先级可能更高。

**为不同文件类型指定默认格式化工具**

```json
"[javascriptreact]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
"[typescript]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
"[html]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
"[css]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
"[less]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
"[scss]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
"[markdown]": { "editor.defaultFormatter": "esbenp.prettier-vscode" },
```

`[javascriptreact]` 这种写法可以为不同类型文件设置不同的 vscode 配置，不限于格式化程序。注意：未安装对应插件时执行格式化会有提示。

**文件保存后的行为**

```json
// 保存时自动执行 ESLint 与 Stylelint 修复
"editor.codeActionsOnSave": {
  "source.fixAll.eslint": "explicit",
  "source.fixAll.stylelint": "explicit"
},
// 针对 vue 文件的定制化设置
"[vue]": {
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit",
    "source.fixAll.stylelint": "explicit"
  }
},
```

`source.fixAll.eslint` 在保存时自动修复 ESLint 检测到的问题，`source.fixAll.stylelint` 同理修复 Stylelint 问题。

**i18n-ally 国际化插件配置**

```json
// 存放语言文件的路径
"i18n-ally.localesPaths": ["src/locales/lang"],
// 键名使用嵌套样式
"i18n-ally.keystyle": "nested",
// 启用键名排序
"i18n-ally.sortKeys": true,
// 启用命名空间
"i18n-ally.namespace": true,
// 语言文件匹配模式
"i18n-ally.pathMatcher": "{locale}/{namespaces}.{ext}",
// 启用的解析器
"i18n-ally.enabledParsers": ["ts"],
// 源语言英语，显示语言中文
"i18n-ally.sourceLanguage": "en",
"i18n-ally.displayLanguage": "zh-CN",
// 启用的框架
"i18n-ally.enabledFrameworks": ["vue", "react"],
```

对国际化开发来说 i18n-ally 可以说是必须的插件。

**拼写检查与其他**

```json
// 自定义单词列表，不触发拼写检查警告
"cSpell.words": ["vben", "antd"],
// Vetur 冗余配置（Vue3 项目推荐 Volar，不推荐 Vetur）
"vetur.format.scriptInitialIndent": true,
"vetur.format.styleInitialIndent": true,
"vetur.validation.script": false,
// 资源管理器：启用文件嵌套，让根目录相关配置文件组织在一起（仅观感差异）
"explorer.fileNesting.enabled": true,
"explorer.fileNesting.expand": false,
"explorer.fileNesting.patterns": {
  "*.ts": "$(capture).test.ts, $(capture).test.tsx",
  "*.env": "$(capture).env.*",
  "package.json": "pnpm-lock.yaml,pnpm-workspace.yaml,LICENSE,README*,.npmrc",
  ".eslintrc.js": ".eslintignore,.prettierignore,.stylelintignore,.commitlintrc.js,.prettierrc.js,.stylelintrc.js"
},
// 终端可回滚查看的历史输出行数，默认 1000
"terminal.integrated.scrollback": 10000,
// 自定义代码片段高亮（vscodeCustomCodeColor 插件）
"vscodeCustomCodeColor.highlightValue": "v-auth",
"vscodeCustomCodeColor.highlightValueColor": "#6366f1"
```

`explorer.fileNesting.patterns` 就是导致“package.json 打开是个文件夹”的原因，它让根目录下相关配置文件尽量收拢显示，实际文件目录并没有改变。`cSpell.words` 的拼写检查在有 TS 的项目中意义不大。

## `.editorconfig` 文件

EditorConfig 是用于定义和维护跨多个编辑器和 IDE 的代码风格规则的标准文件。不像 `.vscode` 只能作用于 vscode，EditorConfig 可以作用于所有编辑器。

```ini
# 指示此文件为顶级文件，EditorConfig 配置的起始点
root = true

# 所有文件的通用设置
[*]
# 字符编码为 UTF-8
charset=utf-8
# 换行符为 LF
end_of_line=lf
# 文件末尾插入空行
insert_final_newline=true
# 使用空格缩进
indent_style=space
# 缩进空格数为 2
indent_size=2
# 最大行长度 100
max_line_length = 100

# yml、yaml、json 文件
[*.{yml,yaml,json}]
indent_style = space
indent_size = 2

# Markdown：不移除末尾空格
[*.md]
trim_trailing_whitespace = false

# Makefile 使用制表符缩进
[Makefile]
indent_style = tab
```

两个基础概念：

- 换行符：LF（`\n`）与 CRLF（`\r\n`），不同操作系统不一致，统一后既保证跨平台一致，也便于全局搜索时正则匹配更准确。
- 制表符：tab 占据的字符宽度是自适应的而非固定的，在编码文件中可能导致奇怪的缩进，所以用固定宽度的空格代替 tab。
