# 其他配置

*类型：knowledge ｜ 难度：进阶 ｜ 标签：vue-vben-admin、环境变量、Docker、UnoCSS、部署*

**Vben Admin 除编辑器、格式化、TS、GIT、包管理之外，还有一类「平台与运行环境」配置：`.env` 系列环境变量、`.browserslistrc` 浏览器范围、Docker/nginx 部署配置、UnoCSS 样式方案等。该主题的源码笔记暂为空，本篇梳理这些配置在项目中的定位与分工，作为后续精读源码的索引。**

## 环境变量体系

vben 根目录下有多份环境变量文件，按环境和用途区分：

```text
.env                # 默认环境变量，所有环境共享的基线
.env.analyze        # 分析环境（构建产物分析）
.env.development    # 开发环境
.env.docker         # Docker 容器环境
.env.production     # 生产环境
.env.test           # 测试环境
```

- Vite 按 mode 加载对应文件，`--mode test` 即加载 `.env.test`。
- 只有 `VITE_` 前缀的变量会注入客户端代码，通过 `import.meta.env` 读取。
- 典型变量：`VITE_PUBLIC_PATH`（部署基础路径）、`VITE_GLOB_API_URL`（接口地址）、端口配置等。
- 本地私密配置可使用 `.env.local`（被 `.gitignore` 忽略），避免敏感信息入库。

## 浏览器兼容配置

`.browserslistrc` 定义项目支持的浏览器范围，供 Babel、Autoprefixer、postcss 等工具共享：

- 决定语法降级的目标范围（需要转译哪些 ES 特性）。
- 决定 CSS 自动前缀需要覆盖哪些浏览器。
- 与 `.editorconfig`、`.npmrc` 一样属于「一处声明、多处生效」的约定文件。

## Docker 与部署

项目根目录的部署相关文件：

- `Dockerfile`：构建 Docker 镜像的配置，配合 `.dockerignore` 排除 node_modules 等无需进入镜像的文件。
- `nginx.conf`：nginx 服务器配置，生产环境常见做法是容器内用 nginx 托管 `dist` 静态产物，并配置 history 路由的回退规则与接口反代。
- `CNAME`：GitHub Pages 自定义域名配置。

## 样式方案：UnoCSS

`uno.config.ts` 是 UnoCSS 的配置文件。UnoCSS 是原子化 CSS 引擎，按需生成样式：

- 配置 presets（预设规则集）、主题色、快捷类等。
- 编辑器侧配合 `antfu.iconify` 等 vscode 插件获得图标与类名提示（见编辑器设置篇）。
- vben 中样式检查由 Stylelint 负责（见代码格式化篇），生成侧由 UnoCSS 负责，两者分工明确。

## mock 目录

`mock/` 存放模拟数据和接口，开发阶段替代真实后端：

- 与构建工具的开发服务器集成，请求命中 mock 规则时直接返回模拟数据。
- 上线构建时 mock 代码不进入产物，只服务于本地开发。

## types 目录与 turbo.json

- `types/`：存放全局类型声明文件（`.d.ts`），在 tsconfig.json 的 include 中被纳入编译（见 TS 配置篇的 `#/*` 路径映射）。
- `turbo.json`：monorepo 任务运行器 turbo 的配置，定义 build、lint、stub 等任务的依赖关系与缓存策略；package.json 的 `postinstall: turbo run stub` 即由它驱动（见包管理器解析篇）。

## 学习建议

- 环境变量是前后端联调和多环境部署的基础，优先弄清 mode 加载规则与 `VITE_` 前缀约束。
- Docker/nginx 配置在需要独立部署时再深入，理解「镜像里跑的是 nginx 托管静态文件」这一模型即可入门。
- UnoCSS 的价值在按需与零运行时，与Tailwind 的取舍可结合项目体量评估。
