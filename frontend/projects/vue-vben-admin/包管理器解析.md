# 包管理器解析

*类型：practice ｜ 难度：进阶 ｜ 标签：vue-vben-admin、pnpm、package.json、npm scripts、turbo*

**Vben Admin 的包管理围绕 `package.json` 展开：`.npmrc` 配置依赖提升，scripts 分为仓库描述、运行脚本、代码修复、提交信息、依赖项目、环境描述六类。其中 npm 生命周期钩子（preinstall/postinstall/prepare）是关键机关——分别用于强制 pnpm、启动 turbo、安装 husky。**

## pnpm 初始化配置

### `.npmrc`

```ini
public-hoist-pattern[]=husky
public-hoist-pattern[]=*eslint*
public-hoist-pattern[]=*prettier*
public-hoist-pattern[]=lint-staged
public-hoist-pattern[]=*stylelint*
public-hoist-pattern[]=@commitlint/cli
public-hoist-pattern[]=@vben/eslint-config
```

- `public-hoist-pattern` 用于做依赖提升，解决幻影依赖问题：将一些子依赖提升到根目录的 node_modules 中，而不是子依赖的 node_modules 中，消除其作为幻影依赖的可能。
- 属于一种保险措施，删除该配置后项目一般仍能运行。

### `pnpm-lock.yaml`

与其他包管理器的 lock 文件类似，用于锁定依赖版本、加快下载和安装速度，在保证项目可重现性和一致性方面起重要作用。安装依赖时自动生成，不需要关注。

### `pnpm-workspace.yaml`

vben 的 internal、packages、apps 三个文件夹也可以作为完整项目运行，该配置文件的主要目的就是给这些子项目共享依赖。

## 仓库描述类

这些属性比较简单，代码托管平台会读取这些字段展示仓库页面，仅作为描述性信息使用：

```json
"name": "vben-admin",                       // 项目的名称
"version": "2.10.0",                        // 项目的版本号
"homepage": "https://github.com/vbenjs/vue-vben-admin",  // 项目主页
"bugs": { "url": "..." },                   // 问题追踪地址
"repository": { "type": "git", "url": "..." }, // 代码仓库信息
"license": "MIT",                           // 授权方式
"author": { "name": "vben", "email": "anncwb@126.com" } // 作者信息
```

### license 补充

license 字段定义项目的授权方式和使用限制。MIT 是一种宽松的开源许可证：

- 使用自由：任何人可免费使用源代码，包括商业用途。
- 修改自由：可自由修改源代码，修改后可保留 MIT 许可证。
- 分发自由：可自由分发源代码，包括在开源或闭源项目中使用。
- 免责声明：软件"按原样"提供，作者不承担任何责任。

`license` 字段与根目录 `LICENSE` 文件的联系与区别：

- `license` 字段：简单声明许可证类型（如 "MIT"），让其他开发者快速了解。
- `LICENSE` 文件：包含完整许可证文本（使用分发方式、版权信息、免责声明），具有法律效力。

两者通常保持一致，从简要说明到详细条款共同满足许可证要求和合规性。

## 运行脚本类

```json
"scripts": {
  "bootstrap": "pnpm install",
  "build": "cross-env NODE_ENV=production pnpm vite build",
  "build:analyze": "pnpm vite build --mode analyze",
  "build:no-cache": "pnpm clean:cache && npm run build",
  "build:test": "pnpm vite build --mode test",
  "commit": "czg",
  "dev": "pnpm vite",
  "preinstall": "npx only-allow pnpm",
  "postinstall": "turbo run stub",
  "lint": "turbo run lint",
  "lint:eslint": "eslint --cache --max-warnings 0  \"{src,mock}/**/*.{vue,ts,tsx}\" --fix",
  "lint:prettier": "prettier --write .",
  "lint:stylelint": "stylelint \"**/*.{vue,css,less.scss}\" --fix --cache --cache-location node_modules/.cache/stylelint/",
  "prepare": "husky install",
  "preview": "npm run build && vite preview",
  "reinstall": "rimraf pnpm-lock.yaml && rimraf package.lock.json && rimraf node_modules && npm run bootstrap",
  "serve": "npm run dev",
  "test:gzip": "npx http-server dist --cors --gzip -c-1",
  "type:check": "vue-tsc --noEmit --skipLibCheck"
}
```

**执行原理**：使用 `npm run script` 执行脚本时会创建一个 shell，该 shell 会将当前项目的可执行依赖目录（`node_modules/.bin`）添加到环境变量 PATH 中，执行后恢复原样——所以脚本命令中的依赖名不需要加路径。

- `bootstrap`：使用 pnpm 执行依赖安装。
- `build`：cross-env 跨平台设置 `NODE_ENV=production`，触发生产环境的优化和压缩行为，再执行 `vite build` 生成生产环境代码。
- `build:analyze`：通过 `--mode analyze` 覆盖默认模式，构建时执行代码分析，生成统计信息和报告。Vite 默认 dev 命令运行在 development 模式，build 运行在 production 模式（自动加载 `.env.production`），`--mode` 可覆盖。
- `build:no-cache`：构建前清除缓存，是常见的排除故障步骤。pnpm 同样可用 `pnpm cache clear` 清空本地缓存。
- `build:test`：构建测试环境使用的代码。
- `commit`：使用 czg 交互式提交代码。
- `dev` / `serve`：运行开发模式。
- `lint`：借助 turbo 完成 lint 相关操作。
- `lint:eslint`：`--cache` 启用缓存提高速度；`--max-warnings 0` 任何警告都视为错误；指定 src 和 mock 下的 vue/ts/tsx 文件；`--fix` 自动修复。
- `lint:prettier`：`--write` 格式化并修改文件，`.` 表示当前目录下所有文件。
- `lint:stylelint`：`--fix` 自动修复；`--cache` 启用缓存；`--cache-location` 指定缓存文件位置。
- `preview`：先构建再通过 `vite preview` 启动本地服务器预览构建后的项目。
- `reinstall`：rimraf 递归删除 lock 文件和 node_modules 后重新安装，用于切换分支、解决依赖冲突等需要干净重装的场景。
- `test:gzip`：用 http-server 启动本地服务器测试 gzip 压缩。`--cors` 允许跨域，`--gzip` 启用 gzip 压缩，`-c-1` 禁用缓存。gzip 压缩可在前端（构建工具生成 .gz 文件）和服务端（服务器压缩响应）两个层面开启。
- `type:check`：`vue-tsc` 对 Vue 项目做类型检查，`--noEmit` 只检查不生成输出文件，`--skipLibCheck` 跳过库文件检查以加快速度。

### 三个 npm 生命周期钩子

- `preinstall`：安装依赖之前执行。`only-allow` 用于限制包管理器——检查当前是否使用 pnpm，不是则中断安装，强制使用正确的包管理器，避免兼容性问题或不一致。
- `postinstall`：安装依赖之后执行。`turbo run stub` 运行 turbo（任务运行器）中定义的 stub 任务。
- `prepare`：安装依赖时执行。`husky install` 安装并配置 Git 钩子，即 GIT 配置篇中 husky 的初始化入口。

## 代码修复类

```json
"lint-staged": {
  "*.{js,jsx,ts,tsx}": [
    "prettier --write",
    "eslint --fix"
  ],
  "{!(package)*.json,*.code-snippets,.!(browserslist)*rc}": [
    "prettier --write --parser json"
  ],
  "package.json": [
    "prettier --write"
  ],
  "*.vue": [
    "prettier --write",
    "eslint --fix",
    "stylelint --fix"
  ],
  "*.{scss,less,styl,html}": [
    "prettier --write",
    "stylelint --fix"
  ],
  "*.md": [
    "prettier --write"
  ]
}
```

提供给 husky 暴露的 git 钩子 pre-commit 使用：触发 git commit 时自动按此配置执行代码修复。写法比较固定。

## 提交信息类

```json
"config": {
  "commitizen": {
    "path": "node_modules/cz-git"
  }
}
```

vben 推荐 czg 提交代码，但不排斥 Commitizen。通过此配置项配置好 Commitizen 的适配器为 cz-git，喜欢 Commitizen 的成员也可以无感切换到统一配置。

## 环境描述类

```json
"packageManager": "pnpm@8.1.0",
"engines": {
  "node": ">=16.15.1",
  "pnpm": ">=8.1.0"
}
```

- `packageManager`：指定项目使用的包管理器是 pnpm 8.1.0。
- `engines`：指定项目所需的 Node.js 和 pnpm 最低版本要求。

这些字段的目的为确保项目在正确的环境中运行，但也仅提供对所需工具和环境的建议，即使无视继续安装其他版本也能执行。
