# 路由配置

*类型：practice ｜ 难度：进阶 ｜ 标签：vue-vben-admin、vue-router、路由守卫、动态路由、权限*

**Vben Admin 的路由体系分四层：`setupRouter` 注册路由实例（hash 模式 + 基础路由），`setupRouterGuard` 挂载九个职责单一的守卫，权限模式下通过 `buildRoutesAction` 动态构建路由（前端角色过滤 / 路由转菜单 / 后台返回路由三种方案），多级路由最终拍平为两级。核心思想是「静态注册基础路由 + 运行时按权限动态追加业务路由」。**

## 路由注册

`main.ts` 中有关 router 的执行代码：

```ts
import { router, setupRouter } from '@/router';
import { setupRouterGuard } from '@/router/guard';

// ...
async function bootstrap() {
  // 配置路由
  setupRouter(app);

  // 路由守卫
  setupRouterGuard(router);
}
```

### 注册路由 setupRouter

来源：`src/router/index.ts`

```ts
import type { App } from 'vue';
// 配置路由器
export function setupRouter(app: App<Element>) {
  app.use(router);
}
```

- `app.use(router)` 是 Vue 标准的插件注册函数，将 vue-router 实例注册在 vue 应用上。
- TS：`app: App<Element>` 直接抄录 vue-app 实例的类型，`createApp` 创建的实例就是 `App<Element>` 类型。

### 路由实例 router

```ts
import type { RouteRecordRaw } from 'vue-router';
import { createRouter, createWebHashHistory } from 'vue-router';

// 创建一个可以被 Vue 应用程序使用的路由实例
export const router = createRouter({
  // 创建一个 hash 历史记录
  history: createWebHashHistory(import.meta.env.VITE_PUBLIC_PATH),
  // 初始路由列表
  routes: basicRoutes as unknown as RouteRecordRaw[],
  // 是否应该禁止尾部斜杠，默认为 false
  strict: true,
  // 切换路由后滚动到顶部
  scrollBehavior: () => ({ left: 0, top: 0 }),
});
```

- `history`：接受路由模式。hash 模式（`createWebHashHistory`）不需要服务器配置、简单易用；history 模式（`createWebHistory`）需要服务器配置。两者观感差距明显：

```js
// history 模式
http://192.168.3.47:5173/main-out
// hash 模式
http://192.168.3.47:5173/#/main-out
```

- `createWebHashHistory` 接受一个基础路径作为参数，用来重制 web 应用根路径：

```ts
// 基于 https://example.com/folder
createWebHashHistory() // 给出 `https://example.com/folder#` 的 URL
createWebHashHistory('/folder/') // 给出 `https://example.com/folder/#` 的 URL
// 基础位置提供 `#` 时不会被再次添加
createWebHashHistory('/folder/#/app/') // 给出 `https://example.com/folder/#/app/` 的 URL
```

- `routes`：接受基础路由列表。
- `scrollBehavior`：控制切换路由后页面滚动的行为。
- TS：`as unknown as RouteRecordRaw[]` 将 basicRoutes 断言为 `RouteRecordRaw[]`。为什么需要双重断言 `as unknown as`，是因为两个类型没有足够的重叠部分，直接断言 TS 会报错，先转 unknown 再转目标类型即可绕过。

### 初始路由 basicRoutes

来源：`src/router/routes/index.ts`

```ts
import type { AppRouteRecordRaw, AppRouteModule } from '/@/router/types';
import { PAGE_NOT_FOUND_ROUTE, REDIRECT_ROUTE } from '/@/router/routes/basic';
import { mainOutRoutes } from './mainOut';

// 根路由：重定向到默认主页
export const RootRoute: AppRouteRecordRaw = {
  path: '/',
  name: 'Root',
  redirect: PageEnum.BASE_HOME,
  meta: {
    title: 'Root',
  },
};

// 登录路由
export const LoginRoute: AppRouteRecordRaw = {
  path: '/login',
  name: 'Login',
  component: () => import('/@/views/sys/login/Login.vue'),
  meta: {
    // 国际化标题
    title: t('routes.basic.login'),
  },
};

export const basicRoutes = [
  LoginRoute,
  RootRoute,
  ...mainOutRoutes,        // layout 外的自定义界面路由
  REDIRECT_ROUTE,          // 重定向处理路由
  PAGE_NOT_FOUND_ROUTE,    // 错误处理路由
];
```

基础路由的组成：登录页、根路由（重定向默认主页）、layout 外页面、重定向处理路由、404 页面。

## 路由守卫

`setupRouterGuard` 用于注册路由守卫。来源：`src/router/guard/index.ts`

```ts
export function setupRouterGuard(router: Router) {
  // 页面守卫：处理页面级别的导航守卫逻辑
  createPageGuard(router);
  // 页面加载守卫：处理页面加载过程（如显示加载动画）
  createPageLoadingGuard(router);
  // HTTP 守卫：处理与后端 API 交互时的逻辑
  createHttpGuard(router);
  // 滚动守卫：处理页面滚动行为
  createScrollGuard(router);
  // 消息守卫：处理消息通知
  createMessageGuard(router);
  // 进度守卫：处理页面加载进度
  createProgressGuard(router);
  // 权限守卫：处理页面权限控制
  createPermissionGuard(router);
  // 参数菜单守卫：必须在权限守卫之后执行（菜单已构建）
  createParamMenuGuard(router);
  // 状态守卫：处理应用状态
  createStateGuard(router);
}
```

设计要点：将不同类型的守卫逻辑拆分为独立函数，代码结构更清晰，可按需选择调用。`createParamMenuGuard` 必须在 `createPermissionGuard` 之后执行，因为此时菜单才构建完成。

## 异步路由

权限路由的核心是 `buildRoutesAction`，根据权限模式（`permissionMode`）动态生成路由：

**两个过滤器**

```ts
// 角色权限过滤：meta 中未声明 roles 的路由默认放行
const routeFilter = (route: AppRouteRecordRaw) => {
  const { meta } = route;
  const { roles } = meta || {};
  if (!roles) return true;
  // 当前用户角色列表与路由要求的角色求交集
  return roleList.some((role) => roles.includes(role));
};

// ignoreRoute 过滤：仅用于菜单生成、不进入实际路由表的路由
const routeRemoveIgnoreFilter = (route: AppRouteRecordRaw) => {
  const { meta } = route;
  const { ignoreRoute } = meta || {};
  return !ignoreRoute;
};
```

**首页 affix 修正**

```ts
// 根据设置的首页 path，递归修正 routes 中的 affix 标记（固定首页）
const patchHomeAffix = (routes: AppRouteRecordRaw[]) => {
  if (!routes || routes.length === 0) return;
  let homePath: string = userStore.getUserInfo.homePath || PageEnum.BASE_HOME;

  function patcher(routes: AppRouteRecordRaw[], parentPath = '') {
    if (parentPath) parentPath = parentPath + '/';
    routes.forEach((route: AppRouteRecordRaw) => {
      const { path, children, redirect } = route;
      // 拼接完整路径与 homePath 比对
      const currentPath = path.startsWith('/') ? path : parentPath + path;
      if (currentPath === homePath) {
        if (redirect) {
          homePath = route.redirect! as string;
        } else {
          route.meta = Object.assign({}, route.meta, { affix: true });
          // 用异常跳出递归循环
          throw new Error('end');
        }
      }
      children && children.length > 0 && patcher(children, currentPath);
    });
  }

  try {
    patcher(routes);
  } catch (e) {
    // 已处理完毕跳出循环
  }
  return;
};
```

**三种权限模式**

```ts
switch (permissionMode) {
  // 角色权限模式
  case PermissionModeEnum.ROLE:
    // 对非一级路由进行过滤
    routes = filter(asyncRoutes, routeFilter);
    // 对一级路由根据角色权限过滤
    routes = routes.filter(routeFilter);
    // 将多级路由转换为 2 级路由
    routes = flatMultiLevelRoutes(routes);
    break;

  // 路由映射模式，默认进入该 case
  case PermissionModeEnum.ROUTE_MAPPING:
    // 两轮角色过滤
    routes = filter(asyncRoutes, routeFilter);
    routes = routes.filter(routeFilter);
    // 将路由转换成菜单
    const menuList = transformRouteToMenu(routes, true);
    // 移除 ignoreRoute: true 的路由（非一级 + 一级）
    routes = filter(routes, routeRemoveIgnoreFilter);
    routes = routes.filter(routeRemoveIgnoreFilter);
    // 菜单按 orderNo 排序后存入 store
    menuList.sort((a, b) => {
      return (a.meta?.orderNo || 0) - (b.meta?.orderNo || 0);
    });
    this.setFrontMenuList(menuList);
    routes = flatMultiLevelRoutes(routes);
    break;

  // 后台动态权限模式：不需要后台动态权限时注释整个判断
  case PermissionModeEnum.BACK:
    const { createMessage } = useMessage();
    createMessage.loading({ content: t('sys.app.menuLoading'), duration: 1 });

    // 模拟从后台获取权限码，实际项目可放在合适的时间执行
    let routeList: AppRouteRecordRaw[] = [];
    try {
      await this.changePermissionCode();
      routeList = (await getMenuList()) as AppRouteRecordRaw[];
    } catch (error) {
      console.error(error);
    }

    // 动态引入组件（后台返回的是组件路径字符串，需要转换为真实组件）
    routeList = transformObjToRoute(routeList);
    // 后台路由转菜单结构
    const backMenuList = transformRouteToMenu(routeList);
    this.setBackMenuList(backMenuList);
    // 删除 meta.ignoreRoute 项
    routeList = filter(routeList, routeRemoveIgnoreFilter);
    routeList = routeList.filter(routeRemoveIgnoreFilter);
    routeList = flatMultiLevelRoutes(routeList);
    routes = [PAGE_NOT_FOUND_ROUTE, ...routeList];
    break;
}

routes.push(ERROR_LOG_ROUTE);
patchHomeAffix(routes);
return routes;
```

三种模式对比：

| 模式 | 路由来源 | 权限判断方式 | 菜单生成方式 |
| --- | --- | --- | --- |
| ROLE | 前端 asyncRoutes | meta.roles 与用户角色比对 | 由路由直接渲染 |
| ROUTE_MAPPING | 前端 asyncRoutes | meta.roles 与用户角色比对 | transformRouteToMenu 转菜单并排序 |
| BACK | 后台接口返回 | 权限码由后台控制 | 后台路由转菜单 |

共同的后处理：追加错误日志路由 `ERROR_LOG_ROUTE`、执行 `patchHomeAffix` 固定首页标记。`flatMultiLevelRoutes` 将多级路由转换为两级——这是 Vue3 keep-alive 与路由嵌套限制下的常见工程化处理。
