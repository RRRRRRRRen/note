# 计算属性

*类型：knowledge ｜ 难度：基础 ｜ 标签：Vue、Vue3、computed、缓存*

**`computed()` 接收一个 getter 函数，返回一个计算属性 ref，其值基于响应式依赖被缓存——依赖不变就不再重新计算，这是它与「模板里调方法」的本质区别。** getter 应保持纯净：不做异步请求、不改 DOM、不就地变更原数组（如 `reverse()` / `sort()`）。需要反向写入时，使用带 getter/setter 的可写计算属性。

## 特征

- `computed()` 方法期望接收一个 getter 函数，返回值为一个计算属性 ref。
- 计算属性值会基于其响应式依赖被缓存：依赖未变化时，重复访问直接返回缓存值。
- getter 不应有副作用：不要在 getter 中做异步请求或者更改 DOM。
- 计算属性中使用 `reverse()` 和 `sort()` 时务必小心：这两个方法会变更原始数组，计算函数中不应这么做（应先创建副本，如 `[...arr].sort()`）。

## 示例：基本用法

```vue
<script setup>
import { reactive, computed } from 'vue'

const author = reactive({
  name: 'John Doe',
  books: [
    'Vue 2 - Advanced Guide',
    'Vue 3 - Basic Guide',
    'Vue 4 - The Mystery'
  ]
})

// 一个计算属性 ref：依赖 author.books，被缓存
const publishedBooksMessage = computed(() => {
  return author.books.length > 0 ? 'Yes' : 'No'
})
</script>

<template>
  <p>Has published books:</p>
  <span>{{ publishedBooksMessage }}</span>
</template>
```

- 模板中使用计算属性 ref 同样自动解包，无需 `.value`。

## 示例：可写计算属性

传入含 `get` / `set` 的对象，计算属性即可双向工作：

```vue
<script setup>
import { ref, computed } from 'vue'

const firstName = ref('John')
const lastName = ref('Doe')

const fullName = computed({
  // getter：读取 fullName 时执行
  get() {
    return firstName.value + ' ' + lastName.value
  },
  // setter：给 fullName 赋值时执行
  set(newValue) {
    // 注意：这里使用的是解构赋值语法
    [firstName.value, lastName.value] = newValue.split(' ')
  }
})
</script>
```

## 计算属性 vs 方法

| 维度 | 计算属性 computed | 方法 method |
| --- | --- | --- |
| 缓存 | 依赖不变时缓存结果 | 每次渲染都重新执行 |
| 适用 | 派生数据、多次使用的昂贵运算 | 事件处理、每次都要执行的动作 |
| 副作用 | getter 必须纯净 | 无此限制 |
| 使用方式 | 当属性访问（自动解包） | 函数调用 `fn()` |

- 结论：模板中「像变量一样用的派生值」一律用 computed；「每次渲染都要执行、或作为事件处理器」才用方法。
