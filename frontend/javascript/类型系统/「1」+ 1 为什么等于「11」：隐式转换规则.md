# 「1」+ 1 为什么等于「11」：隐式转换规则

*类型：knowledge ｜ 难度：进阶 ｜ 标签：类型系统、隐式转换、ToPrimitive、面试 ｜ 更新：2026-09-10*

**结论：隐式转换不用背清单，记方向就够：`+` 只要有一方是字符串就走拼接，`==` 偏好把双方转成数字（ToNumber），`!` 一律走 ToBoolean（对象恒真）。 对象参与运算前先过 ToPrimitive（valueOf → toString）。 所以 `'1' + 1` 是 '11'：'1' 是字符串，+ 选拼接，1 转成 '1'。 面试输出题的富矿全在 `==` 的多步转换链；工程里用 `===` 规避。 类型判断（三把尺子）与浮点精度已拆成独立篇。**

前置篇目（见文末延伸阅读）：先会「认」一个值的类型（三把尺子），再学值之间怎么「变」——转换只发生在运算符要求的位置。

## '1' + 1 是怎么变成 '11' 的：ToPrimitive

`+` 是唯一身兼两职的算术运算符：数字相加与字符串拼接。 它的算法分三步（据 ECMA-262 加法运算符的语义）： ① 双方各自 ToPrimitive——对象依次尝试 `valueOf` → `toString`，原始值原样通过； ② 转换后若**任一方是字符串**，另一方也 ToString，走拼接； ③ 否则双方 ToNumber 相加。 `'1' + 1` 的完整推演： '1' 已是原始值原样通过第①步； 第②步发现字符串，把 1 转成 '1'； 拼接得 '11'。 而 `'1' - 1` 是 0——减法没有拼接语义，'1' 被 ToNumber 成 1。

ToPrimitive 是所有转换题的第一站，因为**对象必须先变成原始值才有资格参与运算**。 普通对象走 valueOf（默认返回自身，等于没转）→ toString（'[object Object]'）； 数组没有 valueOf 价值，toString 等价于 `join(',')`——空数组得 `''`，[1,2] 得 '1,2'。 把这两条规则记牢，下面所有诡异表达式都是它们的排列组合。

```javascript
'1' + 1     // "11" —— + 看到字符串走拼接
'1' - 1     // 0 —— 减法只有数字语义，'1' 被 ToNumber
1 + '1'     // "11" —— 换个位置，规则不变
[] + {}     // "[object Object]" —— '' + '[object Object]'
[1, 2] + 1  // "1,21" —— 数组 ToPrimitive 得 "1,2"
// （Node 22.17 验证）
```

## == 与 ! 的转换方向

`==` 的偏好是**数字**： 遇到布尔先把布尔转数字（false → 0）； 对象与原始值比较时，对象过 ToPrimitive 再比。 `!` 的偏好是**布尔**： 且对象到布尔没有任何转换发生——一律 true。 高频输出题 `[] == ![]` 把两条规则拧在了一起，先自己推一遍再看解读：

```javascript
console.log([] == ![]); // true
// （Node 22.17 验证）—— 空数组既「真」又「等于 false」，不矛盾
```

输出解读（`[] == ![]`）：

```text
![] → false
[] == false
[] == 0
'' == 0 → true
```

- `![] → false`（同步）：右边的 ! 先算——空数组是对象，ToBoolean 永远为 true，取反得到 false。任何对象 ! 一下都是 false。
- `[] == false`（同步）：原式变成空数组与布尔比较。== 遇到布尔值，先把布尔转数字：false → 0。
- `[] == 0`（同步）：左边是对象、右边是数字，触发 ToPrimitive([])：调用 join() 得到空字符串 ''。
- `'' == 0 → true`（同步）：字符串与数字比较走 ToNumber，'' → 0。0 == 0，最终输出 true。

> **记住：转换方向口诀。** `==` 偏好**数字**（ToNumber），`+` 偏好**字符串**（有一方是 string 就拼接），`!` 一律走 **ToBoolean**（对象恒为 true）。 对象参与运算先过 ToPrimitive（valueOf → toString）。

## 类型转换为字符串：ToString 规则表

显式 `String()` 与字符串拼接触发的 ToString 共用同一张规则表。两个易错点单独拎出来：极大/极小数字转科学计数法；`symbol` 只能显式转换，隐式拼接直接抛 TypeError。

| 类型 | 转换结果 | 示例 |
|------|---------|------|
| `undefined` | `"undefined"` | `String(undefined)` → `"undefined"` |
| `null` | `"null"` | `String(null)` → `"null"` |
| `boolean` | `"true"` / `"false"` | `String(true)` → `"true"` |
| `number` | 数字字符串 | `String(123)` → `"123"` |
| `symbol` | 只能显式转换 | `String(Symbol())` → `"Symbol()"` |
| `object` | 调用 `toString()` | `String({})` → `"[object Object]"` |

```javascript
// 极大/极小数字使用科学计数法
String(1e21);        // "1e+21"

// Symbol 隐式拼接会报错，必须走显式 String()
Symbol() + '';       // TypeError: Cannot convert a Symbol value to a string

// 对象转换：数组按 join 逻辑，普通对象得 '[object Object]'
String([1, 2, 3]);   // "1,2,3"
String({ a: 1 });    // "[object Object]"

// 自定义 toString 可以改写结果
const obj = {
  toString() {
    return 'custom';
  }
};
String(obj);         // "custom"
```

## 类型转换为数字：ToNumber 规则表

`==`、算术运算符、一元 `+`、`Number()` 都走 ToNumber。两条反直觉的规则是高频输出题的原料：`null` 转 `0`（不是 NaN），空字符串也转 `0`。

| 类型 | 转换结果 | 示例 |
|------|---------|------|
| `undefined` | `NaN` | `Number(undefined)` → `NaN` |
| `null` | `0` | `Number(null)` → `0` |
| `true` / `false` | `1` / `0` | `Number(true)` → `1` |
| 纯数字字符串 | 数字 | `Number("123")` → `123` |
| 空字符串 | `0` | `Number("")` → `0` |
| 含非数字字符 | `NaN` | `Number("123abc")` → `NaN` |
| `symbol` | 报错 | `Number(Symbol())` → TypeError |
| `object` | 先 `valueOf()` 后 `toString()` | 见下方三步 |

数组转数字是「对象先过 ToPrimitive」的直观案例——数组的 `valueOf` 返回自身（等于没转），实际生效的是 `toString()`：

```javascript
Number([]);      // 0   —— [].toString() → '' → 0
Number([5]);     // 5   —— [5].toString() → '5' → 5
Number([1, 2]);  // NaN —— [1,2].toString() → '1,2' → NaN
Number({});      // NaN —— '[object Object]' 转不了数字
```

对象转数字的三步算法：

- 第 1 步：调用 `valueOf()`，返回原始值就用它转数字
- 第 2 步：否则调用 `toString()`，返回原始值就用它转数字
- 第 3 步：两步都没拿到原始值，抛出 `TypeError`

```javascript
const obj = {
  valueOf() {
    return 42;
  },
  toString() {
    return '100';
  }
};
Number(obj);  // 42 —— valueOf 优先于 toString
```

## 类型转换为布尔值：只有 6 个 falsy 值

ToBoolean 是三条转换路径里最简单的：**只有 6 个假值**，除它们之外的一切都是真值——包括所有对象，空数组、空对象也不例外。

```javascript
Boolean(undefined);  // false
Boolean(null);       // false
Boolean(false);      // false
Boolean(0);          // false
Boolean(NaN);        // false
Boolean('');         // false
```

「长得像假」其实全为真：字符串只看长度不看内容，包装对象一律是真值。

```javascript
Boolean('0');                // true —— 非空字符串
Boolean('false');            // true —— 非空字符串
Boolean(' ');                // true —— 含空格也算非空
Boolean([]);                 // true —— 空数组是对象
Boolean({});                 // true —— 空对象
Boolean(new Boolean(false)); // true —— 包装对象恒真
```

## 逻辑运算符的返回值：返回操作数本身

`||` 与 `&&` 返回的是**参与运算的操作数**，不是布尔值：`||` 返回第一个真值（全假则返回最后一个），`&&` 返回第一个假值（全真则返回最后一个）。

```javascript
'a' || 'b';                      // 'a' —— 第一个就是真值，短路
0 || 'hello';                    // 'hello'
null || undefined || 'default';  // 'default'
null || undefined;               // undefined —— 全假，返回最后一个

'a' && 0;                        // 0 —— 第一个假值，短路
'hello' && null;                 // null
'a' && 'b';                      // 'b' —— 全真，返回最后一个
1 && 2 && 3;                     // 3
```

经典默认值写法的假值坑：`||` 会把 `0`、`''`、`false` 这些**合法输入**一起替换掉，而不只是「没传」：

```javascript
// 坑：''、0、false 都会被 || 误伤
function greet(name) {
  name = name || 'Guest';  // 传 '' 也变成 'Guest'
  return `Hello, ${name}`;
}

// 替代方案 1：?? 只判 null 和 undefined，0、false、'' 安全
const value = input ?? 'default';

// 替代方案 2：?. 可选链，user 为 null/undefined 时短路返回 undefined
user?.getName();
```

## 边界与陷阱

三类高频事故，共同点是「结果无法从写法直接推导」——这正是 `==` 在工程规范里被禁用的原因： 它的每一步转换都合规，但组合起来的行为不成体系。

== 混用比较（loose equality）正误对照：

**错误写法：**

```javascript
// 三行看起来该一致，实际：
''  == 0    // true
'0' == 0    // true
''  == '0'  // false！
// == 的结果不满足传递性
```

问题：与数字比走 ToNumber，字符串互比走字面值——同一组值三种结论。

**正确写法：**

```javascript
Number('0') === 0  // true，显式转换
'' === '0'         // false，与上一行自洽
// 语义可推导，不需要背规范
```

要点：=== 把「转换」从隐式变显式，比较结果随时能心算验证。

语句位的花括号（statement position）正误对照：

**错误写法：**

```javascript
// 在控制台/语句开头直接写：
{} + []
// 0 —— {} 被解析成「空代码块」，
// 剩下的是一元正号：+[] → +'' → 0
```

问题：同一串字符，语句位与表达式位是两棵语法树——解析层陷阱。

**正确写法：**

```javascript
({} + [])  // "[object Object]"
[] + {}    // "[object Object]"
// 需要当值用就包括号，
// 或永远别让 {} 出现在行首
```

要点：表达式位里两者一致——都走 ToPrimitive 拼接。

对象判真（truthy trap）正误对照：

**错误写法：**

```javascript
if (arr) { }   // 空数组也恒真
if (obj) { }   // {} 同样恒真
// 想判「空」的对象写法永远不生效
```

问题：ToBoolean 对对象不做任何转换，一律 true——没有「空对象为假」这回事。

**正确写法：**

```javascript
if (arr.length > 0) { }
if (Object.keys(obj).length > 0) { }
// 「空不空」问属性，别问对象本身
```

要点：唯一例外是 null/undefined/0/''/NaN 这些原始值——它们是 falsy。

## 经典追问链

**追问一：'1' + 1 和 '1' - 1 的结果分别是什么？为什么不同？**

考察点：热身题，考 + 的拼接偏好这条「方向」的第一反应——背清单的人答得慢，记方向的人脱口而出。

'1' + 1 是 "11"： + 发现任一方是字符串就走拼接，数字 1 被 ToString 成 '1'。 '1' - 1 是 0： 减法只有数字语义，'1' 被 ToNumber 成 1。 + 是唯一有双重语义的算术运算符，这正是隐式转换事故的集中地。

- 加分项：规范层面的顺序——先双方 ToPrimitive、再查字符串、最后才 ToNumber。「先转换成原始值、再决定拼接还是相加」，不是直接判断原始类型。

**追问二：[] + {} 和 {} + [] 的结果分别是什么？为什么不一样？**

考察点：考 ToPrimitive 的方向性与语句解析的边界——能讲清第二条的人凤毛麟角，直接拉开层次。

`[] + {}` 得 '[object Object]'： 双方都是对象，+ 偏好字符串拼接，空数组 ToPrimitive 得 ''，空对象得 '[object Object]'，拼接结果就是后者。 `{} + []` 在表达式语境同样得 '[object Object]'，但在控制台/语句开头，`{}` 会被解析成空代码块而不是对象字面量，剩下的 `+ []` 是一元正号转换，`[] → '' → 0`，所以结果是数字 0。

- 加分项：验证方式——把表达式放进括号 `({} + [])` 或赋值给变量后求值，都会回到 '[object Object]'。「语句位陷阱」可以用括号消除。

**追问三：Object.is 和 === 的区别在哪？什么场景必须用它？**

考察点：考边界值语义——NaN 与 -0 两个特殊值的态度，正是三个等号体系（== / === / Object.is）的分层依据。

Object.is 与 === 几乎一致，只修正两处： NaN 与 NaN 相等（=== 为 false，因为规范规定 NaN 不等于任何值包括自身）； +0 与 -0 不相等（=== 视为相等）。 必须用 Object.is 的场景： NaN 判等（如缓存 key 比较、状态变更检测），React 里 Object.is 正是 state 更新判断的依据——setState 传入 NaN 时靠它跳过无效渲染。

- 加分项：== / === / Object.is 的递进关系——== 做隐式转换后比较，=== 不转换直接比（同类型），Object.is 在 === 基础上修正 NaN 与 ±0 两个边界。

**追问四：对象转原始值的 ToPrimitive 有 hint 吗？Date 为什么行为特殊？**

考察点：考 hint 三档与 @@toPrimitive 的覆盖关系——说出 Date 的特殊性而不说 hint，是背现象不是懂机制。

有三档 hint： "number"（==、-、\*、关系运算）、"string"（模板字符串、String()、属性键）、"default"（+ 与 ==）。 普通对象在 default 下 valueOf 优先； Date 通过 @@toPrimitive 把 default 与 string 都导向 toString——所以 `new Date() + 1` 是字符串拼接而 `new Date() - 1` 是数字减法（实测），普通对象两个都是数字运算路径。 这是「对象可以声明自己的转换偏好」的规范入口。

- 加分项：Symbol.toPrimitive 的优先级高于 valueOf/toString，且返回值必须是原始值——返回对象直接抛 TypeError: Cannot convert object to primitive value（实测）。

**追问五：为什么 if([]) 为真、[] == false 也为真？两句话矛盾吗？**

考察点：压轴题，考「转换只发生在运算符要求的位置」——把 ToBoolean 与 == 的算法混为一谈就答不出这题。

不矛盾，两条路径用的是不同算法： if 的 ToBoolean 对任何对象一律返回 true——对象到布尔之间没有任何转换发生； 而 == 的算法要求双方转数字： `![]` 先得 false，false 再 ToNumber 成 0，`[]` 过 ToPrimitive 得 ''，'' ToNumber 成 0，0 == 0。 同一份值在不同运算符语境下走不同转换链——转换不是值的固有属性，而是运算符的要求。

- 加分项：这个模型还解释了 `Boolean([]) === true` 与 `[] == false` 为什么能共存——Boolean() 走 ToBoolean（不转换对象），== 走 ToPrimitive + ToNumber。JS 里唯一让「对象转原始值再转数字」的常规入口就是 == 和关系运算符。
