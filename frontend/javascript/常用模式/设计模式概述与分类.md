# 设计模式概述与分类

*类型：knowledge ｜ 难度：基础 ｜ 标签：设计模式、分类、创建型、结构型、行为型*

**结论：设计模式是软件开发中反复使用、多数人知晓、经过分类编目的代码设计经验总结，目的不是「套模板」而是三件事：可重用（避免重复造轮子）、易理解（用统一词汇沟通设计）、更可靠（久经验证的方案保证正确性）。按目的分为三类——创建型关注「对象怎么创建」（单例、工厂、建造者、原型），结构型关注「对象怎么组合」（适配器、装饰器、代理），行为型关注「对象怎么通信」（观察者、策略、命令、迭代器）。记住分类轴心，面对新场景就能按「创建 / 组合 / 通信」三问定位候选模式。**

## 什么是设计模式

设计模式是软件开发中经过反复使用、多数人知晓、经过分类编目的代码设计经验的总结。使用设计模式是为了可重用代码、让代码更容易被他人理解、保证代码可靠性。

模式不是发明的，是从大量实践中「被发现并命名」的通用解法——它描述的是特定上下文下反复出现的问题及其核心解法。

## 设计模式的分类

按目的（Gang of Four 分类法）分为三类：

**创建型模式（Creational Patterns）**

- 关注对象的创建过程：把「创建」从使用方代码中解耦
- 包括：单例、工厂、抽象工厂、建造者、原型

**结构型模式（Structural Patterns）**

- 关注对象的组合和关系：用组合搭出更大的结构
- 包括：适配器、装饰器、代理、桥接、组合、外观、享元

**行为型模式（Behavioral Patterns）**

- 关注对象之间的通信：划分职责、定义交互方式
- 包括：观察者、策略、命令、迭代器、职责链、模板方法、状态、访问者、中介者、备忘录、解释器

三类的定位可以概括为一张表：

| 分类 | 关注点 | 回答的问题 | JS 常见代表 |
|------|--------|-----------|-------------|
| 创建型 | 对象创建 | 对象由谁、如何、何时创建 | 单例、工厂、建造者 |
| 结构型 | 对象组合 | 类与对象如何组成更大结构 | 适配器、装饰器、代理 |
| 行为型 | 对象通信 | 对象间职责如何分配与交互 | 观察者、策略、命令 |

## 设计模式的优势

- **提高代码复用性**：避免重复造轮子，成熟方案直接落地
- **提高代码可读性**：统一的设计模式便于他人理解意图
- **提高代码可维护性**：结构清晰，改动影响面可预期
- **降低耦合度**：模块之间的依赖关系更清晰

## 实践要点

- 模式是手段不是目的：先有真实变化点，再选模式；为模式而模式会引入不必要的复杂度
- JavaScript 基于原型和一等函数，部分经典模式（如原型模式、迭代器）已有语言级支持，不必按类语言的写法硬套
- 面试与日常的高频集合：创建型的单例/工厂/建造者，结构型的适配器/装饰器/代理，行为型的观察者/策略/职责链
