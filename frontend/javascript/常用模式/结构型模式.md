# 结构型模式

*类型：knowledge ｜ 难度：进阶 ｜ 标签：设计模式、结构型、适配器、装饰器、代理*

**结论：结构型模式关注「对象怎么组合」，JS 高频的三个各管一件事：适配器模式管「接口不兼容」——把已有接口转换成期望的接口，常用于兼容旧代码或第三方库；装饰器模式管「功能增强」——不改变原对象结构，通过包装动态叠加功能（同一接口层层包裹），ES7 装饰器语法是它的语言化；代理模式管「访问控制」——代理与真实对象同接口，在访问前后插入控制逻辑（虚拟代理延迟创建、缓存代理缓存结果、ES6 Proxy 拦截属性操作）。三者的分辨口诀：接口不同用适配器，接口相同加功能用装饰器，接口相同加控制用代理。**

## 适配器模式（Adapter Pattern）

将一个类的接口转换成客户端所期望的另一个接口，让原本不兼容的类可以协作。

```js
// 旧接口：调用方已按 request() 写好的代码
class OldAPI {
  request() {
    return '旧接口返回的数据';
  }
}

// 新接口：方法名是 fetch()
class NewAPI {
  fetch() {
    return '新接口返回的数据';
  }
}

// 适配器：包装新接口，对外暴露旧接口
class APIAdapter {
  constructor(api) {
    this.api = api;
  }
  request() {
    return this.api.fetch(); // 把新接口的 fetch 适配为 request
  }
}

const oldAPI = new OldAPI();
console.log(oldAPI.request()); // '旧接口返回的数据'

const newAPI = new NewAPI();
const adapter = new APIAdapter(newAPI);
console.log(adapter.request()); // '新接口返回的数据'（调用方代码无需改动）
```

实际应用——第三方库适配：外部库接口与自家抽象不一致时，用适配器隔离外部变化。

```js
// 第三方日志库：方法签名是 logMessage(level, message)
class ThirdPartyLogger {
  logMessage(level, message) {
    console.log(`[${level.toUpperCase()}] ${message}`);
  }
}

// 我们的日志接口
class Logger {
  info(message)  { throw new Error('子类必须实现 info 方法'); }
  error(message) { throw new Error('子类必须实现 error 方法'); }
}

// 适配器：继承我们的接口，内部委托第三方实现
class LoggerAdapter extends Logger {
  constructor() {
    super();
    this.thirdPartyLogger = new ThirdPartyLogger();
  }
  info(message) {
    this.thirdPartyLogger.logMessage('info', message);
  }
  error(message) {
    this.thirdPartyLogger.logMessage('error', message);
  }
}

const logger = new LoggerAdapter();
logger.info('这是一条信息');  // [INFO] 这是一条信息
logger.error('这是一条错误'); // [ERROR] 这是一条错误
```

价值：日后更换第三方库，只需替换适配器内部实现，业务代码零改动。

## 装饰器模式（Decorator Pattern）

在不改变对象自身结构的前提下，动态地给对象叠加功能。装饰器与被装饰者实现同一接口，装饰器内部持有原对象。

```js
// 基础组件
class Coffee {
  cost() { return 10; }
  description() { return '咖啡'; }
}

// 装饰器基类：接口与 Coffee 一致，内部持有被装饰对象
class CoffeeDecorator {
  constructor(coffee) {
    this.coffee = coffee;
  }
  cost() { return this.coffee.cost(); }
  description() { return this.coffee.description(); }
}

// 具体装饰器：只叠加自己的增量
class MilkDecorator extends CoffeeDecorator {
  cost() { return this.coffee.cost() + 2; }
  description() { return this.coffee.description() + ' + 牛奶'; }
}

class SugarDecorator extends CoffeeDecorator {
  cost() { return this.coffee.cost() + 1; }
  description() { return this.coffee.description() + ' + 糖'; }
}

let coffee = new Coffee();
console.log(coffee.description(), coffee.cost()); // '咖啡' 10

coffee = new MilkDecorator(coffee); // 层层包裹
console.log(coffee.description(), coffee.cost()); // '咖啡 + 牛奶' 12

coffee = new SugarDecorator(coffee);
console.log(coffee.description(), coffee.cost()); // '咖啡 + 牛奶 + 糖' 13
```

ES7 装饰器语法是同一思想的语言化：

```js
// 类装饰器：修改类（或其原型）
function readonly(target) {
  target.prototype.readonly = true;
  return target;
}

@readonly
class Person {
  constructor(name) {
    this.name = name;
  }
}

// 方法装饰器：拦截方法调用，附加日志逻辑
function log(target, name, descriptor) {
  const original = descriptor.value;

  descriptor.value = function(...args) {
    console.log(`调用 ${name} 方法，参数:`, args);
    const result = original.apply(this, args);
    console.log(`${name} 方法返回:`, result);
    return result;
  };
  return descriptor;
}

class Calculator {
  @log
  add(a, b) {
    return a + b;
  }
}

const calc = new Calculator();
calc.add(2, 3);
// 调用 add 方法，参数: [2, 3]
// add 方法返回: 5
```

## 代理模式（Proxy Pattern）

提供一个代理对象控制对目标对象的访问；代理与真实对象接口一致，在调用前后插入控制逻辑。

### 虚拟代理：延迟创建开销大的对象

```js
// 真实图片类：创建即加载
class Image {
  constructor(src) {
    this.src = src;
    this.load();
  }
  load() {
    console.log(`加载图片: ${this.src}`);
  }
  display() {
    console.log(`显示图片: ${this.src}`);
  }
}

// 图片代理：接口与 Image 一致，把「加载」推迟到真正 display 时
class ImageProxy {
  constructor(src) {
    this.src = src;
    this.image = null;
  }
  display() {
    if (!this.image) {
      console.log('显示占位图');
      // 延迟创建真实对象
      setTimeout(() => {
        this.image = new Image(this.src);
        this.image.display();
      }, 2000);
    } else {
      this.image.display();
    }
  }
}

const imageProxy = new ImageProxy('https://example.com/image.jpg');
imageProxy.display(); // 显示占位图
// 2秒后: 加载图片: https://example.com/image.jpg
//        显示图片: https://example.com/image.jpg
```

### 缓存代理：为昂贵计算缓存结果

```js
function fibonacci(n) {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}

// 缓存代理：包装原函数，调用前查缓存
function createCacheProxy(fn) {
  const cache = new Map();

  return function(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      console.log('从缓存读取');
      return cache.get(key);
    }
    console.log('计算结果');
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const cachedFibonacci = createCacheProxy(fibonacci);
console.log(cachedFibonacci(10)); // 计算结果 55
console.log(cachedFibonacci(10)); // 从缓存读取 55
```

### ES6 Proxy：语言级代理

ES6 的 `Proxy` 把代理模式做成原生能力，可拦截对象的各类操作。

```js
// 数据验证代理：拦截 set 操作
const validator = {
  set(target, property, value) {
    if (property === 'age') {
      if (typeof value !== 'number' || value < 0 || value > 150) {
        throw new Error('年龄必须是 0-150 之间的数字');
      }
    }
    target[property] = value; // 校验通过才写入
    return true;
  }
};

const person = new Proxy({}, validator);

person.age = 25; // 正常
console.log(person.age); // 25

// person.age = -1;   // Error: 年龄必须是 0-150 之间的数字
// person.age = 'abc'; // Error: 年龄必须是 0-150 之间的数字
```

## 三个模式的分辨

| 模式 | 接口关系 | 解决的问题 | 典型场景 |
|------|----------|-----------|----------|
| 适配器 | 接口不同，做转换 | 兼容已有接口 | 接旧库、迁移期兼容 |
| 装饰器 | 接口相同，做增强 | 动态叠加功能 | 日志、计费、权限校验 |
| 代理 | 接口相同，做控制 | 控制访问时机与方式 | 懒加载、缓存、验证 |

## 实践要点

- 适配器是「补丁思维」：修历史包袱，新系统设计时应直接对齐接口
- 装饰器叠加的顺序决定行为（牛奶加糖与糖加牛奶成本相同，但一般逻辑不一定），包装链不宜过长
- Vue3 的响应式系统就是 ES6 Proxy 代理模式的工业级应用，理解手写验证代理即可理解其原理
- 缓存代理与纯函数天然配套：函数有副作用时缓存结果会出错
