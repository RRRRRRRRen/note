# 行为型模式

*类型：knowledge ｜ 难度：进阶 ｜ 标签：设计模式、行为型、观察者、发布订阅、策略、命令、迭代器、职责链、模板方法*

**结论：行为型模式解决「对象之间如何通信与分工」，七个高频模式按问题记：一对多状态通知用观察者（主题直接维护观察者列表）；跨模块解耦通信用发布-订阅（事件中心居中转发，发布者与订阅者互不相识）；消除 if/else 分支用策略（每个算法独立封装、可互相替换）；请求参数化与撤销重做用命令（请求封装成对象，天然支持 undo 栈）；顺序访问集合用迭代器（ES6 已有 `[Symbol.iterator]` 语言级支持）；多级校验过滤用职责链（处理器串成链，逐级传递或拦截）；算法骨架固定、步骤可变用模板方法（父类定流程，子类填步骤，钩子方法控制可选环节）。**

## 观察者模式（Observer Pattern）

定义对象间一对多依赖：主题（Subject）状态变化时，自动通知所有观察者（Observer）。主题与观察者直接关联。

```js
// 主题（被观察者）：维护观察者列表
class Subject {
  constructor() {
    this.observers = [];
  }

  attach(observer) {
    this.observers.push(observer);
  }

  detach(observer) {
    const index = this.observers.indexOf(observer);
    if (index > -1) {
      this.observers.splice(index, 1);
    }
  }

  notify(data) {
    this.observers.forEach(observer => observer.update(data));
  }
}

// 观察者：约定必须有 update 方法
class Observer {
  constructor(name) {
    this.name = name;
  }
  update(data) {
    console.log(`${this.name} 收到通知:`, data);
  }
}

const subject = new Subject();
subject.attach(new Observer('观察者1'));
subject.attach(new Observer('观察者2'));

subject.notify('状态改变了');
// 观察者1 收到通知: 状态改变了
// 观察者2 收到通知: 状态改变了
```

落地形态——事件系统（Node.js EventEmitter 的简化版）：

```js
class EventEmitter {
  constructor() {
    this.events = {};
  }

  on(event, listener) {
    if (!this.events[event]) {
      this.events[event] = [];
    }
    this.events[event].push(listener);
  }

  off(event, listener) {
    if (!this.events[event]) return;
    this.events[event] = this.events[event].filter(l => l !== listener);
  }

  emit(event, ...args) {
    if (!this.events[event]) return;
    this.events[event].forEach(listener => {
      listener.apply(this, args);
    });
  }

  once(event, listener) {
    // 包装函数执行一次后自摘除
    const wrapper = (...args) => {
      listener.apply(this, args);
      this.off(event, wrapper);
    };
    this.on(event, wrapper);
  }
}

const emitter = new EventEmitter();
emitter.on('data', data => console.log('收到数据:', data));
emitter.emit('data', { id: 1, name: 'Alice' });
// 收到数据: { id: 1, name: 'Alice' }
```

## 发布-订阅模式（Pub-Sub Pattern）

观察者模式的解耦变体：引入事件中心，发布者与订阅者互不感知。

```js
class PubSub {
  constructor() {
    this.events = {};
  }

  subscribe(event, callback) {
    if (!this.events[event]) {
      this.events[event] = [];
    }
    this.events[event].push(callback);

    // 返回取消订阅函数，调用方无需持有 callback 引用
    return () => {
      this.unsubscribe(event, callback);
    };
  }

  publish(event, ...args) {
    if (!this.events[event]) return;
    this.events[event].forEach(callback => callback(...args));
  }

  unsubscribe(event, callback) {
    if (!this.events[event]) return;
    if (!callback) {
      delete this.events[event]; // 不传 callback：清空该事件
    } else {
      this.events[event] = this.events[event].filter(cb => cb !== callback);
    }
  }
}

const pubsub = new PubSub();

const unsubscribe1 = pubsub.subscribe('login', user => {
  console.log('用户登录:', user);
});
pubsub.subscribe('login', user => {
  console.log('记录日志:', user);
});

pubsub.publish('login', { name: 'Alice' });
// 用户登录: { name: 'Alice' }
// 记录日志: { name: 'Alice' }

unsubscribe1();
pubsub.publish('login', { name: 'Bob' });
// 记录日志: { name: 'Bob' }
```

观察者与发布-订阅的取舍：

| 特性 | 观察者模式 | 发布-订阅模式 |
|------|-----------|--------------|
| 耦合度 | 观察者和主题直接关联 | 通过事件中心解耦 |
| 灵活性 | 较低 | 较高 |
| 复杂度 | 简单 | 稍复杂 |
| 适用场景 | 对象间直接通信 | 跨模块通信 |

## 策略模式（Strategy Pattern）

定义一系列可互相替换的算法，各自封装，运行时按需切换，消除大量条件分支。

```js
// 策略类族：统一 calculate 接口
class DiscountStrategy {
  calculate(price) {
    throw new Error('子类必须实现 calculate 方法');
  }
}

class NoDiscount extends DiscountStrategy {
  calculate(price) { return price; }
}

class PercentDiscount extends DiscountStrategy {
  constructor(percent) {
    super();
    this.percent = percent;
  }
  calculate(price) {
    return price * (1 - this.percent);
  }
}

class FixedDiscount extends DiscountStrategy {
  constructor(amount) {
    super();
    this.amount = amount;
  }
  calculate(price) {
    return Math.max(0, price - this.amount);
  }
}

// 上下文：持有策略、可运行时替换
class ShoppingCart {
  constructor(strategy) {
    this.strategy = strategy;
  }
  setStrategy(strategy) {
    this.strategy = strategy;
  }
  checkout(price) {
    return this.strategy.calculate(price);
  }
}

const cart = new ShoppingCart(new NoDiscount());
console.log(cart.checkout(100)); // 100

cart.setStrategy(new PercentDiscount(0.2));
console.log(cart.checkout(100)); // 80

cart.setStrategy(new FixedDiscount(15));
console.log(cart.checkout(100)); // 85
```

简化版本：算法无状态时用对象字面量替代类族。

```js
const strategies = {
  S: salary => salary * 6,
  A: salary => salary * 4,
  B: salary => salary * 3
};

function calculateBonus(level, salary) {
  return strategies[level](salary);
}

console.log(calculateBonus('S', 10000)); // 60000
console.log(calculateBonus('A', 10000)); // 40000
```

实际应用——表单验证，策略 + 统一验证器：

```js
// 验证策略：每个规则一个函数，返回错误信息或空串
const validators = {
  required: (value, errorMsg) => {
    if (!value) return errorMsg || '该字段不能为空';
    return '';
  },
  minLength: (value, length, errorMsg) => {
    if (value.length < length) {
      return errorMsg || `长度不能少于${length}个字符`;
    }
    return '';
  },
  email: (value, errorMsg) => {
    const regex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    return regex.test(value) ? '' : (errorMsg || '邮箱格式不正确');
  },
  phone: (value, errorMsg) => {
    const regex = /^1[3-9]\d{9}$/;
    return regex.test(value) ? '' : (errorMsg || '手机号格式不正确');
  }
};

// 验证器：收集规则、依次执行
class Validator {
  constructor() {
    this.rules = [];
  }

  add(value, rules) {
    rules.forEach(rule => {
      // 规则串格式："strategy:参数:自定义错误信息"
      const [strategy, ...args] = rule.split(':');
      this.rules.push(() => validators[strategy](value, ...args));
    });
  }

  validate() {
    for (let rule of this.rules) {
      const error = rule();
      if (error) return error; // 返回第一个错误
    }
    return '';
  }
}

const validator = new Validator();
validator.add('', ['required:用户名不能为空', 'minLength:3:用户名至少3个字符']);
console.log(validator.validate()); // '用户名不能为空'
```

## 命令模式（Command Pattern）

把请求封装成对象（含执行与撤销），请求因此可以被排队、记录、撤销。

```js
// 接收者：真正干活的对象
class Light {
  on()  { console.log('灯打开了'); }
  off() { console.log('灯关闭了'); }
}

// 命令接口：约定 execute 与 undo
class Command {
  execute() { throw new Error('子类必须实现 execute 方法'); }
  undo()    { throw new Error('子类必须实现 undo 方法'); }
}

// 具体命令：绑定接收者，反转动作作为撤销
class LightOnCommand extends Command {
  constructor(light) {
    super();
    this.light = light;
  }
  execute() { this.light.on(); }
  undo()    { this.light.off(); }
}

class LightOffCommand extends Command {
  constructor(light) {
    super();
    this.light = light;
  }
  execute() { this.light.off(); }
  undo()    { this.light.on(); }
}

// 调用者：不关心具体命令，只调用统一接口；history 天然支持撤销
class RemoteControl {
  constructor() {
    this.command = null;
    this.history = [];
  }
  setCommand(command) {
    this.command = command;
  }
  pressButton() {
    this.command.execute();
    this.history.push(this.command);
  }
  pressUndo() {
    if (this.history.length > 0) {
      this.history.pop().undo();
    }
  }
}

const light = new Light();
const remote = new RemoteControl();

remote.setCommand(new LightOnCommand(light));
remote.pressButton(); // 灯打开了

remote.setCommand(new LightOffCommand(light));
remote.pressButton(); // 灯关闭了

remote.pressUndo();   // 灯打开了（撤销最后一条命令）
```

## 迭代器模式（Iterator Pattern）

顺序访问聚合对象的元素，而不暴露内部结构。

```js
// 手写迭代器
class Iterator {
  constructor(items) {
    this.items = items;
    this.index = 0;
  }
  hasNext() {
    return this.index < this.items.length;
  }
  next() {
    return this.items[this.index++];
  }
  reset() {
    this.index = 0;
  }
}

const iterator = new Iterator([1, 2, 3, 4, 5]);
while (iterator.hasNext()) {
  console.log(iterator.next());
}
// 1 2 3 4 5
```

ES6 已把该模式语言化：实现 `[Symbol.iterator]` 即可被 `for...of` 与扩展运算符消费。

```js
class Range {
  constructor(start, end) {
    this.start = start;
    this.end = end;
  }

  [Symbol.iterator]() {
    let current = this.start;
    const end = this.end;

    return {
      // 迭代器协议：next() 返回 { value, done }
      next() {
        if (current <= end) {
          return { value: current++, done: false };
        }
        return { done: true };
      }
    };
  }
}

const range = new Range(1, 5);
for (let num of range) {
  console.log(num); // 1 2 3 4 5
}
console.log([...range]); // [1, 2, 3, 4, 5]
```

## 职责链模式（Chain of Responsibility）

多个处理器串成链，请求沿链传递，每个处理器处理或放行，发送者无需关心谁处理。

```js
// 处理器基类：持有下一环节
class Handler {
  constructor() {
    this.nextHandler = null;
  }

  setNext(handler) {
    this.nextHandler = handler;
    return handler; // 返回下一环节，支持链式搭建
  }

  handle(request) {
    if (this.nextHandler) {
      return this.nextHandler.handle(request);
    }
    return null;
  }
}

// 具体处理器：校验失败即拦截，通过则 super.handle() 传给下一环节
class AuthHandler extends Handler {
  handle(request) {
    if (!request.isAuthenticated) {
      console.log('认证失败');
      return false;
    }
    console.log('认证通过');
    return super.handle(request);
  }
}

class ValidationHandler extends Handler {
  handle(request) {
    if (!request.isValid) {
      console.log('验证失败');
      return false;
    }
    console.log('验证通过');
    return super.handle(request);
  }
}

class ProcessHandler extends Handler {
  handle(request) {
    console.log('处理请求');
    return true;
  }
}

// 搭建链条：认证 → 验证 → 处理
const auth = new AuthHandler();
const validation = new ValidationHandler();
const process = new ProcessHandler();
auth.setNext(validation).setNext(process);

auth.handle({ isAuthenticated: true, isValid: true });
// 认证通过
// 验证通过
// 处理请求
```

## 模板方法模式（Template Method）

父类定义算法骨架（步骤顺序固定），子类实现具体步骤；钩子方法让子类控制可选环节。

```js
// 抽象类：prepare 是模板方法，固定流程
class Beverage {
  prepare() {
    this.boilWater();
    this.brew();
    this.pourInCup();
    if (this.customerWantsCondiments()) { // 钩子：子类可改变流程
      this.addCondiments();
    }
  }

  boilWater() {
    console.log('煮沸水');
  }

  // 以下步骤延迟到子类实现
  brew()        { throw new Error('子类必须实现 brew 方法'); }
  pourInCup()   { throw new Error('子类必须实现 pourInCup 方法'); }
  addCondiments() { throw new Error('子类必须实现 addCondiments 方法'); }

  // 钩子方法：默认加调料
  customerWantsCondiments() {
    return true;
  }
}

class Coffee extends Beverage {
  brew()          { console.log('用沸水冲泡咖啡'); }
  pourInCup()     { console.log('把咖啡倒进杯子'); }
  addCondiments() { console.log('加糖和牛奶'); }
}

class Tea extends Beverage {
  brew()          { console.log('用沸水浸泡茶叶'); }
  pourInCup()     { console.log('把茶倒进杯子'); }
  addCondiments() { console.log('加柠檬'); }
  customerWantsCondiments() {
    return false; // 钩子覆写：茶不加调料
  }
}

new Coffee().prepare();
// 煮沸水
// 用沸水冲泡咖啡
// 把咖啡倒进杯子
// 加糖和牛奶

new Tea().prepare();
// 煮沸水
// 用沸水浸泡茶叶
// 把茶倒进杯子
```

## 模式选择速查

| 场景 | 推荐模式 |
|------|---------|
| 状态变化通知一组对象 | 观察者 |
| 跨模块解耦通信 | 发布-订阅 |
| 替换大量 if/else 分支 | 策略 |
| 请求参数化、撤销/重做 | 命令 |
| 顺序遍历自定义集合 | 迭代器（Symbol.iterator） |
| 多级拦截校验（中间件） | 职责链 |
| 流程固定、步骤可变 | 模板方法 |

## 实践要点

- 观察者 vs 发布-订阅一句话：有没有中间人；跨模块通信用后者，同族对象通信用前者
- 策略模式的 JS 惯用形态是「策略对象 + 函数值」，比类族更轻
- 职责链是 Express/Koa 中间件、axios 拦截器的底层思想，链上「处理 or 放行」二选一
- 模板方法与策略都封装算法：模板方法用继承固定骨架，策略用组合替换整个算法
