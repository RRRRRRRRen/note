# 提示词工程：参数、要素与技巧

*类型：knowledge ｜ 难度：入门 ｜ 标签：提示词工程、大模型、采样参数、Few-shot*

**写好提示词 = 调对参数 + 写全要素 + 用对技巧。参数侧：Temperature 管随机性、Top-p 管选词范围、惩罚项管重复；结构侧：一条合格提示词要包含指令、上下文、输入、输出要求四要素；技巧侧：指令具体、分隔清晰、指定格式、设角色、给示例、分步思考，最后靠小步迭代逼近最优。**

## 模型参数控制

### Temperature（温度）

- 作用：控制输出的「随机性」。
- 低（如 0.1）：更确定、保守，总选最可能的词，回答更一致、易重复。
- 高（如 1.0 或更高）：更随机、有创意，可能出新意，也可能胡说。
- 简单记：温度越低越「死板」，越高越「放飞」。

### Top-p（nucleus sampling）

- 作用：动态选择「靠谱」的词。设为 0.9 时，模型只从累计概率前 90% 的词里挑，忽略太离谱的。
- 与 Temperature 配合：Top-p 控制「选词范围」，Temperature 控制「在这个范围内怎么挑」。
- 简单记：Top-p 是「只考虑比较合理的选项」。

### Max Length（最大长度）

- 作用：限制回答最多多少个 token（字或词的单位）。
- 太短会截断；太长可能啰嗦或超预算。
- 简单记：「最多说这么多字」。

### Stop Sequences（停止序列）

- 作用：遇到指定文字就立刻停止生成。
- 例：设为 `"\n\n"`，生成两个换行就停；设为 `"。"` 就在句号后停。
- 简单记：「看到这几个字就闭嘴」。

### Frequency Penalty（频率惩罚）

- 作用：惩罚**重复出现**的词，值越高越不会反复用同一个词。
- 简单记：「别老说同一个词」。

### Presence Penalty（存在惩罚）

- 作用：惩罚**已经出现过**的词（不管几次），值越高越倾向用新词，内容更多样。
- 简单记：「别炒冷饭，说点新的」。

两者对比：Frequency Penalty 是「说了 'AI' 5 次？罚」；Presence Penalty 是「只要说过 'AI'，再说就罚」。

## 提示词要素

### 指令（Instruction）

明确告诉模型你要它**做什么**。

- 例：「总结以下文章」「翻译成法语」「写一首关于春天的诗」。
- 避免模糊：「说点什么」改为「用 100 字介绍量子计算」。

### 上下文（Context）

可选但推荐。提供背景信息，帮助模型理解场景或角色。

- 例：「你是一位营养师」「这是用户反馈邮件」。

### 输入内容（Input Data）

你要处理的具体文本、问题或数据。

- 例：「原文：人工智能正在改变教育……」

### 输出要求（Output Specification）

指定格式、长度、语气或风格。

- 例：「用列表形式回答」「不超过 50 字」「语气正式」「返回 JSON 格式」。

### 完整示例

```text
指令：总结以下文章
上下文：你是一名科技编辑
输入：近年来，大语言模型在医疗、金融等领域广泛应用……
输出要求：用 3 句话以内，语言简洁专业
```

## 提示词通用技巧

### 指令明确具体

- 模糊：「讲讲 AI。」
- 具体：「用 300 字简述生成式 AI 在医疗诊断中的三个应用。」
- 越具体，输出越可控。

### 用分隔符划分内容

用 `---`、`"""`、`###` 等分隔指令、上下文和输入，避免混淆。

```text
请将以下用户评论分类为正面或负面：
---
评论：这个产品太差了，根本没法用。
```

### 指定输出格式

明确要求列表、JSON、表格、段落等格式，省去后期处理。

- 例：「以 JSON 格式返回，字段包括：title, summary, keywords。」

### 设定角色（Role Prompting）

让模型「扮演」专家角色，提升专业性。

- 例：「你是一位资深 Python 工程师，请解释 async/await 的原理。」
- 角色 = 语气 + 知识视角的双重引导。

### 提供示例（Few-shot Prompting）

给 1～3 个输入-输出样例，示范想要的模式。「看例子学」是模型最擅长的方式之一。

```text
示例：
输入：苹果 → 输出：水果
输入：胡萝卜 → 输出：蔬菜

现在请回答：
输入：鸡肉 → 输出：
```

### 引导分步思考（Chain-of-Thought）

对复杂问题，加一句「请一步步推理」或「先分析再回答」，显著提升逻辑类任务的准确率。

- 例：「小明有 10 元，买 3 元饮料后还剩多少？请逐步计算。」

### 控制长度与重点

用「不超过 XX 字」「聚焦于 XX 方面」等限制，避免啰嗦或跑题。

- 例：「用一句话总结，重点突出技术优势。」

### 迭代优化，小步测试

不要指望一次写完美：先写基础版 → 看输出问题 → 调整措辞/加约束 → 再试。好提示是改出来的，不是想出来的。
