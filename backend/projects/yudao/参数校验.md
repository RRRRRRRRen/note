# 参数校验

*类型：practice ｜ 难度：进阶 ｜ 标签：yudao、Bean Validation、@Validated、自定义校验*

**yudao 的参数校验基于 Bean Validation（JSR-303/380）：`@Validated`（Spring 扩展）负责方法级与分组校验，`@Valid`（标准规范）负责嵌套对象级联校验，两者配合常用约束注解覆盖绝大多数场景，复杂规则通过自定义注解 + `ConstraintValidator` 扩展。校验失败统一交给 `@RestControllerAdvice` 转换为标准错误响应。**

## 深入理解 @Validated 和 @Valid

### 基本概念与来源

- `@Valid` 来自 Java Bean Validation 规范（JSR-303 / JSR-380），包路径为 Java EE 的 `javax.validation.Valid` 或 Jakarta EE 9+ 的 `jakarta.validation.Valid`。
- `@Validated` 来自 Spring Framework，包路径为 `org.springframework.validation.annotation.Validated`，是对 `@Valid` 的增强封装。

### 核心区别

| 特性 | @Valid | @Validated |
| --- | --- | --- |
| 来源 | JSR-303/380 标准 | Spring 扩展 |
| 分组校验 | 不支持 | 支持（通过 `groups` 属性） |
| 嵌套/级联校验 | 支持（标注在字段上） | 不支持 |
| 作用位置 | 方法参数、字段、方法返回值 | 类、方法参数 |
| 方法级别校验 | 不支持 | 支持（标注在类上，配合 AOP） |

### 作用机制

`@Validated`：

- 标注在 Controller 方法参数上时，由 Spring MVC 的 `HandlerMethodArgumentResolver` 处理，触发 Bean Validation 校验请求参数，失败抛出 `MethodArgumentNotValidException`。
- 标注在类上时，Spring 通过 `MethodValidationPostProcessor` 创建 AOP 代理，拦截方法调用并对参数/返回值执行校验，失败抛出 `ConstraintViolationException`。

```java
@Service
@Validated  // 开启该 Bean 的方法级别校验
public class UserService {

    // 方法执行前，Spring AOP 会自动校验参数
    public void createUser(@NotBlank String name, @Min(18) int age) {
        // ...
    }
}
```

`@Valid` 触发标准 Bean Validation，核心用途是级联校验：对象包含嵌套对象时，需在嵌套字段上加 `@Valid` 才能触发对嵌套对象内部字段的校验：

```java
public class OrderDTO {

    @NotNull
    @Valid  // 触发对 AddressDTO 内部字段的校验
    private AddressDTO address;
}

public class AddressDTO {

    @NotBlank
    private String city;

    @NotBlank
    private String street;
}
```

### 能否相互替代

在 Spring MVC Controller 方法参数校验场景中两者基本可以互换：

```java
// 以下两种写法效果相同（不涉及分组和级联）
public Result create(@Valid @RequestBody UserDTO dto) { ... }
public Result create(@Validated @RequestBody UserDTO dto) { ... }
```

不可替代的场景：

- 需要分组校验：必须用 `@Validated(Group.class)`。
- 需要级联校验（嵌套对象）：必须用 `@Valid`。
- 需要 Service 层方法校验：类上必须用 `@Validated`。

## 如何在 Spring Boot 中启用参数校验

添加依赖：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

在 Controller 中使用：

```java
@RestController
@Validated  // 开启路径变量、请求参数的方法级校验
@RequestMapping("/users")
public class UserController {

    @PostMapping
    public Result create(@Validated @RequestBody UserDTO dto) {
        return Result.ok();
    }

    @GetMapping("/{id}")
    public Result get(@PathVariable @Min(1) Long id) {
        return Result.ok();
    }
}
```

统一异常处理：两类校验失败对应两种异常，分别处理：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 处理 @RequestBody 校验失败（MethodArgumentNotValidException）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result handleValidException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining(", "));
        return Result.fail(message);
    }

    // 处理路径变量、请求参数校验失败（ConstraintViolationException）
    @ExceptionHandler(ConstraintViolationException.class)
    public Result handleConstraintException(ConstraintViolationException e) {
        String message = e.getConstraintViolations().stream()
            .map(ConstraintViolation::getMessage)
            .collect(Collectors.joining(", "));
        return Result.fail(message);
    }
}
```

## 常见的参数校验注解

以下注解来自 `javax.validation.constraints`（Java EE）或 `jakarta.validation.constraints`（Jakarta EE 9+），适用于 Spring Boot 项目中的 DTO、实体类等字段校验。

### 空值校验

| 注解 | 要求 | 备注 |
| --- | --- | --- |
| `@Null` | 必须为 `null` | 常用于“禁用”某些字段 |
| `@NotNull` | 不能为 `null` | 注意：允许空字符串 `""` |
| `@NotEmpty` | 非 null 且长度/大小 > 0 | 适用于 String、Collection、Map、Array |
| `@NotBlank` | 仅用于 CharSequence | 非 null 且 trim 后长度 > 0，`"   "` 会被拒绝 |

推荐：字符串校验优先用 `@NotBlank`，集合用 `@NotEmpty`。

### 长度与大小校验

`@Size(min = x, max = y)`：校验元素的长度或大小。String 校验字符长度，Collection/Map/Array 校验元素个数。如 `@Size(max = 50)` 表示最多 50 个字符或元素。

### 数值范围校验

| 注解 | 含义 |
| --- | --- |
| `@Min(value = x)` | 数值 ≥ x（支持 int、long、BigDecimal、BigInteger 等） |
| `@Max(value = x)` | 数值 ≤ x |
| `@DecimalMin(value = "x")` | 数值 ≥ x，字符串形式指定避免精度丢失，`inclusive = false` 表示 > x |
| `@DecimalMax(value = "x")` | 数值 ≤ x，同上 |
| `@Positive` / `@PositiveOrZero` | > 0 / ≥ 0 |
| `@Negative` / `@NegativeOrZero` | < 0 / ≤ 0 |

### 正则与日期校验

`@Pattern(regexp = "正则表达式")`：要求字符串匹配指定正则：

```java
// 邮箱格式校验
@Pattern(regexp = "^[\\w.-]+@[\\w.-]+\\.[a-zA-Z]{2,}$")
private String email;
```

日期时间校验：`@Past`（过去）、`@PastOrPresent`（过去或现在）、`@Future`（将来）、`@FutureOrPresent`（将来或现在）。支持 `java.util.Date`、`LocalDate`、`LocalDateTime`、`Instant` 等类型。

### 其他常用注解

- `@Email`：简单校验电子邮件格式（宽松规则），严格校验建议配合 `@Pattern`。
- `@AssertTrue`：要求 boolean 方法或字段返回 `true`，常用于自定义逻辑校验。
- `@AssertFalse`：要求结果为 false（较少用）。
- `@Digits(integer = x, fraction = y)`：整数部分最多 x 位、小数部分最多 y 位（JSR-380 新增）。

Hibernate Validator 扩展（非 JSR 标准，Spring Boot 默认集成可安全使用）：

- `@URL`：校验合法 URL。
- `@CreditCardNumber`：Luhn 算法校验信用卡号。
- `@Length`：类似 `@Size`，仅用于字符串，语义更清晰。
- `@Range`：整合 `@Min` + `@Max`。

`@AssertTrue` 自定义逻辑校验示例：

```java
// 起止时间的跨字段校验：只能写在校验模型内部
@AssertTrue(message = "起始时间必须早于结束时间")
public boolean isTimeRangeValid() {
    return startTime == null || endTime == null || startTime.isBefore(endTime);
}
```

### 使用建议

- 基础校验优先使用标准 JSR 注解（`@NotBlank`、`@Size`、`@Email` 等）。
- 复杂逻辑结合 `@AssertTrue` 或自定义约束（`@Constraint`）。
- 分组校验配合 `groups` 属性实现不同场景（如创建/更新）的差异化校验。
- 嵌套对象别忘了在字段上加 `@Valid` 触发级联校验。

## 如何自定义校验注解

自定义校验注解需要两步：定义注解 + 实现校验器。

### 定义注解

```java
@Documented
@Constraint(validatedBy = PhoneValidator.class)  // 指定校验器
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
public @interface Phone {

    String message() default "手机号格式不正确";  // 默认错误信息

    Class<?>[] groups() default {};  // 分组校验（必须有）

    Class<? extends Payload>[] payload() default {};  // 负载（必须有）
}
```

### 实现校验器

```java
public class PhoneValidator implements ConstraintValidator<Phone, String> {

    private static final Pattern PHONE_PATTERN = Pattern.compile("^1[3-9]\\d{9}$");

    @Override
    public void initialize(Phone annotation) {
        // 可从注解中读取配置参数
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        // null 值由 @NotNull 处理，这里允许 null 通过
        if (value == null) {
            return true;
        }
        return PHONE_PATTERN.matcher(value).matches();
    }
}
```

### 使用自定义注解

```java
public class UserDTO {

    @NotBlank(message = "手机号不能为空")
    @Phone  // 使用自定义注解
    private String phone;
}
```

### 带参数的自定义注解

注解中声明自定义参数（如允许的枚举值列表）：

```java
@Documented
@Constraint(validatedBy = EnumValueValidator.class)
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
public @interface EnumValue {

    String message() default "枚举值不合法";

    Class<?>[] groups() default {};

    Class<? extends Payload>[] payload() default {};

    int[] values();  // 自定义参数：允许的枚举值列表
}
```

校验器在 `initialize` 中读取注解参数：

```java
public class EnumValueValidator implements ConstraintValidator<EnumValue, Integer> {

    private Set<Integer> allowedValues;

    @Override
    public void initialize(EnumValue annotation) {
        // 从注解中读取允许的枚举值
        allowedValues = Arrays.stream(annotation.values())
            .boxed()
            .collect(Collectors.toSet());
    }

    @Override
    public boolean isValid(Integer value, ConstraintValidatorContext context) {
        return value == null || allowedValues.contains(value);
    }
}
```

使用示例：

```java
public class ProductDTO {

    @EnumValue(values = {1, 2, 3}, message = "商品状态只能是 1、2、3")
    private Integer status;
}
```

### 最佳实践小结

- Controller 方法参数（`@RequestBody`）：使用 `@Validated`。
- 嵌套对象级联校验：在嵌套字段上使用 `@Valid`。
- Service 层方法参数校验：类上加 `@Validated`，参数上加具体约束注解。
- 分组校验：定义 `interface Create {}` / `interface Update {}` 分组，配合 `@Validated(Create.class)` 使用。
- 统一在 `@RestControllerAdvice` 中处理校验异常，返回统一格式。
