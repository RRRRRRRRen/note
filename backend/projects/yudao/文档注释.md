# 文档注释

*类型：knowledge ｜ 难度：入门 ｜ 标签：yudao、Javadoc、注释规范、文档*

**yudao 项目的文档注释以 Javadoc 为核心约定：公共类和方法必须用 `/** */` 说明「行为契约」，参数、返回值、异常分别用 `@param`、`@return`、`@throws` 标注。该主题的专题源码笔记暂为空，本篇梳理文档注释在项目中的定位与基本规范，详细标签用法见「Java 约定与习惯」篇。**

## 文档注释在项目中的定位

- Javadoc 是 Java 官方的文档注释标准：编译器忽略其内容，但 `javadoc` 工具可以扫描源码中的 `/** */` 注释生成 HTML API 文档。
- IDE 的悬浮提示（hover）直接读取 Javadoc，写好的注释就是团队成员的即时文档。
- yudao 这类多人协作、模块众多的项目，公共 API（Service 接口、工具类、VO 字段）的 Javadoc 是理解业务语义的第一入口。

```java
/**
 * 用户服务，封装用户查询与创建逻辑。
 * <p>
 * 以「行为契约」描述为主：说明方法做什么、有什么前置条件、
 * 抛什么异常，而不是写实现细节。
 *
 * @author ren
 * @since 1.0.0
 */
public interface UserService {

    /**
     * 根据用户 ID 查询用户。
     *
     * @param id 用户 ID，必须大于 0
     * @return 用户对象；不存在时返回 {@code null}
     * @throws IllegalArgumentException 当 id 小于等于 0 时抛出
     */
    User findById(long id);
}
```

## 基本规范

### 必须写注释的位置

- 公共类与接口：说明职责与使用场景。
- 公共方法：说明行为、参数含义、返回值语义（尤其 null 语义）、异常条件。
- VO/DTO 的字段：用单行 `/** */` 说明业务含义，前端联调时字段名不表意的情况很常见。

### 常用标签速记

| 标签 | 用途 |
| --- | --- |
| `@param` | 参数说明，一个参数一条 |
| `@return` | 返回值说明，含 null 语义 |
| `@throws` | 异常说明及触发条件 |
| `@see` | 关联引用 |
| `{@link ...}` | 内联链接到其他类/方法 |
| `{@code ...}` | 内联代码，避免 HTML 转义问题 |
| `@deprecated` | 废弃声明，必须说明替代方案 |
| `@since` / `@author` / `@version` | 版本与作者元信息 |

### 项目约定

- 公共 API 必须补齐 `@param`、`@return`、`@throws`。
- 废弃 API 必须说明替代方案和迁移方向。
- 以「行为契约」描述为主，不写实现细节——实现细节放代码注释 `//` 里。
- HTML 标签（`<p>`、`<ul>`、`<pre>`）可用于结构化长描述，配合 `{@code}`、`{@link}` 提升可读性。

## 与其他注释的分工

- 文档注释 `/** */`：面向使用者的 API 契约，可生成文档。
- 行内注释 `//`：面向维护者的实现说明，解释「为什么这么写」。
- 不要用注释复述代码（`// 获取用户` 紧跟 `getUser()`），要写代码表达不出来的信息。

## 文档生成

```bash
# 扫描源码中的 /** */ 注释并生成 HTML 文档到 docs 目录
javadoc -d docs src/com/example/*.java
```
