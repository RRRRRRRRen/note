# 对象构造
*类型：knowledge ｜ 难度：入门 ｜ 标签：Java、构造器、重载、初始化块、finalize ｜ 更新：2026-09-22*

**构造器核心规则：重载由「方法名 + 参数类型」签名区分（返回类型不算）；仅当类没有任何构造器时才有默认无参构造器；`this(...)` 可调用同类另一个构造器且必须是第一条语句；实例初始化块先于构造器执行，静态初始化块类加载时只执行一次；finalize 不保证执行，不可依赖。**

## 重载

- 多个方法（或构造器）同名但参数不同，便形成重载
- 重载解析：编译器用各方法首部的参数类型与调用值的类型进行匹配选出正确方法，匹配失败产生编译时错误

注意：

- Java 允许重载任何方法，不只是构造器
- 方法的签名 = 方法名 + 参数类型；返回类型不是签名的一部分
- 两个方法名字相同、参数类型相同、仅返回类型不同，不构成重载，Java 不允许出现

## 默认字段初始化

构造器中没有显式赋值的字段会自动设为默认值：

| 数据类型 | 默认值 |
| --- | --- |
| byte / short / int | 0 |
| long | 0L |
| float | 0.0f |
| double | 0.0d |
| char | `'\u0000'`（空字符） |
| boolean | false |
| 引用类型（对象、数组等） | null |

- 局部变量没有默认值，必须初始化后才能使用

## 无参构造器

- 类没有任何构造器时，系统提供一个无参构造器，将所有实例字段设为默认值
- 类中提供了至少一个构造器但没有无参构造器时，构造对象必须传参，`new X()` 不合法
- 仅当类没有其他构造器时才存在默认的无参构造器

## 显式字段初始化

- 无论调用哪个构造器，每个实例字段都应设置为一个有意义的初始值
- 可以在字段声明处直接赋值，该赋值会先于构造器体执行：

```java
private String name = "";
```

## 参数名与 this

this 指示隐式参数（当前对象），因此参数名可以与实例字段同名，用 this 区分：

```java
public Employee(String name, double salary) {
    this.name = name;
    this.salary = salary;
}
```

## 调用另一个构造器

构造器第一条语句形如 `this(...)` 时，将调用同一个类的另一个构造器：

```java
class Person {
    String name;
    int age;

    // 构造器1：委托给构造器2
    public Person() {
        this("未知", 0); // 调用构造器2，必须是第一条语句
        System.out.println("无参构造器被调用");
    }

    // 构造器2：带参数的构造器
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("带参数构造器被调用，name: " + name + ", age: " + age);
    }
}
```

## 初始化块

初始化块是对象创建时执行额外初始化逻辑的代码块，分实例初始化块与静态初始化块。

实例初始化块：直接写在类中的 `{}`，每次创建对象都执行，且先于构造器体，适合多个构造器共用初始化逻辑：

```java
class Example {
    int a;

    // 实例初始化块
    {
        a = 10;
        System.out.println("实例初始化块执行，a = " + a);
    }

    public Example() {
        System.out.println("构造器执行");
    }
}
```

输出顺序为「实例初始化块 -> 构造器」，每个新对象都重复一次。

静态初始化块：`static {}`，类加载时执行一次（第一次使用该类时），适合静态变量初始化、加载配置等只需一次的逻辑：

```java
class StaticExample {
    static int x;

    // 静态初始化块
    static {
        x = 100;
        System.out.println("静态初始化块执行，x = " + x);
    }
}
```

两种块对比：

| 类型 | 关键字 | 执行时机 | 特点 |
| --- | --- | --- | --- |
| 实例初始化块 | `{}` | 创建对象时执行（每次都执行） | 先于构造器，适合多构造器共享初始化代码 |
| 静态初始化块 | `static {}` | 类加载时执行一次 | 适合静态变量与只需执行一次的逻辑 |

## 对象析构与 finalize

- Java 没有类似 C++ 的显式析构函数，对象销毁依赖垃圾回收机制（GC）：没有任何引用指向的对象被视为不可达，最终由 GC 回收
- 每个对象的 finalize() 方法在 GC 回收前**可能**被调用一次，但不保证一定执行、执行时间也不确定，不适合用于关键资源释放：

```java
class Example {
    @Override
    protected void finalize() {
        System.out.println("对象被回收");
    }

    public static void main(String[] args) {
        Example obj = new Example();
        obj = null;  // 移除引用，对象变成可回收的垃圾
        System.gc(); // 只是建议 JVM 运行 GC，不保证立即执行
        System.out.println("程序结束");
    }
}
```

- 关键资源（文件、连接等）应使用 try-with-resources 显式关闭，而不是依赖 finalize
