# 类设计技巧

*类型：knowledge ｜ 难度：入门 ｜ 标签：Java、类设计、封装、最佳实践 ｜ 更新：2026-09-22*

**类设计七条军规：数据私有、数据初始化、少用基本类型做字段、不必每个字段都有 getter/setter、职责过多就拆分、命名体现职责、优先不可变类。**

## 七条技巧

- 一定要保证数据私有：私有字段 + 访问器/更改器，破坏封装迟早会付出代价
- 一定要初始化数据：不要依赖默认值，显式初始化（构造器、初始化块或声明处）确保字段有意义
- 不要在类中使用过多的基本类型：相关的多个基本类型字段应合并成一个类（如 Address 替代 street/city/state 三个字段），更易理解和修改
- 不是所有字段都需要单独的 get 和 set：按需提供，避免无意义的接口暴露
- 分解有过多职责的类：一个类职责过多就拆成多个类（如拆出 Address 类）
- 类名和方法名要能体现它们的职责：类名用名词（Order、Invoice），方法名用动词（deposit、cancel），命名让代码自解释
- 优先使用不可变的类：不可变对象线程安全、可共享，能不提供更改器就不提供；字段设为 final，需要变化时返回新对象

## 示例：用类替代基本类型堆砌

```java
// 反例：字段全是零散的基本类型
class Customer {
    private String street;
    private String city;
    private String state;
}

// 正例：地址收拢为独立的 Address 类
class Customer {
    private Address homeAddress;
}
```
