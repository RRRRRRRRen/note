# 容器注册

*类型：knowledge ｜ 难度：基础 ｜ 标签：Spring、IoC、@Bean、@Configuration、@ComponentScan*

**向 Spring 容器注册组件有两条路线：`@Component` + `@ComponentScan` 靠类扫描自动发现，适合自己写的业务类；`@Configuration` + `@Bean` 显式声明，适合第三方库和需要复杂初始化逻辑的对象。注册之后用 `getBean()` 从容器获取，注意组件名字全局唯一、单例默认饿汉创建这两条规则。**

## @Bean 注解

`@Bean` 通常用在 `@Configuration` 类中，将方法返回的对象注册为 Bean，是替代 XML `<bean>` 的 Java Config 核心注解。

```java
@Configuration
public class AppConfig {
    @Bean // 方法名默认作为 Bean 的名称，可用 @Bean(name = "myService") 自定义
    public UserService userService() {
        return new UserServiceImpl();
    }

    @Bean
    public UserService userService(UserRepository userRepository) { // 参数自动注入其他 Bean
        return new UserServiceImpl(userRepository);
    }
}
```

高级特性：

```java
// 生命周期回调：适合第三方库对象
@Bean(initMethod = "connect", destroyMethod = "disconnect")
public DataSource dataSource() {
    return new HikariDataSource();
}

// 条件化注册：配置满足时才创建
@Bean
@ConditionalOnProperty(name = "cache.enabled", havingValue = "true")
public CacheManager cacheManager() {
    return new RedisCacheManager();
}

// 多例：每次请求新实例
@Bean
@Scope("prototype")
public TaskExecutor taskExecutor() {
    return new ThreadPoolTaskExecutor();
}
```

使用场景：

- **注册第三方库组件**：无法修改源码的类，如 `RestTemplate`、数据库连接池。
- **复杂对象初始化**：需要自定义配置的 Bean。

```java
@Bean
public DataSource dataSource() {
    HikariConfig config = new HikariConfig();
    config.setJdbcUrl("jdbc:mysql://localhost:3306/mydb");
    config.setUsername("root");
    config.setPassword("123456");
    return new HikariDataSource(config);
}
```

方法调用陷阱：在同一个 `@Configuration` 类中直接调用 `@Bean` 方法，会绕过 Spring 代理导致单例失效，正确做法是通过参数注入依赖。

```java
// 【反例】直接调用方法，new 的是新对象而非容器中的单例
@Bean
public B b() {
    return new B(a());
}

// 【正解】Spring 自动注入 A
@Bean
public B b(A a) {
    return new B(a);
}
```

`@Bean` 与 `@Component` 的选择：

| 特性 | @Bean | @Component |
| --- | --- | --- |
| 控制粒度 | 方法级别，精确控制实例化逻辑 | 类级别，自动扫描 |
| 适用场景 | 第三方库、复杂对象 | 自定义业务类（Service、Repository） |
| 灵活性 | 高（可编程式配置） | 低（依赖注解声明） |

## @Configuration 注解

标记类为 Spring 配置类，替代 XML 配置文件，通常与 `@Bean` 配合使用。

- **类型安全**：编译时检查，支持 IDE 自动补全和重构。
- **本身也是 `@Component`**：配置类自身被容器管理，可注入其他 Bean。

### CGLIB 代理机制

`@Configuration` 类在运行时被 CGLIB 动态代理，确保跨 `@Bean` 方法调用返回的是容器中的单例：

```java
@Configuration
public class AppConfig {
    @Bean
    public A a() {
        return new A(b()); // b() 被代理拦截，返回的是容器中的单例 B
    }

    @Bean
    public B b() {
        return new B();
    }
}
```

- 如果换成 `@Component`，`a()` 直接调用 `b()` 会创建新的 `B` 实例（非单例）。
- Spring 5.2+ 可用 `@Configuration(proxyBeanMethods = false)` 关闭代理提升性能，适用于无跨 `@Bean` 方法调用的场景。

### 与其他注解的配合

```java
// @ComponentScan：自动扫描指定包下的 @Component 类（等效 <context:component-scan>）
@Configuration
@ComponentScan("com.example")
public class AppConfig {}

// @Import：引入其他配置类，模块化配置
@Configuration
@Import({DatabaseConfig.class, SecurityConfig.class})
public class AppConfig {}

// @PropertySource：加载外部配置文件
@Configuration
@PropertySource("classpath:application.properties")
public class AppConfig {
    @Value("${db.url}")
    private String dbUrl;
}

// @Profile：按环境区分 Bean
@Bean
@Profile("dev")
public DataSource devDataSource() {
    return new EmbeddedDatabaseBuilder().setType(H2).build();
}
```

## @ComponentScan 注解

自动扫描并注册 `@Component`、`@Service`、`@Repository`、`@Controller` 标记的类。

- 不指定包路径时，默认扫描**当前配置类所在包及其子包**。
- `@SpringBootApplication` 已包含 `@ComponentScan`，默认扫描主类所在包及其子包。
- 支持多包路径：`@ComponentScan({"com.example.service", "com.example.dao"})`。
- 支持过滤：`includeFilters` / `excludeFilters`，过滤类型有 `ANNOTATION`（按注解）、`ASSIGNABLE_TYPE`（按类）、`REGEX`（按正则）、`CUSTOM`（自定义 `TypeFilter`）。

```java
@Configuration
@ComponentScan(
    basePackages = "com.example",
    includeFilters = @ComponentScan.Filter(type = FilterType.ANNOTATION, classes = Service.class),
    excludeFilters = @ComponentScan.Filter(type = FilterType.REGEX, pattern = ".*Test.*")
)
public class AppConfig {}
```

注意事项：

- 多个配置类扫描同一包可能导致 Bean 重复注册；显式配置（`@Bean`）优先于自动扫描。
- 扫描路径应尽量精确，避免不必要的类扫描开销。

## @Import 注解

显式、精确地导入配置类或组件，与 `@ComponentScan` 的模糊包扫描相对。

- **导入配置类**：`@Import({DatabaseConfig.class})`，模块化整合配置。
- **导入普通类**：无 Spring 注解的类直接注册为 Bean。
- **条件化加载**：结合 `@Conditional`，条件满足时才加载导入的配置。

```java
// 动态导入：编程式选择要导入的配置，Spring Boot 自动配置的底层机制
public class MyImportSelector implements ImportSelector {
    @Override
    public String[] selectImports(AnnotationMetadata metadata) {
        // 根据条件返回要导入的配置类全限定名
        return new String[]{"com.example.ConfigA", "com.example.ConfigB"};
    }
}

@Configuration
@Import(MyImportSelector.class)
public class AppConfig {}
```

注意事项：避免循环导入（A 导 B、B 导 A 会启动失败）；导入 Bean 的默认名称为类的全限定名。

## getBean 获取组件

```java
// 开启 Spring 应用上下文（即 IoC 容器）
ConfigurableApplicationContext ioc = SpringApplication.run(SpringIocApplication.class, args);

// 查看容器中所有组件名（容器自带很多内置组件）
String[] names = ioc.getBeanDefinitionNames();

// 通过名字获取（需强转）
Person person1 = (Person) ioc.getBean("person");

// 通过类型获取
Person person2 = ioc.getBean(Person.class);

// 通过名字 + 类型获取
Person person3 = ioc.getBean("person", Person.class);

// 通过类型获取组件集合，key 为 Bean 名字
Map<String, Dog> type = ioc.getBeansOfType(Dog.class);
```

获取组件的各种情况：

- 组件不存在：抛出异常。
- 组件不唯一：按名字获取返回最先声明的那个；按类型获取抛出异常；可用 `List` 集合正常获取。
- 组件唯一：返回该对象。

组件对象的创建特征：

- **单实例**：重复获取返回同一个对象。
- **创建时机**：容器启动过程中即完成实例化（饿汉），并非获取时才创建。

## @Scope 作用域

决定容器如何创建和管理 Bean 实例。

| 作用域 | 描述 | 适用场景 |
| --- | --- | --- |
| `singleton` | 默认，容器中仅一个共享实例 | 无状态工具类、Service、DAO |
| `prototype` | 每次请求都创建新实例 | 有状态 Bean、线程不安全对象 |
| `request` | 每个 HTTP 请求一个实例（Web） | 请求相关数据 |
| `session` | 每个会话一个实例（Web） | 购物车、用户个性化设置 |
| `application` | 整个 Web 应用共享一个实例 | 全局缓存、应用级配置 |
| `websocket` | 每个 WebSocket 会话一个实例 | 实时通信场景 |

```java
@Component
@Scope("prototype") // 或 @Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)
public class ShoppingCart {}
```

关键注意点：

- **单例的线程安全**：单例被所有线程共享，含可变成员变量时需自行保证线程安全（无状态设计、`ThreadLocal`、同步机制）。
- **原型不管理销毁**：Spring 不管理原型 Bean 的生命周期，`@PreDestroy` 不会触发，资源需手动释放。

## @Lazy 延迟初始化

推迟 Bean 的创建时机到首次被真正使用，可加快启动速度、打破循环依赖。

```java
// 标注在 Bean 定义上
@Component
@Lazy
public class HeavyResourceService {}

// 标注在注入点上：即使 Bean 本身未标 @Lazy，也延迟注入
@Service
public class UserService {
    @Autowired
    @Lazy
    private HeavyResourceService heavyResourceService;
}

// 解决循环依赖：注入代理而非真实 Bean
@Service
public class ServiceA {
    private final ServiceB serviceB;

    public ServiceA(@Lazy ServiceB serviceB) { // 延迟注入
        this.serviceB = serviceB;
    }
}
```

原理与注意点：

- **代理机制**：延迟 Bean 被 CGLIB 代理包裹，首次调用方法时才初始化真实对象（打印会显示 `$$EnhancerBySpringCGLIB$$` 代理类名）。
- 单例 Bean 延迟后仅首次创建，之后一直复用；Web 作用域默认已是懒加载。
- 适合初始化耗时的组件和可能不用的可选依赖；启动必备的核心组件、高频轻量 Bean 不适合。

## @Conditional 条件化注册

根据特定条件动态决定是否注册 Bean，是 Spring Boot 自动配置的基石。

```java
// 自定义条件：实现 Condition 接口
public class MyCustomCondition implements Condition {
    @Override
    public boolean matches(ConditionContext context, AnnotatedTypeMetadata metadata) {
        Environment env = context.getEnvironment();
        return "true".equals(env.getProperty("myfeature.enabled"));
    }
}

@Bean
@Conditional(MyCustomCondition.class) // 仅当条件满足时注册
public MyService myService() {
    return new MyService();
}
```

Spring Boot 常用衍生注解：

| 注解 | 作用 | 示例 |
| --- | --- | --- |
| `@ConditionalOnProperty` | 配置属性满足时加载 | `@ConditionalOnProperty(name = "cache.type", havingValue = "redis")` |
| `@ConditionalOnClass` | 类路径存在指定类时生效 | `@ConditionalOnClass(name = "com.example.ThirdPartyClass")` |
| `@ConditionalOnMissingBean` | 容器无此类型 Bean 时生效 | `@ConditionalOnMissingBean(type = DataSource.class)` |
| `@ConditionalOnWebApplication` | 仅 Web 环境生效 | `@ConditionalOnWebApplication(type = SERVLET)` |
| `@ConditionalOnExpression` | SpEL 表达式判断 | `@ConditionalOnExpression("${feature.enabled:false}")` |

组合使用示例：

```java
@Configuration
@ConditionalOnClass(DataSource.class)                      // 类路径检查
@ConditionalOnProperty(prefix = "spring.datasource", name = "url") // 配置检查
public class DataSourceAutoConfig {
    @Bean
    @ConditionalOnMissingBean                              // 容器中无此类型时注册
    public DataSource dataSource() {
        return new HikariDataSource();
    }
}
```

复杂逻辑可用 `AnyNestedCondition` / `AllNestedCondition` / `NoneNestedCondition` 组合条件。调试时启动加 `--debug` 参数可查看条件评估详情。

与 `@Profile` 的区别：`@Profile` 仅基于 profile 名称做环境匹配，是 `@Conditional` 的环境专用简化版；复杂条件判断用 `@Conditional`。

## @Profile 环境隔离

根据当前运行环境动态激活或禁用 Bean，常用于 dev/test/prod 差异化配置。

```java
@Configuration
public class DataSourceConfig {
    @Bean
    @Profile("dev")
    public DataSource h2DataSource() {
        // 开发环境：H2 内存数据库
        return new EmbeddedDatabaseBuilder().setType(H2).build();
    }

    @Bean
    @Profile("prod")
    public DataSource mysqlDataSource() {
        // 生产环境：MySQL
        return DataSourceBuilder.create()
            .url("jdbc:mysql://prod-server:3306/db")
            .username("admin")
            .password("123456")
            .build();
    }
}
```

激活方式：

```properties
# 配置文件（推荐）
spring.profiles.active=dev
```

```bash
# 命令行
java -jar app.jar --spring.profiles.active=prod

# 环境变量
export SPRING_PROFILES_ACTIVE=test
```

```java
// 测试场景编程式激活
@SpringBootTest
@ActiveProfiles("test")
class UserServiceTest {}
```

组合规则：

- 同时激活多个：`spring.profiles.active=dev,db-h2`。
- `@Profile({"dev", "test"})` 为 OR 关系；`@Profile("dev & db-mysql")`（Spring 5.1+）为 AND 关系。
- `@Profile("default")` 在没有激活任何 Profile 时生效；无 `@Profile` 标注的 Bean 全局生效。

## FactoryBean 接口

`FactoryBean` 是一个工厂本身，负责定制化生成最终注册的 Bean，常用于集成第三方库（如 MyBatis 的 `SqlSessionFactoryBean`）。

```java
public interface FactoryBean<T> {
    T getObject() throws Exception;  // 返回实际要注册的 Bean
    Class<?> getObjectType();        // 返回 Bean 的类型
    boolean isSingleton();           // 是否为单例
}
```

基础实现：

```java
public class ConnectionFactoryBean implements FactoryBean<Connection> {
    private String url;
    private String username;
    private String password;
    // Setter 省略

    @Override
    public Connection getObject() throws Exception {
        return DriverManager.getConnection(url, username, password);
    }

    @Override
    public Class<?> getObjectType() {
        return Connection.class;
    }

    @Override
    public boolean isSingleton() {
        return false; // 每次请求返回新连接
    }
}
```

获取时通过 `&` 前缀区分工厂与产品：

```java
Connection conn = context.getBean("connection", Connection.class);              // 获取产品
ConnectionFactoryBean factory = (ConnectionFactoryBean) context.getBean("&connection"); // 获取工厂本身
```

与普通 `@Bean` 的区别：

| 特性 | FactoryBean | 普通 @Bean |
| --- | --- | --- |
| 注册对象 | 工厂本身 + `getObject()` 返回的产品 | 直接注册方法返回的对象 |
| 获取方式 | 加 `&` 前缀获取工厂，不加获取产品 | 直接获取 Bean 实例 |
| 适用场景 | 复杂初始化、动态代理、条件化创建 | 简单直接的 Bean 创建 |
