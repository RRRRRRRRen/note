# 组件生命周期

*类型：knowledge ｜ 难度：进阶 ｜ 标签：Spring、Bean 生命周期、BeanPostProcessor、@PostConstruct*

**Spring Bean 的生命周期是一条固定流水线：实例化 → 属性注入 → 初始化（@PostConstruct → InitializingBean → init-method）→ 就绪使用 → 销毁（@PreDestroy → DisposableBean → destroy-method）。BeanPostProcessor 是包裹初始化阶段的全局拦截器，也是 Spring AOP 的底层基础。三条铁律：注解方式优先（JSR 标准、低耦合）、同类的多个回调按固定顺序执行、原型 Bean 交给调用方处理销毁。**

## 生命周期总览（单例 Bean）

```text
1. 实例化（Instantiation）：构造器或工厂方法创建实例
2. 属性赋值（Population）：注入依赖（@Autowired / @Resource）
3. 初始化前：BeanPostProcessor.postProcessBeforeInitialization()
4. 初始化：@PostConstruct → InitializingBean.afterPropertiesSet() → init-method
5. 初始化后：BeanPostProcessor.postProcessAfterInitialization()，Bean 完全就绪
6. 销毁前（容器关闭）：@PreDestroy → DisposableBean.destroy() → destroy-method
```

## @PostConstruct 与 @PreDestroy

JSR-250 标准注解，是生命周期回调的**推荐方式**：`@PostConstruct` 在 Bean 初始化后执行（数据加载、缓存预热），`@PreDestroy` 在销毁前执行（资源释放、连接关闭）。

```java
@Component
public class DatabaseService {

    @PostConstruct
    public void init() {
        System.out.println("数据库连接初始化..."); // 容器启动时调用
    }

    @PreDestroy
    public void cleanup() {
        System.out.println("释放数据库连接...");   // 容器关闭时调用
    }
}
```

技术细节：

- 方法签名：`public void` 且无参数，不能是 `static` 或 `final`，方法名任意。
- 一个类可定义多个 `@PostConstruct` 方法，但执行顺序不确定；最佳实践是每个 Bean 只定义一个。
- 继承关系中父类方法先于子类执行；子类重写父类方法时父类不会自动调用，需手动 `super.init()`。

注解不生效的排查点：

- 类未被 `@ComponentScan` 扫描或未显式配置为 `@Bean`。
- 缺少依赖：Jakarta EE 9+ 需引入 `jakarta.annotation-api`。

```xml
<dependency>
    <groupId>jakarta.annotation</groupId>
    <artifactId>jakarta.annotation-api</artifactId>
    <version>2.1.1</version>
</dependency>
```

- **原型 Bean 的 `@PreDestroy` 不生效**：Spring 不管理原型 Bean 的销毁。

## InitializingBean 与 DisposableBean 接口

Spring 原生的初始化/销毁回调接口，耦合 Spring API，适合需要强保证的场景。

```java
// 初始化回调：属性注入完成后自动调用
@Component
public class MyService implements InitializingBean {
    private String apiKey;

    @Autowired
    public void setApiKey(@Value("${app.api.key}") String apiKey) {
        this.apiKey = apiKey;
    }

    @Override
    public void afterPropertiesSet() {
        if (apiKey == null) {
            throw new IllegalStateException("API Key 未配置！"); // 属性校验
        }
    }
}
```

```java
// 销毁回调：容器关闭时执行资源清理
@Component
public class DatabaseConnection implements DisposableBean {
    private Connection conn;

    @Override
    public void destroy() throws Exception {
        if (conn != null && !conn.isClosed()) {
            conn.close(); // 确定性释放，100% 执行（区别于 finalize 的不可靠）
        }
    }
}
```

技术细节：

- `afterPropertiesSet()` 方法名固定，抛出异常会导致 `BeanCreationException`。
- `destroy()` 可抛异常，Spring 记录但不中断销毁流程。
- 手动触发原型 Bean 销毁：`context.getBeanFactory().destroyBean(prototypeBean)`。
- 与 `finalize()` 的区别：`DisposableBean` 在容器关闭时确定性调用，`finalize` 依赖 GC 不保证执行（不推荐依赖）。

## @Bean 的 initMethod 与 destroyMethod

通过配置指定生命周期方法，**不需要修改 Bean 的源码**，最适合第三方库的 Bean。

```java
@Configuration
public class DataSourceConfig {
    // HikariCP 的 close() 方法作为销毁回调
    @Bean(destroyMethod = "close")
    public DataSource dataSource() {
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl("jdbc:mysql://localhost:3306/test");
        config.setUsername("root");
        config.setPassword("123456");
        return new HikariDataSource(config);
    }

    @Bean(initMethod = "initialize", destroyMethod = "shutdown")
    public ExecutorService threadPool() {
        return Executors.newCachedThreadPool();
    }
}
```

特殊规则：

- **默认销毁行为**：Bean 实现了 `Closeable` / `AutoCloseable` 时，Spring 默认自动调用其 `close()`；显式设置 `@Bean(destroyMethod = "")` 可禁用。
- 方法签名要求：无参数、返回 `void`、非 `private`。
- 指定的 `initMethod` 不存在会抛 `BeanCreationException`；`destroyMethod` 不存在则静默忽略。
- 原型 Bean 的 `destroyMethod` 不生效，需调用方手动触发。

## 三种回调的执行顺序

同类的多个回调可共存，按固定顺序执行：

```text
初始化：@PostConstruct → InitializingBean.afterPropertiesSet() → initMethod
销毁：  @PreDestroy       → DisposableBean.destroy()            → destroyMethod
```

验证代码：

```java
@Component
public class MyBean implements InitializingBean {

    @PostConstruct
    public void postConstruct() {
        System.out.println("@PostConstruct");        // 1
    }

    @Override
    public void afterPropertiesSet() {
        System.out.println("InitializingBean");      // 2
    }

    public void init() {
        System.out.println("init-method");           // 3（需 @Bean(initMethod = "init") 配合）
    }
}
```

三种方式对比：

| 回调方式 | 优点 | 缺点 | 初始化顺序 |
| --- | --- | --- | --- |
| `@PostConstruct` / `@PreDestroy` | JSR 标准注解，无侵入 | 需修改源码 | 最早 / 最晚 |
| `InitializingBean` / `DisposableBean` | Spring 原生支持 | 耦合 Spring API | 中间 |
| `initMethod` / `destroyMethod` | 不修改源码，适合第三方库 | 需显式配置 | 最晚 / 最早 |

## BeanPostProcessor 全局拦截器

在**所有 Bean 初始化前后**拦截处理，可修改或包装 Bean 实例，是 Spring AOP、自动代理等核心功能的底层基础。

```java
public interface BeanPostProcessor {
    // 初始化前回调
    default Object postProcessBeforeInitialization(Object bean, String beanName) {
        return bean;
    }

    // 初始化后回调（AOP 代理通常在这里生成）
    default Object postProcessAfterInitialization(Object bean, String beanName) {
        return bean;
    }
}
```

在流水线中的位置：

```text
实例化 → 属性注入 → postProcessBeforeInitialization()
       → @PostConstruct → afterPropertiesSet() → init-method
       → postProcessAfterInitialization() → Bean 就绪
```

典型应用：

```java
// 日志处理器：打印所有 Bean 的初始化过程
@Component
public class LogBeanPostProcessor implements BeanPostProcessor {
    @Override
    public Object postProcessBeforeInitialization(Object bean, String beanName) {
        System.out.println("Before init: " + beanName);
        return bean;
    }

    @Override
    public Object postProcessAfterInitialization(Object bean, String beanName) {
        System.out.println("After init: " + beanName);
        return bean;
    }
}

// 模拟 AOP：初始化后为目标 Bean 包装代理
public class DebugBeanPostProcessor implements BeanPostProcessor {
    @Override
    public Object postProcessAfterInitialization(Object bean, String beanName) {
        if (bean instanceof UserService) { // 只代理特定 Bean
            return Proxy.newProxyInstance(
                bean.getClass().getClassLoader(),
                bean.getClass().getInterfaces(),
                (proxy, method, args) -> {
                    System.out.println("方法拦截: " + method.getName());
                    return method.invoke(bean, args);
                });
        }
        return bean;
    }
}
```

使用要点：

- 执行顺序控制：实现 `Ordered` 接口或 `@Order` 注解，数字越小优先级越高。
- 只处理特定 Bean：通过 `instanceof` 或包名、注解判断过滤。
- **避免在处理器中调用 `beanFactory.getBean()` 获取其他 Bean**，可能引发循环依赖。
- 处理器本身需被组件扫描到，否则不生效。

## Aware 接口在生命周期中的位置

Aware 回调（`BeanNameAware`、`ApplicationContextAware` 等）发生在**属性填充之后、初始化（`@PostConstruct`）之前**，由 `ApplicationContextAwareProcessor` 在 `postProcessBeforeInitialization` 阶段触发。

## 原型 Bean 的生命周期差异

- 生命周期**不包含销毁阶段**：实例化 → 属性赋值 → 初始化 → 交给调用方，容器不再跟踪。
- 因此 `@PreDestroy`、`DisposableBean`、`destroyMethod` 对原型 Bean 全部无效。
- 持有数据库连接等资源的原型 Bean，必须由调用方显式关闭，或借助 `ObjectProvider` 管理。

## 最佳实践

- **优先使用注解**：`@PostConstruct` / `@PreDestroy` 是 JSR 标准，比 Spring 专用接口更解耦。
- **避免接口污染**：`InitializingBean` / `DisposableBean` 会把业务类耦合到 Spring API。
- **第三方库对象**：用 `initMethod` / `destroyMethod`，不改源码。
- **回调方法要快**：避免耗时操作，影响启动速度和容器关闭。
- **复杂全局逻辑用 `BeanPostProcessor`**：如统一监控 Bean 初始化耗时。

## 常见问题

- **多个 BeanPostProcessor 的顺序**：`@Order(1)` 数字越小越先执行。
- **原型 Bean 为什么没有销毁回调**：容器创建后即交出所有权，不再跟踪。
- **生命周期回调与 AOP 代理的关系**：Bean 被代理时，`@PostConstruct` 等回调在代理对象生成后执行（代理在 `postProcessAfterInitialization` 阶段产生）。
- **销毁方法没被调用**：确认是单例 Bean，且容器执行了 `context.close()`。
