# 容器注入

*类型：knowledge ｜ 难度：基础 ｜ 标签：Spring、DI、@Autowired、@Qualifier、@Resource、@Value*

**依赖注入（DI）是 IoC 的具体实现：Spring 在运行时把依赖对象塞进目标组件，组件自己不创建依赖。注入方式首选构造器注入（不可变、易测试），同一类型多个实现时用 `@Qualifier` 精确指定或 `@Primary` 设默认值；需要按名称注入或跨框架兼容用 `@Resource`；外部配置值用 `@Value` 注入，感知容器底层资源则实现 Aware 接口。**

## @Autowired 注解

Spring 最核心的 DI 注解，自动装配 Bean，减少手动 `new` 和 XML 配置。

### 三种注入方式

```java
// 1. 构造器注入（推荐）：字段可声明 final，依赖显式、易于测试
//    Spring 4.3+ 单构造器时可省略 @Autowired
@Service
public class UserService {
    private final UserRepository userRepository;

    @Autowired
    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}

// 2. Setter 注入：适合可选依赖或需动态重新绑定的场景
@Service
public class UserService {
    private UserRepository userRepository;

    @Autowired
    public void setUserRepository(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}

// 3. 字段注入（不推荐）：代码简洁，但依赖隐藏、难以测试、无法声明 final
@Service
public class UserService {
    @Autowired
    private UserRepository userRepository;
}
```

### 注入规则

- **按类型匹配（默认）**：根据字段类型查找 Bean；同类型多个实现会抛 `NoUniqueBeanDefinitionException`。
- **按名称匹配**：结合 `@Qualifier` 指定 Bean 名称。
- **集合与 Map 注入**：自动注入所有匹配类型的 Bean。

```java
@Autowired
private List<Validator> validators;        // 注入所有 Validator 实现

@Autowired
private Map<String, Validator> validatorMap; // key 为 Bean 名称
```

### 可选依赖

```java
@Autowired(required = false)              // 允许依赖为 null
private OptionalDependency optionalDep;

@Autowired
private Optional<OptionalDependency> optionalDep2; // Java 8+ 风格

@Autowired
@Nullable                                 // JSR-305 标记可为 null
private OptionalDependency optionalDep3;
```

### 高级用法

```java
// 泛型依赖注入：Spring 会区分泛型参数
public abstract class BaseService<T> {
    @Autowired
    protected Repository<T> repository; // 子类 UserService 注入 Repository<User>
}

@Service
public class UserService extends BaseService<User> {}

// 方法注入：任意方法（非 Setter）也可用于注入
@Autowired
public void setupDependencies(UserRepository repo, PasswordEncoder encoder) {
    this.repo = repo;
    this.encoder = encoder;
}
```

### 常见问题

**循环依赖**（A 依赖 B，B 又依赖 A）：优先重构解耦，也可用 `@Lazy` 延迟加载其中一方：

```java
@Service
public class ServiceA {
    private final ServiceB serviceB;

    public ServiceA(@Lazy ServiceB serviceB) { // 延迟注入代理
        this.serviceB = serviceB;
    }
}
```

**多实现类的歧义性**：用 `@Qualifier` 指定名称，或在实现类上标 `@Primary` 设默认。

**静态字段无法注入**：Spring 注入基于对象实例，静态字段注入失败；需通过非静态 Setter 间接赋值：

```java
private static UserRepository userRepository;

@Autowired
public void setUserRepository(UserRepository repo) {
    userRepository = repo; // 间接赋值给静态字段
}
```

## @Qualifier 注解

解决同一类型多个实现的注入歧义，明确指定注入哪个 Bean。

```java
@Service("jdbcUserService")
public class JdbcUserService implements UserService {}

@Service("jpaUserService")
public class JpaUserService implements UserService {}

@Autowired
@Qualifier("jpaUserService") // 明确注入 JpaUserService
private UserService userService;
```

构造器注入中使用：

```java
@Autowired
public OrderService(@Qualifier("jdbcUserService") UserService userService) {
    this.userService = userService;
}
```

与 `@Primary` 的优先级：`@Qualifier` 更高，会覆盖 `@Primary`。

进阶：自定义 Qualifier 注解提升可读性：

```java
// 定义限定符注解
@Qualifier
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
public @interface CryptoType {
    String algorithm();
}

// 标记 Bean
@Component
@CryptoType(algorithm = "AES")
public class AesEncryptor implements Encryptor {}

// 注入指定算法的实现
@Autowired
@CryptoType(algorithm = "AES")
private Encryptor encryptor;
```

## @Primary 注解

标记同类型多个 Bean 中的默认注入项，避免在每个注入点写 `@Qualifier`。

```java
@Service
@Primary  // 默认注入此实现
public class CreditCardPaymentService implements PaymentService {}

@Service
public class AlipayPaymentService implements PaymentService {}

@Service
public class OrderService {
    @Autowired  // 自动注入 CreditCardPaymentService
    private PaymentService paymentService;
}
```

典型场景：

```java
@Configuration
public class DataSourceConfig {
    @Bean
    @Primary  // 默认数据源
    public DataSource primaryDataSource() {
        return DataSourceBuilder.create().url("jdbc:mysql://primary").build();
    }

    @Bean
    public DataSource backupDataSource() {
        return DataSourceBuilder.create().url("jdbc:mysql://backup").build();
    }
}
```

注意事项：

- 同一类型只能有一个 `@Primary`，多个会抛 `NoUniqueBeanDefinitionException`。
- `@Qualifier` 优先级更高，明确指定时忽略 `@Primary`。
- 测试中可用 `@TestConfiguration` + `@Primary` 让 Mock 实现覆盖真实 Bean。

| 特性 | @Primary | @Qualifier |
| --- | --- | --- |
| 目的 | 标记默认注入的 Bean | 明确指定注入的 Bean |
| 配置位置 | 类/方法级别（定义 Bean 时） | 字段/参数级别（注入时） |
| 冲突处理 | 多个 @Primary 报错 | 无冲突问题 |

## @Resource 注解

Java 标准注解（JSR-250），功能类似 `@Autowired`，默认按名称匹配，不依赖 Spring。

```java
@Component
public class OrderService {
    @Resource  // 按字段名匹配，相当于 @Resource(name = "userService")
    private UserService userService;

    @Resource(name = "jdbcUserService")  // 显式指定 Bean 名称
    private UserService userService2;
}
```

匹配规则：未指定 `name` 时用字段名作为 Bean 名称；名称找不到时回退到按类型匹配。

与 `@Autowired` 的对比：

| 特性 | @Resource | @Autowired |
| --- | --- | --- |
| 来源 | Java 标准（JSR-250） | Spring 特有 |
| 默认匹配规则 | 先按名称，后按类型 | 仅按类型 |
| required 属性 | 无 | 支持 `required = false` |
| 构造函数注入 | 不支持 | 支持 |

注意事项：

- `@Primary` 对 `@Resource` 无效（它优先按名称匹配）；需要利用 `@Primary` 时改用 `@Autowired`。
- 不能用于构造函数参数，仅支持字段和方法注入。
- 名称匹配失败回退按类型时，可能触发多实现歧义，可配合 `@Qualifier` 使用。

## Spring 感知接口（Aware Interfaces）

让 Bean 感知并获取容器底层资源（如 `ApplicationContext`、`BeanName`），在无法通过普通注入实现时使用。

| 接口 | 作用 | 使用场景 |
| --- | --- | --- |
| `ApplicationContextAware` | 获取应用上下文 | 动态获取 Bean、发布事件 |
| `BeanNameAware` | 获取当前 Bean 的名称 | 日志、动态代理识别 Bean |
| `BeanFactoryAware` | 获取 BeanFactory | 编程式创建 Bean |
| `EnvironmentAware` | 获取环境配置 | 读取配置、判断激活 Profile |
| `ApplicationEventPublisherAware` | 获取事件发布器 | 发布自定义事件 |

```java
@Component
public class DynamicBeanLoader implements ApplicationContextAware {
    private ApplicationContext context;

    @Override
    public void setApplicationContext(ApplicationContext context) {
        this.context = context;
    }

    public void loadBeanDynamically(String beanName) {
        Object bean = context.getBean(beanName); // 运行时动态获取 Bean
    }
}
```

底层原理：Spring 初始化 Bean 时通过 `ApplicationContextAwareProcessor`（一个 `BeanPostProcessor`）在 `postProcessBeforeInitialization` 阶段回调 Aware 方法。

注意点：回调发生在属性填充后、`@PostConstruct` 前；避免滥用，优先用 `@Autowired`/`@Resource`。

## @Value 注解

注入外部配置值到 Bean 的字段或方法参数，支持 SpEL 表达式。

```java
// 注入静态值
@Value("100")
private int maxAttempts;

// 注入配置文件属性（application.properties 中 app.name=MyApp）
@Value("${app.name}")
private String appName;

// 默认值：配置不存在时用 5000
@Value("${app.timeout:5000}")
private int timeout;

// SpEL 表达式
@Value("#{T(java.lang.Math).random() * 100}") // 调用静态方法
private double randomNumber;

@Value("#{systemProperties['user.timezone']}") // 系统属性
private String timezone;
```

注入数组或集合：

```properties
app.servers=192.168.1.1,192.168.1.2
```

```java
@Value("${app.servers}")
private String[] servers; // ["192.168.1.1", "192.168.1.2"]

@Value("#{'${app.servers}'.split(',')}")
private List<String> serverList;
```

值来源优先级（高到低）：命令行参数 → JNDI → Java 系统属性 → 环境变量 → `application.properties` → 默认值。

注意事项：

- 属性不存在且无默认值会抛异常，关键属性务必写 `${key:default}`。
- 启动时解析，运行时不能动态更新（热更新需 `@RefreshScope`）。
- 类型转换失败（如非数字注入 `int`）会抛 `NumberFormatException`。

与 `@ConfigurationProperties` 的选择：

| 特性 | @Value | @ConfigurationProperties |
| --- | --- | --- |
| 功能 | 单个属性注入 | 批量绑定属性到对象 |
| SpEL 支持 | 支持 | 不支持 |
| 类型安全 | 需手动处理 | 自动类型转换 |
| 适用场景 | 简单属性、动态表达式 | 结构化配置（如连接池配置） |

## @PropertySource 加载外部配置

将自定义属性文件加载进 Spring `Environment`，供 `@Value` 或 `Environment` 读取。

```java
@Configuration
@PropertySources({
    @PropertySource("classpath:app.properties"),
    @PropertySource("classpath:db.properties")
})
public class AppConfig {}
```

- 查找路径：`classpath:`（resources 目录，推荐）、`file:`（文件系统绝对路径）、无前缀默认类路径。
- 默认 YAML 不支持，需自定义 `PropertySourceFactory` 并引入 SnakeYAML。
- `ignoreResourceNotFound = true` 可忽略缺失文件；后加载的文件覆盖先加载的同名属性。
- Spring Boot 默认加载 `application.properties`，`@PropertySource` 用于非标准自定义配置文件。

## ResourceUtils 工具类

简化资源路径解析的非容器工具类，适合单元测试或工具场景。

```java
import org.springframework.util.ResourceUtils;

// 读取类路径下的文件
File file = ResourceUtils.getFile("classpath:config.json");

// 读取文件系统文件
File file2 = ResourceUtils.getFile("file:/home/user/data.txt");

// 判断资源类型
URL url = ResourceUtils.getURL("classpath:app.properties");
boolean isJar = ResourceUtils.isJarURL(url); // 资源是否在 JAR 包内
```

路径前缀：

| 前缀 | 示例 | 解析方式 |
| --- | --- | --- |
| `classpath:` | `classpath:config.xml` | 从类路径加载 |
| `file:` | `file:/data/config.yml` | 从文件系统加载 |
| `http:` / `https:` | `https://example.com/data.json` | 从网络加载 |
| 无前缀 | `data.txt` | 默认按类路径解析 |

已知坑：资源打包在 JAR 内时 `getFile()` 会抛 `FileNotFoundException`，应改用流式读取 `new ClassPathResource("data.json").getInputStream()`。Spring 项目中优先用 `ResourceLoader` 或 `@Value("classpath:file.json") Resource resource`。
