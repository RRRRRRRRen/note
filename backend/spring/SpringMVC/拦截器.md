# 拦截器

*类型：knowledge ｜ 难度：进阶 ｜ 标签：SpringMVC、拦截器、HandlerInterceptor、登录校验*

**拦截器（Interceptor）是 SpringMVC 提供的请求预处理/后处理机制，围绕 Controller 的执行时机提供 preHandle、postHandle、afterCompletion 三个钩子。它比 Servlet Filter 更贴近 SpringMVC 流程——能拿到 handler 信息、能注入 Spring Bean，是登录校验、权限验证、请求日志的标准落点。注册时用 addPathPatterns/excludePathPatterns 控制拦截范围，多个拦截器按注册顺序形成链式执行。**

## 拦截器的作用

- **请求到达 Controller 之前**执行：登录校验、权限验证。
- **Controller 执行之后、视图渲染之前**执行：统一 Model 处理。
- **整个请求完成后**（包括视图渲染）执行：日志记录、资源释放。

## 核心接口与三个方法

```java
public interface HandlerInterceptor {

    // Controller 方法调用前执行；返回 false 表示拦截，中断后续流程
    boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception;

    // Controller 返回后、视图渲染前执行（仅页面渲染场景可修改 ModelAndView）
    void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler, ModelAndView modelAndView) throws Exception;

    // 整个请求完成后执行（含渲染），可用于日志、异常补充处理、资源释放
    void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) throws Exception;
}
```

| 方法 | 执行时机 | 返回值/意义 |
| --- | --- | --- |
| `preHandle()` | Controller 方法调用前 | `false` 中断后续流程 |
| `postHandle()` | Controller 返回后、视图渲染前 | 可修改返回数据（仅限页面） |
| `afterCompletion()` | 整个请求完成后 | 日志、异常处理、资源释放 |

## 定义拦截器

```java
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        Object user = request.getSession().getAttribute("loginUser");
        if (user == null) {
            response.sendRedirect("/login"); // 未登录跳转登录页
            return false;                    // 拦截请求，Controller 不再执行
        }
        return true; // 放行
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) {
        System.out.println("请求结束：" + request.getRequestURI());
    }
}
```

前后端分离场景，`preHandle` 里返回 JSON 而非重定向：

```java
@Override
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
    Object user = request.getSession().getAttribute("loginUser");
    if (user == null) {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED); // 401
        response.setContentType("application/json;charset=UTF-8");

        Map<String, Object> resp = new HashMap<>();
        resp.put("code", 401);
        resp.put("message", "未登录，请先登录");

        String json = new ObjectMapper().writeValueAsString(resp);
        response.getWriter().write(json);
        return false;
    }
    return true;
}
```

## 注册拦截器

通过配置类实现 `WebMvcConfigurer` 注册：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor())
          .addPathPatterns("/**")         // 拦截所有请求
          // 放行登录接口和静态资源
          .excludePathPatterns("/login", "/doLogin", "/logout", "/css/**", "/js/**", "/static/**");
    }
}
```

配套的登录控制器示例：

```java
@RestController
@RequestMapping("/api")
public class UserController {

    @PostMapping("/doLogin")
    public Map<String, Object> login(@RequestParam String username, HttpSession session) {
        session.setAttribute("loginUser", username); // 写入会话，后续请求凭此放行
        return Map.of("code", 200, "message", "登录成功");
    }

    @PostMapping("/logout")
    public Map<String, Object> logout(HttpSession session) {
        session.invalidate();
        return Map.of("code", 200, "message", "退出登录");
    }

    @GetMapping("/users")
    public Map<String, Object> getUserList() {
        return Map.of("code", 200, "data", List.of("张三", "李四", "王五"));
    }
}
```

## 多拦截器链式执行

注册多个拦截器时按**注册顺序**形成拦截器链，类似过滤器链：

```text
请求 → 拦截器1.preHandle → 拦截器2.preHandle → Controller
     → 拦截器2.postHandle → 拦截器1.postHandle
     → 渲染 → 拦截器2.afterCompletion → 拦截器1.afterCompletion
```

- `preHandle` 按注册顺序正序执行，任一返回 `false` 则中断。
- `postHandle` 和 `afterCompletion` 按注册顺序**逆序**执行。
- 某拦截器 `preHandle` 返回 `false` 时，只有它**之前**的拦截器会执行 `afterCompletion`。

## 拦截器与 Filter 的区别

| 特性 | Filter | Interceptor（SpringMVC） |
| --- | --- | --- |
| 生命周期 | Servlet 容器层面 | SpringMVC 层面（DispatcherServlet 之后） |
| 技术接口 | `javax.servlet.Filter` | `HandlerInterceptor` |
| 拦截范围 | 所有请求（含静态资源） | 只拦截 DispatcherServlet 处理的请求 |
| 可访问数据 | 无 Spring 上下文 | 可注入/使用 Spring Bean |

选型原则：编码级通用过滤（字符集、跨域头）用 Filter；需要 Spring Bean、依赖业务语义（登录态、权限）的拦截用 Interceptor。

## 最佳实践

- **拦截器不做重业务**：它处于所有请求的入口，`preHandle` 判断逻辑要轻，复杂逻辑交给 Service。
- **与 @ControllerAdvice 分工**：异常处理、全局数据绑定用 `@ControllerAdvice`；请求前后的流程控制用拦截器。
- **放行清单要完整**：登录、注册、静态资源、健康检查等路径必须加入 `excludePathPatterns`，否则会造成死循环重定向或全量拦截。
- **认证信息建议后置到参数解析器**：Token 校验放拦截器，解析出的用户对象通过 `request.setAttribute` 传递或封装成 `HandlerMethodArgumentResolver` 注入参数。
