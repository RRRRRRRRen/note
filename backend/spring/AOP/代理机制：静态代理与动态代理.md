# 代理机制：静态代理与动态代理

*类型：knowledge ｜ 难度：进阶 ｜ 标签：代理模式、AOP、JDK 动态代理、CGLIB*

**代理模式的本质是在不改动目标类的前提下插入增强逻辑。静态代理在编译期手写代理类，直观但冗余；动态代理在运行时生成代理类，是 Spring AOP 的核心实现——目标类有接口走 JDK 动态代理（反射 + InvocationHandler），没有接口走 CGLIB（字节码生成子类 + MethodInterceptor）。理解「Spring 如何选代理」和「自我调用失效」这两个问题，是掌握 Spring 事务与 AOP 失效场景的地基。**

## 静态代理

编译期就确定代理关系，通过手动编写代理类实现功能增强。

核心原理：

- 代理类与被代理类实现相同接口。
- 代理类持有被代理对象的引用。
- 在调用目标方法前后插入增强逻辑。

```java
// 1. 定义接口
public interface OrderDao {
    void createOrder();
}

// 2. 目标类
public class OrderDaoImpl implements OrderDao {
    public void createOrder() {
        System.out.println("执行订单入库操作");
    }
}

// 3. 静态代理类：在目标方法前后插入事务逻辑
public class OrderDaoProxy implements OrderDao {
    private OrderDao target;

    public OrderDaoProxy(OrderDao target) {
        this.target = target;
    }

    @Override
    public void createOrder() {
        try {
            System.out.println("【代理】开启事务...");
            target.createOrder();                 // 委托给目标对象
            System.out.println("【代理】提交事务...");
        } catch (Exception e) {
            System.out.println("【代理】回滚事务！");
            throw e;
        }
    }
}

// 4. 使用代理
public class Main {
    public static void main(String[] args) {
        OrderDao realDao = new OrderDaoImpl();
        OrderDao proxyDao = new OrderDaoProxy(realDao); // 面向接口持有代理
        proxyDao.createOrder();
    }
}
```

优缺点：

- 优点：编译期检查类型安全、无运行时生成开销、代理逻辑直观可控。
- 缺点：每个被代理类都要手写代理类、修改逻辑需重新编译、接口变更时代理类要同步修改。

## JDK 动态代理

基于 `java.lang.reflect.Proxy`，**要求目标类必须实现接口**，运行时动态生成 `$ProxyN` 类字节码。

```java
// 1. 定义接口
public interface UserService {
    void saveUser();
}

// 2. 实现类（被代理目标）
public class UserServiceImpl implements UserService {
    public void saveUser() {
        System.out.println("保存用户数据...");
    }
}

// 3. 调用处理器：增强逻辑写在这里
public class JdkProxyHandler implements InvocationHandler {
    private Object target;

    public JdkProxyHandler(Object target) {
        this.target = target;
    }

    // 所有方法调用都会转发到这里
    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("[JDK代理] 前置处理");
        Object result = method.invoke(target, args); // 反射调用目标方法
        System.out.println("[JDK代理] 后置处理");
        return result;
    }
}

// 4. 使用代理
public class Main {
    public static void main(String[] args) {
        UserService target = new UserServiceImpl();
        UserService proxy = (UserService) Proxy.newProxyInstance(
            target.getClass().getClassLoader(),
            target.getClass().getInterfaces(),  // 关键：接口数组，代理类靠它实现接口
            new JdkProxyHandler(target)
        );
        proxy.saveUser();
    }
}
```

底层实现关键：

- `ProxyGenerator` 动态生成 `$ProxyN` 类字节码。
- 代理类继承 `Proxy` 并实现目标接口（所以 Java 单继承决定了必须有接口）。
- 方法调用统一转发给 `InvocationHandler.invoke()`。

## CGLIB 动态代理

基于 ASM 字节码操作，**通过生成目标类的子类实现代理**，无需接口。

```java
// 1. 目标类（无需实现接口）
public class OrderService {
    public void createOrder() {
        System.out.println("创建订单...");
    }
}

// 2. 方法拦截器
public class CglibInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("[CGLIB代理] 前置处理");
        Object result = proxy.invokeSuper(obj, args); // 调用父类（目标类）方法
        System.out.println("[CGLIB代理] 后置处理");
        return result;
    }
}

// 3. 使用代理
public class Main {
    public static void main(String[] args) {
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(OrderService.class);  // 设置父类为目标类
        enhancer.setCallback(new CglibInterceptor());
        OrderService proxy = (OrderService) enhancer.create(); // 创建子类代理实例
        proxy.createOrder();
    }
}
```

底层实现关键：

- ASM 库直接生成目标类的子类字节码，重写父类方法加入拦截逻辑。
- 默认使用 `FastClass` 机制索引方法，避免反射调用开销。
- 代理类命名形如 `TargetClass$$EnhancerByCGLIB$$...`。

局限：无法代理 `final` 类和 `final` 方法（子类无法重写）。

## Spring 如何选择代理方式

Spring AOP 的选择逻辑（`DefaultAopProxyFactory`）：

```java
public AopProxy createAopProxy(AdvisedSupport config) {
    if (config.isOptimize() || config.isProxyTargetClass() || hasNoUserSuppliedProxyInterfaces(config)) {
        return new ObjenesisCglibAopProxy(config);  // 使用 CGLIB
    } else {
        return new JdkDynamicAopProxy(config);      // 使用 JDK 代理
    }
}
```

决策条件：

- 目标类未实现接口 → 强制 CGLIB。
- 设置 `proxyTargetClass = true` → 强制 CGLIB。

```properties
spring.aop.proxy-target-class=true  # 强制使用 CGLIB
```

- 其他情况 → 优先 JDK 动态代理。

## 两种动态代理的性能对比

| 维度 | JDK 动态代理 | CGLIB |
| --- | --- | --- |
| 生成速度 | 慢（需生成新类） | 快（直接修改字节码） |
| 调用性能 | 快（直接调用接口方法） | 稍慢（需方法拦截） |
| 代理类命名 | `$Proxy0`、`$Proxy1` | `TargetClass$$EnhancerByCGLIB$$` |
| 内存占用 | 低 | 较高（生成更多类） |

优化建议：对频繁创建的代理对象，考虑缓存代理实例。

## 动态代理的局限性

- **JDK 代理的接口依赖**：无法代理没有接口的类。
- **CGLIB 的 final 限制**：无法代理 final 类/方法。
- **自我调用问题**：对象内部 `this` 调用不经过代理，增强逻辑失效——这是 `@Transactional` 同类方法互调不生效的根因。

```java
public class UserService {
    public void a() {
        this.b();  // 直接调用 this，不经过代理，不会被 AOP 拦截！
    }
    public void b() { /* 增强逻辑不会触发 */ }
}
```

## 三者横向对比

| 对比维度 | 静态代理 | JDK 动态代理 | CGLIB |
| --- | --- | --- | --- |
| 生成时机 | 编译期 | 运行时 | 运行时 |
| 代码侵入性 | 需手动编写代理类 | 无侵入（自动生成） | 无侵入（自动生成） |
| 目标类要求 | 需实现接口 | 必须实现接口 | 可代理普通类 |
| 灵活性 | 低（逻辑固定） | 高 | 高 |
| 适用场景 | 简单固定需求 | 目标有接口的 AOP | 无接口目标、框架级代理 |

## 典型应用场景

- **Spring AOP**：`@Aspect` 切面底层就是动态代理拦截目标方法。
- **Spring 事务管理**：`@Transactional` 方法被代理包裹，方法前后执行事务开启/提交/回滚。

```java
@Transactional
public void transferMoney(Account from, Account to, double amount) {
    // 事务方法：代理负责在此方法前后插入事务控制
}
```

- **MyBatis Mapper 接口代理**：接口无需实现类，运行时由动态代理生成实现。

```java
UserMapper userMapper = sqlSession.getMapper(UserMapper.class);
```

## 最佳实践

- 优先使用 Spring AOP 声明式代理（`@Aspect`），不要手写代理。
- 需要代理无接口的类时，配置 `spring.aop.proxy-target-class=true` 强制 CGLIB。
- 性能敏感场景：缓存代理对象，避免在频繁调用的方法上叠加复杂切面。
- 警惕自我调用：需要增强生效时，通过自注入代理对象或拆分类来解决。
